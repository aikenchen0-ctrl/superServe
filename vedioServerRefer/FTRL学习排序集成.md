# FTRL 学习排序集成

日期：2026-11-06。状态：可选实验路径，默认关闭；不作为生产质量或“三低”达成证明。

<重表述提示词为问题>如何复用成熟 Rust 学习机制，使公开候选与授权画像产生可学习的跨场景排序，同时不增加在线模型服务调用，不污染事实画像，并保留基线、版本与回退边界？</重表述提示词为问题>

## 问题与取舍

本轮保留三个问题：Q4-a 学习是否产生可复现的排序增益；Q4-b 旧召回在新评分下是否遗漏结果；
Q5-r 模型如何进入固定部署与跨机器发布。本轮只深入 Q4-a，后两项记录前置条件。

- S0：已有标签平均亲和度、先验同分排序，以及按旧评分取 Top-K 的可选召回。
- IFR：从可信反馈学习有用排序，在线只计算已授权、已存在的必要特征。
- TC：模型表达能力提高，会增加计算、模型分发、样本治理和评价成本。
- PC：同一个模型需要变化以学习，又需要固定以保证多副本请求可追溯。
- 分离：离线单次训练；不可覆盖地发布新文件；实例启动时指定目录和模型指纹，运行时只读。
- 代偿：新增训练导出契约与离线评价；在线评分增加局部计算；新模型不能直接沿用旧 Top-K 的保真结论。

真实需求是“用户在授权范围内得到有用结果”，不是“上线一个更大的推荐模型”。
付费和运维方承担 CPU、带宽与维护成本；用户提供最小偏好投影并持有拒绝权；
评价方必须同时检查质量、授权、开销与回退。训练产物不会写回知识图谱或长期事实层。

## 数据、特征与时间边界

训练输入是 `rank-training-v1`，目录文件上限 8 MiB，样本 JSON 上限 32 MiB、
最多 100,000 个样本；只接收冻结曝光及明确的 `like`/`dislike`，不把未曝光、下载、
CMCD、播放预留、未点击或模型推断自动当负反馈。

每个样本包含曝光 ID、证据引用、公开候选 ID、曝光时请求与授权投影、
投影形成时间、曝光时间、反馈时间。校验顺序为：

1. 固定目录指纹匹配，候选存在且属于请求的允许范围。
2. 投影形成时间不晚于曝光；曝光早于反馈；反馈严格早于训练截止时间。
3. 反馈按时间排列，曝光 ID 唯一，同一请求与候选不能重复标注。
4. 所有样本均有效且正负两类均存在后，才执行单次训练。
5. 推理请求时间不得早于模型训练截止时间。

这些检查只能验证契约内部一致性。时间戳和证据 ID 不能证明导出器没有伪造来源，
也不能证明投影授权仍有效；真实采集、授权撤销、曝光选择偏差及撤回重训仍待完成。

固定六维特征为常量、候选先验、正兴趣均值、负兴趣均值、非零兴趣命中比例、
是否存在非零兴趣。每个领域拥有同样的修正权重，加一组全局权重；最多 64 个训练领域、
390 个坐标。未训练领域仅使用全局权重。
特征不含主体 ID、候选 ID、标签 ID 或私人原文，但这不构成完整的隐私安全证明。

模型采用 `ftrl-ranker-v1` / `profile-candidate-6-v1` /
`explicit-preference-v1`，限制权重有限且绝对值不大于 100。
输出 `rank_score` 为未校准线性值；旧 `affinity` 字段继续表达标签亲和度，
不能把新分数解释为点击概率、事实置信度或跨领域效用已校准。

## 发布与服务

```powershell
cargo run -p vs-service --example train_ranker --locked --offline -- `
  <固定目录JSON> <冻结训练样本JSON> <新模型JSON>

$env:VS_ROLE = 'api'
$env:VS_CATALOG = '<同一目录JSON>'
$env:VS_RANK_MODEL = '<模型JSON>'
$env:VS_RANK_MODEL_SHA256 = '<训练收据中的sha256>'
```

离线入口输出指纹、大小、训练截止时间、样本数和数据类型；不输出原始画像。
文件发布复用既有不可覆盖原语；再次使用同一路径会失败，改模型须发布新路径。

在线读取最多 128 KiB 模型，先验证指定 SHA256、目录原始字节指纹、格式和数值，
再监听请求。`/v1/recommendations` 与 `/v1/feed` 均经过原有范围、隐藏和拒绝标签过滤，
共用有界阻塞计算许可，无逐请求模型 RPC。响应添加 `x-rank-model-sha256`，
就绪响应披露模型指纹及 synthetic/observed 类型；没有热更新或共享可变优化器。

模型用于 api/all 实例，与 Qdrant、分组召回及画像权威角色互斥，
并在配置的两种调用顺序下检查。原因是旧召回分数不保真、画像权威不负责排序。
初版与部署记录互斥的限制已由[排序模型发布与部署绑定](排序模型发布与部署绑定.md)补齐：
支持目标内明确模型指纹，部署模式禁止重复设置本地模型路径。不能静默忽略冲突配置。
核心库的显式子集排序仍支持模型，供固定候选评价使用，不据此声称召回保真。

关闭配置继续使用标签基线，响应中不增加 `rank_score`；
默认路径仍保存原有候选/亲和度二元组，避免为关闭的模型添加逐候选分数缓存。
学习路径会增加评分与排序存储，6 维权重和文件大小不是服务进程 RSS。
请求级非零兴趣标记只计算一次；`RequestContext` 兴趣表改为只读访问器 `interests()`，
避免外部修改兴趣后留下失效标记，仓库内召回与回放调用已迁移。

## 回放与尚未闭合的证据

实验入口为 `rank_learning_replay`，生成与训练身份、标签命名、先验取值不同的合成留出数据。
同一领域使用同一组 32 个留出候选、同一过滤和返回数量，对比四路：
标签基线、完整学习模型、领域修正置零的全局模型、保持模型容量的画像绑定打乱。
同时保存 NDCG@5、Recall@5、退化查询数量和重复耗时分布。

探索版 v1 中打乱仅改变偏好幅值、没有改变主题绑定，控制偏弱；
服务场景 NDCG@5 约 0.686→0.986，视频与文章均为 1，不能据此证明画像的普遍增益。
正式 v2 在所有路径中统一加入主题轮换，并保留参数与算法不变。
该调整用于增强否证能力，不把 v1 的探针耗时当 release 性能证据。

正式结果、日志路径与验证数量以 `problem-space/rank-learning-evaluation.json` 为准。
合成规则和标签由同一已知机制生成，存在模型族相容性；没有真实行为分布、曝光倾向、
跨领域混排评价、在线满意度或端到端尾延迟。只有机制闭环，不能判定生产质量门通过。

v2 两轮结果和独立训练命令的模型完全一致，9216个训练样本，
模型JSON 844字节、24个权重192字节、三个训练领域；这些数字不代表服务RSS。

| 领域 | 基线NDCG@5 | 学习NDCG@5 | 领域修正置零 | 打乱画像绑定 |
| --- | --- | --- | --- | --- |
| video | 0.984371 | 1.000000 | 0.995577 | 0.000000 |
| article | 1.000000 | 1.000000 | 1.000000 | 0.000000 |
| service | 0.774011 | 0.951958 | 0.853083 | 0.072412 |

每领域48个留出查询，完整学习模型在这144个查询上未降低NDCG@5。
领域修正置零是训练后消融，不是独立训练的等容量全局模型；
打乱使用同一留出主体集合的固定置换，模型容量与候选池保持不变。
本夹具的大幅打乱退化说明它对主体主题绑定敏感，不证明真实画像收益。
第一轮排序P50：基线2.8微秒，学习3.8–4.1微秒；
第二轮基线2.8微秒，学习4.0–4.2微秒。耗时含单次请求校验、过滤、排序和结果分配，
不含网络和排队；测量固定顺序、重复热缓存、小候选池，不设置生产切换阈值。

```powershell
cargo build --release --locked --offline -p vs-service `
  --example rank_learning_replay --example train_ranker
./labs/recommendation/run-learning.ps1
```

脚本为每次运行创建独立实验目录，保存两轮JSON、冻结样本、目录、模型、训练收据、
二进制/源码/锁文件指纹。复跑须重新构建对应源码；保存的指纹标明历史收据实际对应版本。
验证使用编译器1.96.0，固定工具链Clippy组件缺失时使用同版本stable；
源覆盖参数需放在`cargo +stable clippy`子命令之后，避免子进程回退到全局旧镜像。
