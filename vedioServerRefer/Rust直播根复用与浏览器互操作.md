## 本轮选择

**普通HLS实验根使用Xiu v0.13.0，浏览器继续复用hls.js 1.7.4。**
没有重写RTMP、TS封装、HLS解析或解码器；源码仓库已克隆并获取固定版本标签，
实际运行官方Windows二进制，第一方改动集中在Rust适配和实验工具。
其他子问题继续使用现有根参考记录，本轮只替换直播兼容路径的空缺。

“最强”按当前子问题解释为：先满足语言、可运行和访问边界，
再比较复用范围及新增代价。当前没有同负载跨候选的计算、带宽和延迟排名。

## HMM约束与代偿

现状是新版直播候选失败，而点播播放器已经能观测真实帧。
本轮现实目标是一个可替换、可取消、可定位失败的普通HLS消费路径。
平台承担带宽和计算，用户需要播放稳定，维护者需要缩小改动面。

核心阻力是媒体功能与新增云存储初始化耦合。
同一默认路径本应不需要云存储，却受云存储初始化前置条件阻塞。
采用版本条件分离：以不含该路径的固定发布物验证媒体边界，
把新版修复与额外依赖构建留在独立分支。

代偿是旧依赖需要后续安全和维护复核，且普通HLS约5秒分片不满足实时互动目标。
本轮不将这一代偿转为生产默认。Rust中间层还增加一次HTTP转发，
未测量其CPU、RSS或延迟成本。

保留三个问题：

1. 普通HLS的消费、取消、失败和生命周期：本轮深入。
2. WebRTC实时房间、鉴权和物理扩容：独立待验。
3. 播放事实、明确反馈与跨域推荐效用：继续作为业务链路优先问题。

## 已实现路径

```text
FFmpeg读取固定H.264/AAC测试素材并按原码流推送
  → Xiu v0.13.0接收RTMP并封装滚动TS/HLS
  → Rust实验入口固定房间、有界流式转发
  → hls.js消费清单和TS
  → 浏览器出帧、取消、清单更新及代次观测
```

FFmpeg只作为测试发布源，不作为此路径的服务端转码实现。
Rust入口位于`examples/playback_lab.rs`，窄适配位于
`examples/support/live_proxy.rs`，没有新增Cargo包或修改生产Rust模块。

接口固定到本机指定端口的`/live/lab/lab.m3u8`和数字命名TS：
禁止浏览器选择任意URL/房间，禁止上游重定向、自动重试和系统代理，
不转发浏览器提供的凭证。读取并发8，单次连接2秒、请求8秒，
清单128KiB、片段8MiB预算；正文按块转发，许可随正文释放。
这些值用于实验，尚未据真实负载调优。

沿用Host、Origin和跨站检查，浏览器不持有内部服务令牌。
页面切换来源会创建新代次；异步配置、请求统计和清单回调绑定各自代次，
避免旧请求写入新播放记录。

## 真实验证

同一32秒、640×360、24fps的合成H.264/AAC素材循环推流，
本机Chrome晚加入已运行的直播。网络未限速。

| 观测 | 结果 |
| --- | --- |
| 首帧回调 | 约211ms，单次晚加入测量 |
| 帧回调 | 116次，像素非空且变化 |
| 直播清单 | 确认为live，末序号19→20 |
| 客户端XHR正文 | 1277096字节，含清单、TS及重复请求 |
| 该短窗口卡顿 | 0次，不代表长期稳定性 |
| 直播→点播 | 代次1→2，点播记录未混入直播请求 |
| 停止 | 等待后请求数与正文字节不再增加 |
| 读取许可 | 完整回收8/8 |
| 布局 | 桌面与390像素视口通过 |
| 上游停止 | Rust返回502，许可保持8/8 |

服务端累计下发1473704字节与客户端正文分别记录；
没有把其差额当成省流。目录单次抽样为6个TS、2557364字节，
只证明该时刻的滚动窗口，不代表长期磁盘、日志或录制保留成本。

约211ms只包含点击播放后的客户端启动，不含推流源启动、分片等待和采集到显示时差。
该路径为普通MPEG-TS HLS，不是LL-HLS、CMAF低延迟或WebRTC。

原始证据：

- `.artifacts/playback/xiu-v013-admission-20261107/receipt.json`
- `.artifacts/playback/live-gateway-20261107/acceptance.json`
- `.artifacts/playback/live-gateway-20261107/failure.json`
- `.artifacts/playback/live-v013-20261107/cleanup.json`

## 工具与交付边界

`start-xiu-live.ps1`核对固定二进制后启动有时限的推流，
`run.ps1 -LivePort`连接Rust入口，`verify-live.js`验证消费，
`stop-xiu-live.ps1`按进程号和精确启动时间清理，拒绝误停复用的进程号。
Xiu实验可能监听所有网卡，只在隔离开发环境运行。
本轮发布源已到时退出、Xiu已停止，常驻50551入口恢复为仅点播。

2项定向Rust测试通过，覆盖已有访问边界、流式首块、恶意文件名、重定向拒绝及取消许可回收；
定向Clippy零警告、Rust格式、JavaScript和4个PowerShell脚本语法通过。
新增直播浏览器验收通过；恢复点播后，限速暂停/恢复/停止和布局回归通过。
没有重复运行或冒用历史全工作区测试数量。

仍未完成：旧版本安全与维护审计、新版窄修复、真实设备、采集到显示延迟、
CPU/RSS和线路开销、鉴权撤销、录制恢复、房间迁移、物理集群及跨域推荐效用。
下一轮优先继续真实消费与明确反馈；实时媒体根另按发布/订阅、房间路由和故障域选择，
不把HLS兼容链推广为所有直播场景的最优解。
