# 跨端播放与消费契约

日期：2026-11-07。状态：点播授权、共同播放描述、内部消费及可选消费专用JWT入口已实现；用户登录/签发网关和原生适配待完成，不是三端SDK或原生验收完成声明。

## 三端是同级目标

| 客户端 | 播放器接入基线 | 当前证据 |
| --- | --- | --- |
| Android原生 | Media3/ExoPlayer适配 | 已参考和移植部分缓冲规则；未集成原生客户端，未做真机验收 |
| iOS原生 | AVFoundation/AVPlayer适配 | 已核对官方接口语义；未集成原生客户端，未做真机验收 |
| Web | hls.js，按浏览器能力选择原生HLS | 本机Chrome点播和普通HLS直播验收通过 |

服务端继续使用Rust。三端共享业务身份和控制协议，播放器适配及设备资源控制分别实现。
原生客户端不以WebView为默认前提，浏览器XHR与帧回调不成为三端共同前置条件。

## 当前接口与缺口

| 现有接口 | 当前用途 | 对接限制 |
| --- | --- | --- |
| `POST /v1/feed` | 按主体生成推荐并返回候选 | 内部服务鉴权；用户身份映射与客户端网关尚未接入 |
| `GET /v1/media/{sha256}/{filename}` | 固定内容、类型别名及Range读取 | 使用内部Bearer；不能把该服务令牌下发到手机或浏览器 |
| `GET /v1/playback/policy` | 固定目录的实验缓冲策略 | 控制器标记为`media3-buffer-v1`，不声明iOS具有相同执行能力 |
| `POST /internal/v1/playback/grants` | 可信网关按主体投影签发短期点播凭据 | 默认关闭；仍需要真实用户登录与权限网关 |
| `GET/HEAD /v1/playback/{token}/{sha256}/{filename}` | 三端共同签名媒体路径，保护主子清单及片段 | 当前覆盖固定点播，未提供单用户即时撤回或原生验收 |
| `POST /internal/v1/consumption/events` | 可信网关转交三端消费声明，复用Iggy写入和固定快照 | 不是公开用户网关；只检查单批顺序/口径，原生采集与跨批连续性未完成 |
| `POST /v1/client/consumption/events` | 默认关闭；以消费专用JWT绑定主体、决策、候选、实例、代次及平台，再复用内部消费链路 | 不是登录或签发服务；真实发行者、即时撤回及原生采集尚未接入 |
| 网关学习事件档案及训练导出 | 关联决策、可见性和明确反馈 | 尚未连通真实客户端身份、显示事实与授权撤回 |
| `labs/playback` | 本机浏览器验证与可选Xiu桥接 | 只允许本机；不是面向三端的生产播放网关 |

已实现接口、配置及边界见[三端播放授权与清单签名集成](三端播放授权与清单签名集成.md)。
机器可读响应契约位于`../vedioServer/contracts/playback-grant-v1.schema.json`。
HLS子清单与分片继承相同到期时间，但完整用户登录网关与生产撤权仍未完成。
消费凭据与本地公钥验证见[消费凭据根选型与三端入口集成](消费凭据根选型与三端入口集成.md)，
不能用普通登录JWT或内部服务Bearer代替该消费授权。

## 共同边界与进度

1. 内容与决策身份：候选ID、目录版本、媒体版本、推荐决策ID。
2. 用户级播放授权：签发和读取内核已实现；可信网关须先认证主体。
   过期覆盖主清单、子清单及分片的新请求，单用户即时撤回仍待实现。
   内部服务令牌仅用于服务间调用。
3. 能力声明：按实际播放器、系统与解码能力报告协议和编码支持，不仅根据平台名猜测；
   能力声明不授予资源访问权限。
4. 播放描述：点播描述v1已实现协议、版本、入口和有效期。
   能力协商与多路回退待实现；普通HLS的验证不代表WebRTC或LL-HLS验证。
5. 播放意图：后端下发启动、恢复及前向缓冲目标，按端声明可执行项与建议项；
   不要求AVPlayer执行Media3的完整滞回状态机或精确字节上限。
6. 消费事件：共同协议与内部接收已实现交互实例、代次、序号、单调时间、来源与测量口径；
   未知指标为`null`或缺失，不能冒充0。见[三端消费事件与跨域推荐输入](三端消费事件与跨域推荐输入.md)。
   固定来源归并已保留顺序到v2投影/训练，支持有证据的同秒反馈；
   原生请求结构保持`client-consumption-v1`，不能跨实例推断单调时间。
7. 明确反馈：喜欢、不喜欢等用户动作与推荐决策和候选关联；
   下载完成、位置跳转和静音后台播放不自动成为喜欢或有效曝光。

以上是同一对接边界中的必要项，不要求每次拉取片段都请求编排或推荐服务。
统计优先在端侧聚合，再进行有界批量传输；首帧、下载、可见性和偏好分开保存。

## 三端指标不能直接等同

| 指标 | Android | iOS | Web |
| --- | --- | --- | --- |
| 首帧 | `AnalyticsListener.onRenderedFirstFrame`，绑定媒体项与代次 | `AVPlayerLayer.isReadyForDisplay`表示首帧已可供显示，需保留该语义 | `requestVideoFrameCallback`属于浏览器帧回调 |
| 播放与等待 | 播放器状态及`isPlaying`等事件联合判断 | `timeControlStatus`和`reasonForWaitingToPlay`联合判断 | `playing`、`waiting`、`pause`等事件联合判断 |
| 网络字节 | 适配实际数据源的传输统计 | 访问日志累计值可能未知，不与XHR计数直接混算 | 当前实验为XHR正文进度，不含线路开销 |
| 缓冲控制 | 可适配Media3阈值和端侧字节预算 | `preferredForwardBufferDuration`是秒单位的偏好，不是精确硬上限 | hls.js配置与浏览器行为单独验证 |

每项必须保留测量来源。三类首帧信号都不自动证明物理屏幕出光或用户看到内容。
iOS访问日志的`numberOfBytesTransferred`为负时表示未知，应归一化为`null`，
不能转为无符号大数，也不能写成0。

## 验收与推进顺序

当前三个问题为：三端共同授权与播放/消费契约；实时媒体与物理集群；跨域推荐真实效用。
本轮先收敛第一个问题。

先完成共同契约及其Rust服务边界，再分别接入Android、iOS、Web。
协议夹具只能验证字段和状态语义，不能代替原生编译、真机显示或功耗测试。
发布判断要求分别记录三端的播放、切换、后台、切网、授权过期/撤回及资源成本，
不能用Chrome通过覆盖Android/iOS未验项。
