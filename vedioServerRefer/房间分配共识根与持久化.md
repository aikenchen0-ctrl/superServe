## HMM与边界

S0：直播凭据能绑定目标节点和启动代次，但两个节点仍可各自得到同房间授权。
IFR：分配只提交一次，旧请求不能覆盖新所有者，重启后不用重新猜测权威状态。
Sg：独立、可持久恢复的线性一致分配控制面，保留版本墓碑和受控成员变更；
媒体接受分配及排空/fencing作为下一条必要作用链。

使用者承担故障等待，平台承担复制与落盘，运维者承担持久身份与成员变更。
TC：最新且唯一的分配需要协调，协调增加网络、磁盘与依赖。
PC：分区时节点既想独立继续决策，又不能与其他节点独立产生冲突所有者。
本轮按功能分离：媒体继续沿用原执行内核，协调面只决定小型分配状态，
少数派停止确认，不通过本机TTL自动抢占。代偿是多数派可用性和控制提交成本。

三个问题按顺序推进：

1. 控制面已提交状态的唯一性、持久恢复与成员变化：本轮深入。
2. 分配到媒体的接受、排空、fencing和安全接管：继续开放。
3. S3条件写对照、真实负载、原生端与三低联合成本：继续开放。

## 候选的条件判断

| 路线 | 本轮决定 | 必须保留的代价或缺口 |
| --- | --- | --- |
| OpenRaft＋redb | 固定实现共识控制面实验根，直接依赖协议/数据库内核 | 新增46个外部锁文件包、常驻心跳、同步提交；不是总体成本最优证明 |
| 既有OpenDAL＋RustFS条件对象更新 | 保留低增量成本对照，不因新根被删除 | 需以相同房间语义验证后端条件更新、读取和故障边界；尚未做同负载对比 |
| Danube整套平台 | 不复制平台，只改编持久日志结构 | 会引入消息、watch、TTL、gRPC及额外业务状态 |
| TiKV或已有事务候选 | 暂不引入另一套数据库和控制组件 | 未做本地房间工作负载和运维成本比较 |
| 外部etcd/PostgreSQL路线 | 保留系统边界对照，本轮未运行 | 不符合本轮继续推进Rust控制服务的直接实现选择 |

这不是性能总排名。媒体对象存储仍为RustFS实验根，
OpenRaft不是替换媒体存储，也不用于推荐评分热路径。
如果S3条件写已能满足同等语义且总成本更低，新控制面仍应让位；
不能把“有了Raft”当作必须继续维护另一套平台的理由。

## 没有直接照搬的部分

固定Danube模块中的状态机与快照只在内存，本地读取也不确认多数派。
直接复制不满足本项目的全体重启和权威读取要求。
本地适配将状态、快照、投票、日志和压缩水位落到redb，
状态落盘后才公开投影，先持久化日志才确认Raft回调。
存储错误不折叠为空值；快照校验元数据，错节点/集群目录身份拒绝覆盖。
每个业务读取先执行OpenRaft的ensure_linearizable；metrics只作本地诊断。

redb默认缓存预算1GiB，已显式设为8MiB。
这是缓存配置，不是RSS、物理分配或生产内存上限。
状态最多64房间键，保留释放墓碑；单批16条日志、快照2MiB、
HTTP 8在途与3秒期限。同步落盘可能阻塞控制调度，尚需成本与IO隔离实验。

## 实验结果与反例

存储验证使用OpenRaft官方Suite::test_all，另验收并发命令/ABA与
状态、快照、投票、压缩水位的重开及身份冲突。
上游Suite在本地计为1个测试函数，不夸大成独立业务样本数。

四轮真实进程均通过，首轮与最终补充观察：

| 项目 | 结果 |
| --- | --- |
| 初始节点 | 三个独立协调进程，固定名册与服务认证 |
| 并发分配 | 200/409，仅一份已提交所有者 |
| 幂等、释放、ABA | 重试保持原修订，墓碑阻止null重建，旧释放不能覆盖新所有者 |
| 快照和压缩 | 触发后确认purged达到已确认记录修订 |
| 领导者退出 | 新领导者保留修订7及原分配 |
| 少数派 | 权威读503，写504，结果未知 |
| 超时提案预算 | HTTP超时后仍占用4个提案许可，最终超额请求503；恢复后许可释放 |
| 多数派恢复 | 先前超时写实际以修订10提交；没有自动重发或断言不存在 |
| 全体重启 | 原分配及修订7保留，拒绝再次初始化 |
| 成员变化 | 追加节点4为learner，经成员变更稳定到1/2/4，再写成功 |
| 文件大小 | 每节点redb逻辑长度约1.59MB；不是介质占用或成本排名 |

超时后提交是本轮最重要的实测反例。
客户端必须核对操作身份和权威状态，不能用HTTP失败反推没有副作用。
进程都在同一Windows主机，强杀不等于断电、跨物理故障域或真实网络分区。
正式采用前仍需持续压力、IO停顿、跨机网络、日志保留及迁移实验。
最后一轮稳定投票者为2/3/4，移出的是非领导旧成员；
本轮不覆盖主动移除当前领导者。
18项定向Rust测试函数（协调3、直播15）和全工作区所有目标Clippy零警告通过。
最终运行额外验证少数派超时提案预算，不从HTTP请求数推导提案已取消。
最后复跑同时核验中文格式错误响应，原始结果位于
.artifacts/room-authority/verification-20261107/cluster-release-check/receipt.json。
