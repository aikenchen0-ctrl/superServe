# 共享反馈入口与Iggy适配

启动：2026-11-06；最终验证：2026-11-07，Asia/Hong_Kong。
本轮完成HTTP适配、主题持久化策略预检和真实Iggy单节点合约；
正常重启、强杀恢复及权限反例通过，生产集群和真实手机显示仍未准入。

<重表述提示词为问题>如何接收可信网关的最小反馈，复用Rust共享日志形成固定证据快照，同时限制往返、传输、在途资源和不确定重试代价？</重表述提示词为问题>

## HMM与选型

现状S0：推荐决策与离线来源关联已经存在，但网关归档靠外部准备，缺少共享写入端。
理想功能IFR：反馈自然形成证据，不增加排序请求的共享持久化等待。
现实目标Sg：独立收集角色，通过已有日志服务写入；只确认明确持久化结果，
固定范围导出沿用现有格式，训练批准仍在后续来源关联阶段。

技术矛盾：提高确认强度增加反馈往返和稳定存储等待。
物理矛盾：反馈要立即返回，又必须在持久化边界之后才能确认。
本轮采用空间分离，把收集从排序、媒体和画像服务分开；
时间分离，把最小回调保存与训练批准分开；
批次合并只处理已经收集好的事件，不主动延时等候凑批。

| 候选路径 | 本轮取舍 |
| --- | --- |
| 继续手工网关归档 | 保留输入兼容，但不是共享在线入口 |
| 新写本地WAL或分布式去重库 | 不采用；增加另一份持久化和集群生命周期 |
| Apache Iggy共享事件日志 | 固定源码构建，窄HTTP适配及真实单节点合约通过；生产集群待准入 |
| 直接引入完整Iggy SDK及二进制协议 | 暂不采用；先冻结窄持久化/偏移契约，避免新运行依赖面 |

提交`71f29618ba04917fded0ef5cd085c206fef0ee49`，不是最新版本声明。
阅读HTTP消息客户端、JSON发送/消费结构、持久化选项与HTTP处理器。
实际改编面是路径、消息封装、确认和显式偏移读取；
未复制或修改共识、io_uring和存储内核。
Apache-2.0的LICENSE/NOTICE原文已保留。

官方配置与持久化文档均返回200并存档：

- `https://iggy.apache.org/docs/server/configuration`
- `https://iggy.apache.org/docs/server/durability/`

## 服务与配置

`VS_ROLE=feedback`仅开放通用探针、指标和
`POST /internal/v1/learning/events`，不开放Feed、排序、画像或媒体。
该实例使用空内部目录，不要求推荐目录或媒体根；不能配置模型、部署或画像写者。
路由需要独立`VS_SERVICE_TOKEN`，可信网关持有，不能直接把服务令牌交给手机用户。

配置样例已在`vedioServer/examples/feedback-config.json`：

```json
{
  "endpoint": "http://127.0.0.1:3000",
  "stream_id": 0,
  "topic_id": 0,
  "partition_id": 0,
  "source_id": "trusted-gateway",
  "data_kind": "synthetic",
  "operation_timeout_ms": 1000
}
```

端口3000对应固定参考的HTTP配置，不要误用其TCP端口8090。
配置文件没有密钥，Iggy Bearer凭证通过`VS_FEEDBACK_IGGY_TOKEN`注入。
收集凭证需要指定主题的追加权限及主题预检读取权限；
固定版本的`read_topic`还包含消息读取，不能宣称它是纯写凭证。
离线快照另用没有追加和管理权限的读取凭证。此权限耦合必须纳入部署审查。
实例配置：

```powershell
$env:VS_ROLE = 'feedback'
$env:VS_BIND = '127.0.0.1:8082'
$env:VS_FEEDBACK_CONFIG = '<配置JSON绝对路径>'
# VS_SERVICE_TOKEN和VS_FEEDBACK_IGGY_TOKEN由运行环境注入
cargo run --locked -p vs-service
```

流、主题和分区必须由受信运维预建；消息主题必须显式声明`persisted`。
坐标取自资源创建响应；首个流、主题或分区可以为`0`，不能将`0`当作未配置。
适配器不会创建资源、提升权限或自动修改持久化策略。
配置中source ID及synthetic/observed类型必须匹配提交归档，
切换为observed仍不自动证明真实显示。生产链路应使用受保护网络/TLS。

提交正文沿用`gateway-learning-events-v1`，最小事件仍为
`event_id/decision_id/subject/candidate_id/at/kind`，kind仅visible/like/dislike。
网关负责身份和渲染语义；收集端只校验来源、类型、时间、标识和批内冲突，
不读取推荐决策，不授予画像或行动权限。

## 确认与重试

确认必须同时满足：

```text
HTTP 201
AND Iggy-Durability为persisted
AND 恰好一条确认
AND 流/主题/分区与固定配置完全相同
-> 收集端202，返回批次SHA256、固定坐标及base_offset
```

服务对Iggy不发送`ack=none`。
缺头部、replicated、提前202、确认缺失/错坐标、网络失败或超时，
均返回503和`commit_state=unknown`及批次SHA256，不自动重发。
这表示可能已经保存，不是“没有写入”。
确认仅是日志服务对该批次的声明，不证明真实渲染，也不表示训练批准。

序列化载荷SHA256前128位作为Iggy消息ID，用于读回内容核对；
该ID不是签名、全局唯一证明或broker幂等机制。
网关可按同一event ID及同内容重传；保存层可能出现重复批次。
后续证据导出按事件ID去重，同ID不同内容拒绝；不能每次重试都生成新的event ID。
当前没有在线跨批全局去重，也没有exactly-once或自动不确定写入对账。

## 资源和扩展

单批最多64事件、原归档32KiB，HTTP请求入口仍受64KiB正文上限。
每实例最多4个远端操作，无界等待不进入内部队列；满额返回503。
每次远端等待100至5000ms，默认配置1000ms。
HTTP等待取消后远端任务仍持有许可至结束；正常退出排空已接纳任务。
进程被强杀后的未收确认写入仍需按未知结果处理。

两收集实例可以共享固定broker分区；收集侧无需共享本地文件。
这只解决收集实例的无状态扩展形式，不代表固定分区无限吞吐或broker多机已验。
分区容量、保留、主题重建、扩容迁移与故障域需另行设计。
不把numeric流/主题ID当不可变实例身份，也不自动跟随同名重建主题。
本轮没有全局顺序需求；事件可乱序，训练依赖既有显式时间/来源校验。

`/v1/metrics`报告确认/未知批次数和在途许可，计数重启清零。
反馈角色启动前及每次`/readyz`请求都会查询目标主题的线性一致元数据，
只有主题、目标分区和显式`persisted`策略均匹配时才返回`broker_checked=true`。
这只是该次主题元数据预检，不证明追加权限、仲裁健康、崩溃后稳定存储、保留期限或持续可用；
生产路由仍不能只据此准入。

## 固定快照

```powershell
cargo build --locked -p vs-service --example snapshot_feedback
./target/debug/examples/snapshot_feedback.exe <配置JSON> <起始偏移> <排他结束偏移> <新归档JSON>
```

命令使用读取权限的`VS_FEEDBACK_IGGY_TOKEN`。
只读显式offset，`auto_commit=false`；不使用next或latest，不写消费位点。
区间必须包含1至128条完整消息，每次至多取8条。
逐条校验固定分区、连续偏移、载荷长度、内容ID、来源和事件结构；
缺失、错分区、篡改或超长响应都会失败且不发布部分归档。
单响应最多512KiB，单条归档载荷32KiB，最终最多8192事件。
完整区间核对后，用既有不可覆盖发布原语写`gateway-learning-events-v1`。
命令输出文件SHA256及精确坐标，操作者将其纳入已有证据清单。
重传重复原样保留，后续统一关联消解；物理保留不足或offset已不可读时显式失败。

因此当前链路为：

```text
可信网关回调
-> feedback角色
-> Iggy固定分区
-> 显式区间归档
-> 已有决策/反馈来源校验
-> 新训练样本或统一模型回放
```

它不替代推荐决策日志的跨机复制，也不自动传播撤回到旧快照和模型。
