## 本轮核心矛盾

`S0`：日志只有用户、候选ID和动作；候选改标签或删除后，重启会改变历史含义或失败。
`IFR`：目录更新不改变已发生事实；新副本可以据同一历史重建有效状态。
`PC`：推荐需要新目录，历史必须保持提交时解释。
按时间分离：提交时冻结最小特征，重放时只用冻结事实，当前目录只解释新事件。

用户承担错误偏好和隐藏失效的后果，运营者承担迁移与恢复成本。
禁止静默猜测原目录、覆盖原日志、未知规则继续执行，以及旧目录副本混入新服务。

## 新日志契约

```text
profile-event-v2
  envelope.aggregate_id = 用户主体
  envelope.sequence = 该主体连续提交序号
  envelope.payload.event = 原事件
  envelope.payload.facts = 当时的领域、有序标签
  envelope.metadata.catalog_sha256 = 提交目录指纹
  envelope.metadata.projection_version = tag-additive-v1
```

候选ID已有于event，不另存完整候选、媒体路径、先验或整份目录。混合目录历史按各自冻结特征
重放；未知schema、投影规则、非法特征、主体不符及序号跳跃拒绝启动。
未来改变加权规则必须升级版本并提供明确重放处理。

目录不同仍在RPC边界返回409；历史可重放不代表所有API版本可混用。
旧日志无法自证当时目录，迁移要求操作者提供可信原目录与预先确认的SHA256。
散列只证明输入匹配，不能证明操作者选对了历史目录。

## 迁移入口

迁移器只读并锁住源文件，验证原目录、完整记录、去重、候选存在性、画像及输出容量，
完整写入、刷新和同步后才发布到不存在的目标。原文件不覆盖、已有目标不替换；
未完成尾部不在迁移时顺便修补。

在仓库根可用合成样例运行：

```powershell
cargo build --locked --manifest-path vedioServer/Cargo.toml `
  -p vs-service --example migrate_profile_log
$catalogHash = (Get-FileHash vedioServer/examples/profile-log/original-catalog.json).Hash.ToLowerInvariant()
./vedioServer/target/debug/examples/migrate_profile_log.exe `
  vedioServer/examples/profile-log/legacy.jsonl `
  .artifacts/migrated-profile-events.jsonl `
  vedioServer/examples/profile-log/original-catalog.json $catalogHash
```

父目录需已存在。真实迁移需停写、备份并明确原目录；本轮仅使用合成资料。
输出超过32MiB会拒绝，日志轮转尚未实现。Windows掉电持久性未实测，
Unix目录同步代码尚未在Unix编译和运行，不能据此宣称跨机或断电原子发布通过。
