## HMM 范围与取舍

S0：已有消费语义、Iggy写入和回放，但入口只接受内部服务令牌，不能直接交给客户端。
IFR：必要声明自然进入同一证据链，用户不操作内部凭证，服务不重复保存身份会话。
Sg：本轮提供默认关闭的消费专用短期JWT入口，受信发行者先核对身份和权限，
收集服务用固定公钥验证；后续复用已有消费协议、预算与回放。

行动者包括用户、凭据发行者、采集端、日志服务及维护者。
用户需要隐私、低上传量与稳定播放；发行者负责身份和权限事实；
收集端负责拒绝越界请求，日志负责持久化声明。签名不能把声明提升为真实观看证明。

TC：加强鉴权通常增加远程往返或会话存储；共享服务密钥又会扩大客户端权限。
PC：同一凭据需要能被各收集节点验证，同时不能让收集节点或客户端据此签发新授权。
采用空间分离：发行者持有Ed25519私钥，收集副本只持固定公钥；
每次批次在本地验签，不向身份服务器发RPC，不保存逐用户会话。
代偿是签发与配置轮换要求、签名计算、附加令牌字节和到期前撤回限制。

三个待办问题：

2. 登录与签发网关、原生Android/iOS/Web采集、逐主体撤回：继续开放。

## 候选与选定根

| 候选 | 本地核验 | 本轮判断 |
| --- | --- | --- |
| jsonwebtoken 11.1.0 | 固定发布包、发行者/受众/时间/算法校验、自定义密码后端接口、MIT许可 | 本轮选择；复用完整解析和校验，不复制维护JWT实现 |
| jwt-compact | 克隆`6b410eeff261738123d6993388183fde66df5e26`；主工作区为`0.9.0-beta.1`，声明不内建发行者等业务语义检查 | 保留对照；当前选择会增加手写校验和测试版适配代价 |
| 自行拼接JWT解析器或复制旧JWT实现 | 已有base64/ring不等于已有完整JWT验证器 | 不选；不为减少几个包而维护另一份认证协议实现 |

这是当前约束下的职责选型，不是吞吐或安全性的通用最强排名。
`jwt-compact`的主分支声明与README不被视为所有历史发布的功能结论。

实际依赖锁定`jsonwebtoken =11.1.0`，关闭默认PEM及整套密码后端；
通过官方`CryptoProvider/JwtVerifier`接口接已有`ring =0.17.14`。
只支持Ed25519验签；签发和JWK辅助调用返回错误，不使用会panic的占位实现。
没有复制或重写Ed25519，也不引入新的身份服务器或数据库。

新增锁文件包四个：`jsonwebtoken`、`signature`、`rand_core`、`zeroize_derive`。

## 接口与签发责任

可选入口：

```text
POST /v1/client/consumption/events
Authorization: Bearer <消费专用短期JWT>
```

正文沿用`client-consumption-v1`，没有修改内部日志或模型格式。
内部路径继续要求服务令牌；消费凭据不能读取ready、metrics或调用内部写接口。
只有feedback角色可加载`VS_CONSUMPTION_ACCESS_CONFIG`，配置最多16KiB。
省略配置时不注册公开路径；既有客户端和内部配置不需要迁移。

配置结构：

```json
{
  "issuer": "https://identity.example",
  "audience": "consumption-ingress",
  "keys": [
    {
      "kid": "issuer-current",
      "public_key": "<发行者的32字节原始Ed25519公钥，无填充Base64URL>"
    }
  ]
}
```

这是配置格式示意，公钥占位符必须替换为实际受信公钥。
最多四个不同kid；配置不包含私钥，不从令牌指定地址下载密钥。
固定公钥轮换需要部署者协调，当前不热更新或自动发现JWKS。

JWT头部固定使用`alg=EdDSA`、`typ=vs-consumption+jwt`及已配置`kid`。
拒绝其他算法、普通登录JWT类型、未知kid、带值的证书/远端密钥/压缩及critical扩展。
受信发行者必须先认证用户，核对真实推荐决策、候选权限、平台及交互实例，再签发以下载荷：

```json
{
  "iss": "https://identity.example",
  "aud": "consumption-ingress",
  "sub": "subject",
  "iat": 1794000000,
  "nbf": 1794000000,
  "exp": 1794000120,
  "source_id": "trusted-gateway",
  "data_kind": "observed",
  "decision_id": "<64个小写十六进制字符>",
  "candidate_id": "video",
  "interaction_id": "interaction",
  "generation": 1,
  "platform": "android"
}
```

数值仅示意，不是可直接使用的当前令牌。
最长有效期300秒，零时间宽限；要求发行时间不晚于服务时间、nbf不早于iat、
当前时间位于`[nbf, exp)`，正文上传后提交前再检查到期。
API不提供签发端点，也没有新增登录流程；不能把任意客户端自报字段直接签成可信授权。

`sub`绑定正文subject，其余来源、数据类别、平台、决策、候选、实例和代次逐项一致。
事件原UTC秒必须在凭据窗口内，再由原消费验证器检查未来时间、顺序、来源和容量。
不改写秒数或单调时钟。collector配置中的来源与数据类别校验仍继续执行。
手机切换内容、重置代次或更新身份范围，需要相应的新授权。

两个JSON Schema分别为：

```text
vedioServer/contracts/consumption-access-config-v1.schema.json
vedioServer/contracts/consumption-access-v1.schema.json
```

JSON Schema负责结构，签名、时间关系、固定资源绑定及密钥一致性由Rust完成。

## 成本与边界

单次Bearer最多4096字节，先鉴权后读取JSON正文。
验签通过四个在途许可和阻塞任务执行，请求取消不提前释放已经启动的任务许可。
验签成功后复用原Iggy四写入预算、取消守卫及persisted确认；unknown不自动重发。
本轮不新增每批远程身份RPC、逐片RPC、用户会话表或后台轮询器。

令牌只出现在请求头，不写入原始消费载荷、快照或模型。
每个批次仍附带JWT字节，重复提交仍会增加日志成本。
没有恰好一次承诺、在线跨批去重或物理观看证明。
有效期内单主体即时撤回未实现；删除公钥属于发行密钥范围的撤回，不能代替单用户撤权。
离线导出的排除名单继续执行，但它不等于在线即时撤回。

网络边界仍需部署者提供TLS、入口限流与浏览器同源路由；
本轮没有开放任意跨域CORS，也没有引入WebView或改写原生播放器。
原生SDK、真机、用户登录及真实发行者尚未接入。
受信发行者若签发了不真实的决策，签名只能证明发行者授权；
既有训练导出仍会核对决策日志、主体、候选、权限和时间。
