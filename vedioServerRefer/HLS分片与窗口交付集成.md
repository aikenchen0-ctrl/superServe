# HLS分片与窗口交付集成

日期：2026-11-06。范围：普通MP4到fMP4/HLS的离线实验集成。
当前不是完整CMAF规范认证、播放器产品或生产集群验收。

<重表述提示词为问题>如何复用Rust分片内核，让推荐结果指向可按观看窗口请求的音视频片段，同时保留原编码与播放时间线，并控制处理内存、存储对象和网络请求的新增代价？</重表述提示词为问题>

## HMM取舍

现状已有MP4索引前置、不可覆盖发布、固定目录、推荐与Range数据面。
理想功能是只搬运当前消费所需的数据，不因封装破坏原编码、时间线和恢复边界。
本轮现实目标是“源MP4 → 音视频分片及清单 → 固定目录 → 推荐/Feed地址 → 真实HTTP解码”。

待解问题依次为：分片内核及时间线、清单与发布、观看窗口与反馈控制。本轮深入第一项，
只实现后两项所需的最窄通路；自适应预取、学习推荐与客户端埋点继续独立验证。

付费者承担CPU、出口与对象存储；观看者需要可播放和较少等待；发布者需要可重试；
运维者需要有界内存与稳定版本。DAU、真实设备、首帧SLO及预算尚未提供。

技术矛盾是分片越小，取消与按需读取越细，但对象、清单和请求开销上升。
核心矛盾是同一尚未观看区间为减少等待需要提前下载，为减少浪费又需要不下载。
本轮按时间和条件分离：先提供独立片段，客户端后续依据缓冲、网络和观看概率决策。
服务器不在推荐请求里在线重封装，也不默认拉取全部片段。

## 实现边界

`publish_hls`是可信离线工作进程调用的阻塞函数，不放进在线HTTP请求：

1. 源文件先封存，最多32MiB，仅一条H.264视频及可选一条AAC音轨。
2. 每轨最多25000个样本，同级盒子最多4096个；预检采样表数量、实际字节及声明载荷总量。
3. 拒绝分片输入、多个采样描述、带符号CTTS、空编辑、多段编辑和非正常播放速率。
4. 目标分片1至6秒，默认命令示例用2秒；切分依赖原片关键帧，实际单片允许至30秒。
5. 每轨最多512片；沿用既有媒体散列验证、不可覆盖对象和目录版本发布。

当前库会把源文件及采样载荷放入内存，因此它不是64KiB全程流式处理；
32MiB是源文件上限，不是进程RSS上限。重复块引用的声明载荷总量必须不超过源文件长度，
避免小文件通过采样表扩张复制内存。一个离线进程一次处理一个文件；跨机任务队列和调度未接入。

适配层保留原电影时基、轨道矩阵与单段连续编辑列表，将fMP4初始化头的电影/轨道时长置零。
这针对源音视频时间线的机制缺口，避免只对当前测试文件改时间常量。
内部压缩码流、容器偏移与分片写入由上游负责；没有自行实现编码器。

所有资产采用`media/<sha256>`。叶子片段先发布，再生成轨道清单和主清单，最后提交目录：

```text
音视频初始化片及媒体片
    -> 各轨道M3U8
    -> 主M3U8
    -> 固定目录版本
    -> 推荐与Feed返回主清单地址
```

清单引用同源的`/v1/media/<sha256>/media.mp4`和`/v1/media/<sha256>/index.m3u8`。
别名仅允许这两个名称，必须匹配已发布资产的内容类型；仍走原鉴权、ETag、HEAD、Range、
背压、取消和缓存路径。不是任意文件路径或远程URL代理。
推荐与Feed用现有候选和资产哈希索引，为HLS返回带后缀的入口，最多处理50个返回项。

目录失败可能留下未引用媒体，保留/GC仍待实现。本命令创建单候选新目录，不合并原目录。
本轮发布入口只接本地FS；生成对象仍沿用FS/S3读取契约，HLS专门的S3多机实验尚未执行。

## 运行与验证

在`vedioServer`中执行：

```powershell
New-Item -ItemType Directory -Path '.local/hls-publication' -Force | Out-Null
cargo run --locked -p vs-service --example publish_hls -- `
  '.local/hls-publication' 'input.mp4' 'hls-demo-v1' 'clip' 2
```

启动服务继续使用`VS_PUBLICATION_ROOT`、`VS_CATALOG_RELEASE=hls-demo-v1`及相同FS根。
`GET/HEAD /v1/media/<主清单散列>/index.m3u8`需要服务Bearer，由可信网关连接客户端。
客户端不持有服务密钥。固定目录与媒体实例可复用既有副本机制，当前没有新增自动扩容保证。

独立验证：

```powershell
cargo build --locked -p vs-service --bin vs-service --example publish_hls
./labs/video/run-hls-contract.ps1 -Ffmpeg '<原生ffmpeg.exe的绝对路径>'
./labs/video/run-hls-contract.ps1 -Ffmpeg '<原生ffmpeg.exe的绝对路径>' `
  -InputVideo 'crates/vs-service/tests/fixtures/mp4/h264-aac-tail.mp4' -TargetSeconds 1
```

Windows须使用原生可执行文件，批处理包装会破坏HTTP头换行。
播放器保留默认HLS扩展名检查，使用`-copyts`逐轨比较解码记录的时间戳、时长、长度与SHA256；
不把不同输入的自动起始时间归一化或音视频交错顺序当作媒体时间线。

两个本机样本的独立HTTP解码均通过：8秒/2秒目标为284条记录，2秒/1秒目标为71条。
8秒样本源文件94110字节，全部发布资产98408字节；初始化加首个音视频片23718字节。
这个窗口字节量不含清单、协议、重传和播放器后续预取；完整封装增加4298字节，
不作为压缩率或实际用户节省比例。原始证据见`problem-space/hls-packaging-evaluation.json`。

真实Android/iOS/浏览器首帧与卡顿、滑动取消、动态预取、CPU/RSS、CDN命中、学习推荐、
多码率编码与多机扩容继续开放。下一步优先把观看窗口和实际消费/取消事件关联起来。
