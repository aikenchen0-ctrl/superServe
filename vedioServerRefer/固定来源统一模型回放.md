全量模型排序、精确Top-K和分组上界剪枝；新增可选模型召回漏召回审计。

## HMM取舍

S0：三条路径已有合成矩阵，来源导出器却只输出有明确反馈的训练样本。
IFR：一次可信最小快照就能同时核对结果、计算和反馈覆盖，用户无需改写历史画像。
Sg：共用来源校验，全部窗口请求做成本回放；只有明确反馈参与部分标签诊断。

技术矛盾：仅挑有反馈请求可以少做计算，却会扭曲实际请求分布。
物理矛盾：无标签请求要被剔除才能计算监督指标，又要被保留才能评价请求成本。
解决方式是整体与部分分离：成本样本和标签子集独立计数；缺少反馈保持未知。

主要代偿是离线冻结和读取快照、全目录对照计算、结果存储及数据来源信任。
系统没有消除物理计算成本，也没有通过散列获得真实显示或授权证明。
本轮只深化统一回放输入；实际采集、撤回、多机三条问题保持可见。

## 输入与运行

继续使用`learning-evidence-export-v1`清单。其历史字段`train_before`在本回放中
表示决策提交和反馈的共同排他截止时间，不触发训练。
目录、日志、网关归档及模型内容必须匹配指定指纹；来源只允许清单目录内的普通相对路径，
解析后不得越界，活动写者不能直接作为快照。

新增配置：

```json
{
  "schema": "model-evidence-replay-config-v1",
  "decisions_from": 1000,
  "model": {
    "path": "prior-model.json",
    "sha256": "<固定模型SHA256>"
  },
  "samples_per_query": 24,
  "warmup_per_query": 6
}
```

模型路径也相对证据清单目录。采样数为6至96且为6的倍数；
预热为0、6或12，三路径的六种顺序均衡轮换。
启动方式：

```powershell
cargo run --release --locked --offline -p vs-service --example replay_model_evidence -- `
  <目录JSON> <证据清单JSON> <回放配置JSON> <不存在的报告JSON>
```

标准输出是报告指纹、字节数、查询数和保真收据，详细报告写入指定新文件。
成功退出0；无效输入退出1且不发布报告；若三路不一致，保留诊断报告并退出2。
已有报告不覆盖，重复运行应使用新输出路径。
调试构建可做功能验证，报告记录debug/release；成本结论只使用本轮release收据。

可选召回审计配置：

```json
{
  "recall_audit": {
    "require_full_retention": true
  }
}
```

审计使用同一历史请求和冻结画像，先用本地完整分组亲和度参考选最多128个候选，
再用固定模型重排，与全量模型Top-K比较。它不是远端Qdrant复现，也不把旧亲和度
当作模型分数上界。关闭严格门禁时只输出诊断；开启后，只有存在可评价模型结果且
所有模型Top-K均被保留才允许CLI成功退出。门禁失败仍原子发布报告并返回退出码2；
输入无效或重复输出仍返回退出码1。无标签请求进入成本与漏召回审计，但不生成负标签；
无可评价候选不构成通过。

配置仍使用`model-evidence-replay-config-v1`，新增字段是显式可选扩展；旧二进制会拒绝新字段，
须先升级回放工具再启用。不开启时该字段从规范化配置及回执中省略。
每条请求的本地召回和子集重排新增两次逻辑目录遍历单位，纳入原五千万预算；
额外计时是单次诊断，不参与原三条精确路径的均衡顺序，不能比较为性能收益。
报告输出缺失的公开候选ID，不复制主体或原始画像；报告仍应与来源数据按授权范围管理。

## 规则与预算

一个决策进入窗口必须同时满足：

```text
主体未被排除
AND 快照时间不早于decisions_from
AND 提交时间早于train_before
AND 决策链、目录、授权投影和历史返回候选有效
-> 参与三路回放，无需可见或明确反馈
```

模型训练截止必须不晚于`decisions_from`，模型仍须符合当前目录和结构校验。
这能挡住明显的同窗口评价，但截止字段本身不能证明全部训练来源真实，也不能证明
不同时间窗口来自独立用户、独立偏好机制或无重复数据。

反馈沿用既有规则：同主体、已返回候选、可见性早于明确偏好、反馈早于截止。
重复同内容去重、重复冲突拒绝；未显示/未反馈不产生负标签。
反馈对应的冻结画像在可见时已过期或越权时拒绝。
全部证据先校验，再构建分组索引和开始计时，不用当前画像补历史。
跨副本同一客户端请求ID保留为不同服务端决策，不误合并。

最多1000条窗口决策、32MiB来源输入合计含模型、8MiB目录，
清单和配置各最多256KiB，模型最多128KiB，最终报告最多16MiB。
全部计划评分路径的“目录项数×路径次数”不超过五千万单位，
包含单次基线/工作计数探针和预热/测量；该口径不等于实际ID检查数、CPU指令、RSS或时间保证。
超过预算显式失败，不静默丢掉尾部决策或按是否有标签抽样。

## 报告解释

报告包含原始日志/网关/模型指纹、规范化结构指纹、窗口、被排除和窗外计数、
全部窗口决策、可见性/明确反馈覆盖、标签基线与模型的部分标签指标、
三路逐字段和浮点位保真、原始计时、评分/过滤工作量及索引布局。
结构指纹是按已解析Rust结构重新序列化的SHA256，不是原JSON文件指纹或RFC规范化JSON。

未评价的候选不会生成负标签。诊断NDCG/Recall/MRR只基于已明确评价的历史返回候选；
无正标签时为null，未知候选不增加已知增益。
因此即使显示NDCG=1，也不能推出真实全候选效果好。
报告固定声明`partial-label-diagnostic-only`，无偏评价、真实渲染、物理集群、
完整训练来源与生产准入都不标成通过。
也不声称重现历史策略：历史返回可能来自另一模型或候选路径。
