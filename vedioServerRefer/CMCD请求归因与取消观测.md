# CMCD请求归因与取消观测

日期：2026-11-06。范围：Q0/Q1的可选请求观测，不改变推荐权重、授权或播放器控制。

## HMM取舍

现状已有可解码HLS、固定目录和Range，但媒体统计只有进程合计，无法解释同一次取消或窗口请求。
理想功能是在原请求上携带最小上下文，不额外调用逐会话数据库，并能将事实与客户端声明分开。
本轮目标是可选CMCD请求字段解析、媒体正文结束观测，以及真实网络的首窗口/完整/取消探针。

本轮三个待解问题是请求归因、消费/取消语义、窗口决策；深入前两项的最小闭环，
窗口策略、真实渲染反馈和学习推荐仍是开放问题。

付费者需要准确的CPU/字节成本，观看者需要少等待，运维者需要观测有界且不扰动默认链路。
核心矛盾是为优化需要更细观测，而每请求解析、关联和日志会增加资源开销。
按条件分离：默认关闭，仅在明确启用的媒体实例收集；固定字段、有限输入，不维护高基数会话表。
首窗口和实际消费之间仍缺少播放器反馈，不能用服务端字节填充这个断点。

## 接入方式

`VS_DELIVERY_OBSERVATION=1`只允许`media`或`all`实例。缺省或`0`关闭，其他值拒绝启动。
业务接口不增加往返；观测中间件在服务鉴权之后运行，未经授权的请求不进入CMCD解析和计数。
现有`/v1/metrics`新增`delivery`，关闭时为`null`。

支持四个CMCD头，存在任一头时忽略URL中的CMCD；无头时解析唯一的`CMCD`查询参数。
头部合并输入最多4096字节；查询串最多12288字节、解码后最多4096字节。
复用RFC 8941解析模式，识别：

- `sid`：不记录原始会话值，只输出SHA256；这不是匿名化保证，仍需使用随机临时ID。
- `cid`：当前限制为64字节内的业务标识符。
- `vs-rid`：本项目扩展，用于携带推荐/Feed返回的`x-request-id`，最长64字节。
- `bl`、`d`：缓冲和对象时长声明，单位毫秒，最大24小时。
- `mtp`、`br`：吞吐和编码码率声明，单位kbps，最大10亿。
- `ot`、`su`、`bs`、`v`：对象类别、启动、缓冲饥饿和版本。

键顺序不限；重复键使用最后一项。未知键可以忽略，但仍须满足结构化字段语法。
语法错误、已识别字段类型/范围错误会丢弃整个观测报告，媒体请求继续按原语义处理。
`v`缺省按v1；显式其他版本记为不支持，不解释v2的内列表或事件语义。
这比完整标准接收器更保守，属于有限子集，不冒充全量CMCD验证器。

所有值均为客户端声明；`cid`和`vs-rid`不授予授权，不证明曝光或叶子片归属。
不将它们写入用户画像，不基于它们限速，也不执行`nor`等预取提示。
推荐请求与媒体请求的可信关联仍需要网关或受信客户端约束。

每次已鉴权媒体请求最多输出一条`media_delivery`结束日志，字段包括目录指纹、
资产指纹、响应状态、范围、预期/实际产出字节、响应头等待、生命周期和受限客户端报告。
正文以原流的背压驱动，不额外读取后续数据，也不分配整片缓存。

结束状态区分：

| 状态 | 含义 |
| --- | --- |
| `complete` | 已向HTTP层交出声明的全部媒体字节，不证明终端收到或渲染 |
| `dropped` | 正文未交足即被本地释放，不直接证明用户滑动或远端停读 |
| `failed` | 底层正文错误或提前EOF，不能当正常客户端取消 |
| `before_headers_drop` | 等待处理响应头时本地任务被释放 |
| `no_media_body` | HEAD、304、416、错误响应等不追踪媒体正文；错误JSON体不计为媒体字节 |

完整最后一块交出后不要求额外轮询EOF，避免把正常结束误记为取消。
`active_bodies`和各计数为独立进程内原子快照，不是跨机事务、持久会话库或观看账本。
启用后每请求解析和同步日志都有代价；默认关闭不代表启用时免费。

## 可复现实验

在`vedioServer`中：

```powershell
cargo run --locked -p vs-service --example delivery_trace -- 'input.mp4' 2
```

探针使用可信本地鉴权，先请求推荐，再读取主/轨道清单、初始化片及首个音视频片，
随后补齐其余片段，并对一个媒体片在首块后取消。每次请求都带同一推荐ID与临时会话声明。
应用收到字节、响应状态、时间和散列单独记入JSON；服务器记录经stderr输出。
实验服务器结束时退出，端口释放；没有让客户端获得生产服务密钥。

CMCD的缓冲和吞吐值来自合成输入，`application_received_bytes`仅指HTTP客户端实际轮询的字节，
不代表渲染、观看或有效消费。探针不为每请求时间计算无意义的P95，也不声称模拟了真实播放器。

真实HLS解码可使用既有脚本的`-ObserveDelivery`开关，继续逐轨验证原时间线与帧散列。
最终测试、收据和限制见`problem-space/cmcd-delivery-evaluation.json`。

下一步依据真实端侧的缓冲、渲染、滑动取消与网络轨迹，验证无预取/有限窗口/动态策略；
再把反馈接入跨域推荐的质量评价，避免直接用媒体下载次数作为兴趣权重。
