## 问题边界

`S0` 是全目录标签排序可以工作，但候选量随目录增长；Qdrant 标签召回和场景先验能把排序
候选从 1,076 降到 606 或 607，却可能在排序前漏掉真实有用候选。

`IFR` 是只计算必要候选，同时保持真实正反馈的覆盖。当前 `Sg` 是一个可重放、无未来信息
泄漏、能同时报告质量和候选量的评估器。评估器不把无标签候选当负反馈，也不把隐藏后不可见
的正标签算作推荐失败。

核心矛盾是：

```text
排序候选数量下降 -> 排序阶段工作量下降；总请求成本仍需实测
排序前裁剪过强 -> 正标签覆盖下降
```

本轮使用 HMM 的时间分离：画像事件必须早于 `history_cutoff`；查询标签必须满足
`query_at < observed_at <= label_window_end`。未来标签只用于评价，不进入画像。

## 评估器

入口：

```powershell
cargo run --locked --manifest-path vedioServer/Cargo.toml `
  -p vs-service --example recommendation_replay -- --demo
```

也可以使用外部文件：

```powershell
cargo run --locked --manifest-path vedioServer/Cargo.toml `
  -p vs-service --example recommendation_replay -- `
  <catalog.json> <trace.json>
```

轨迹格式包含 `catalog_version`、`catalog_as_of`、`history_cutoff`、有序行为事件及查询的
未来标签。输入预检拒绝重复事件、未知候选、时间泄漏、重复标签、错误场景和无效主体。

报告包含：

- 全量与有限召回的 Recall@K、NDCG@K、MRR。
- 全量 Top-K 在有限召回中的保留率。
- 正标签进入候选集的比例。
- 去重后的排序候选数、目录覆盖和逐请求退化数。
- 按请求场景切片的同类指标。

NDCG 使用指数相关度 `2^relevance - 1` 和 `log2(rank + 2)` 折扣；未标注候选不当作负反馈。
样本没有正标签时不计入宏平均质量，但仍报告该查询数量。隐藏策略使正标签不可见时单独记录，
不把策略合规错误混为召回错误。

## 当前结果

固定诊断轨迹含 7 个查询、5 个有正标签查询。比较结果：

| 指标 | 全量排序 | 有限召回 |
| --- | ---: | ---: |
| 排序候选总量 | 1076 | 606 |
| Recall@K | 0.800 | 0.500 |
| NDCG@K | 0.570 | 0.410 |
| MRR | 0.500 | 0.400 |
| 全量 Top-K 保留率 | 1.000 | 0.967 |

真实 Qdrant 1.20.0 重放得到 607 个排序候选和相同两条质量下降：mixed-video 及
mixed-cross-domain。它们先查询 rust 正兴趣，却不在召回分数中扣除 noise 负兴趣；
多标签干扰项占用召回预算，tail-video 没有进入后续排序。这个路径在真实索引上得到复验，
不等于线上损失已有同样规模。门禁保持失败。

## 下一步修复

1. 保持候选预算，比较包含负兴趣的召回能否对齐最终排序。
2. 比较分组或亲和度上界召回，及增大预算的成本对照，不预设某一路必然最优。
3. 把诊断集与之后的留出集分开，再用真实时间切分数据复验质量、覆盖和成本。

当前没有把 607 个排序候选误算为全部请求只处理 607 个候选。离线精确参考仍扫描全目录，
真实索引有自己的检索成本；局部单次微秒计时不提供生产 CPU、内存、P95/P99 或带宽结论。

## 复现与真实输入

三个模式由 `REPLAY_RECALL_MODE` 选择：

- `exact-sparse-reference`：默认，本地穷举正向标签点积，按 ID 解同分；用于检查截断路径。
- `prior`：仅使用现有场景先验，作为少计算候选对照。
- `qdrant`：查询通过 `VS_QDRANT_URL` 配置的已发布索引，真实故障直接中止评估，不静默降级。

完整复现合成轨迹、真实索引及三模式报告：

```powershell
cargo build --locked --manifest-path vedioServer/Cargo.toml -p vs-service `
  --example recommendation_replay --example publish_recall
& ./vedioServer/labs/qdrant/run-replay.ps1 `
  -Binary .artifacts/downloads/qdrant-1.20.0/extracted/qdrant.exe
```

脚本只启动自己拥有的回环 Qdrant，使用临时密钥和独立数据目录，保存输入、发布及三份报告
后回收进程。`run.json` 的 completed 表示实验执行完成，quality_gate_passed 表示质量门禁；
本次前者为 true，后者为 false。首次脚本因日志同名失败，旧目录保留，没有用于质量结论。

导出输入模板：

```powershell
& ./vedioServer/target/debug/examples/recommendation_replay.exe --demo-catalog
& ./vedioServer/target/debug/examples/recommendation_replay.exe --demo-trace
```

外部轨迹的最小结构如下；候选 ID 和版本必须与实际目录一致：

```json
{
  "schema": "recommendation-replay-v1",
  "data_kind": "observed",
  "catalog_version": "demo-v1",
  "catalog_as_of": 100,
  "history_cutoff": 150,
  "events": [
    {"at": 110, "event": {"event_id": "e1", "subject": "user-a", "candidate_id": "video-rust", "kind": "like"}}
  ],
  "queries": [
    {
      "request_id": "q1", "subject": "user-a", "at": 200, "label_window_end": 220,
      "domains": ["video"], "limit": 10,
      "labels": [{"candidate_id": "video-rust", "relevance": 3, "observed_at": 210}]
    }
  ]
}
```

上例展示格式，不是提供了真实观察证据；data_kind 和 catalog_as_of 是输入者声明，
工具不能自行证明候选历史特征没有泄漏。该版本使用固定训练窗口，所有评估查询只看到切分点
之前的历史；评估窗口中不继续回写行为，也不模拟逐条在线学习。

容量上限为目录 8 MiB、轨迹 32 MiB、历史 100,000 条、主体 10,000 个、查询 1,000 条，
每查询最多 1,000 个判断、K 为 1–50。相关度使用 0–3，0 表示已判断但不相关，缺省标签
表示未知。没有有效正标签的查询返回 null 质量指标，仍保留在数量及覆盖统计中。
隐藏后的正标签数另行报告，不能悄悄隐藏其分母变化。

追加 `--require-no-regression` 时，只要一条可评价请求的 Recall/NDCG/MRR 相对全量下降，
或没有任何有效正标签，就以 2 退出。输入或运行错误退出 1，完整且满足所配置门禁退出 0。
没启用门禁时退出 0 只表示评估运行完成，报告仍会显示退化。请求场景切片可以相互重叠，
不是互斥样本分组；同分截断边界也可能使本地参考与 Qdrant 候选数不同。
