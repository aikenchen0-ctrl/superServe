# Rust 服务与集群选型

## 一、语言边界

第一方在线代码使用 Rust。边界如下：

| 面 | 语言 | 说明 |
| --- | --- | --- |
| 在线 API、调度、缓存、存储适配 | Rust | 统一部署和资源控制 |
| 视频算法编排、质量门禁、分片 | Rust | 调用原生编解码器 |
| 特征读取、召回、排序调度 | Rust | 控制尾延迟和资源上限 |
| 训练、离线实验、模型搜索 | Python 可保留 | 保持 PyTorch 生态和论文复现能力 |
| 编解码内核 | C、C++、汇编 | FFmpeg、SVT-AV1、libaom 等成熟实现 |
| 模型推理后端 | 独立服务 | ONNX Runtime、TensorRT 或等价运行时 |

“全 Rust”指的是第一方控制面和数据面统一，不是重写编解码内核或训练生态。

## 二、基础组件

| 能力 | 首选 | 备选 | 选型原则 |
| --- | --- | --- | --- |
| 异步运行时 | Tokio | 无 | 统一取消、背压和任务生命周期 |
| 外部 HTTP | Axum、Tower、Hyper | pingora 自定义服务 | 普通 API 与控制面 |
| 内部 RPC | Tonic、Protobuf | Arrow Flight | 强类型且可演进 |
| 列式数据 | Arrow、Parquet、DataFusion | 自研列式格式 | 特征和离线分析复用 |
| 元数据事务 | TiKV | PostgreSQL 分片 | 水平扩容和事务边界 |
| 事件流 | Apache Iggy | Kafka 兼容服务 | 行为事件、反馈和转码任务 |
| 对象存储 | RustFS | Garage | 媒体正文和不可变产物 |
| 对象访问抽象 | OpenDAL 风格接口 | S3 SDK 适配层 | 后端可替换 |
| 向量检索 | Qdrant | LanceDB 或独立向量服务 | 在线召回和候选检索 |
| 进程内缓存 | S3-FIFO | SIEVE | 真实 trace 命中率优先 |
| 边缘代理 | Pingora | Nginx、ATS | 回源合并、Range 和缓存 |
| 可观测性 | OpenTelemetry、Prometheus | 统一日志导出 | 延迟、字节和资源一体观测 |

## 三、状态放置

在线服务只持有可重建状态。以下数据不能只存在进程内存中：

- 资产版本和发布状态。
- 用户画像的有效投影。
- 召回和排序模型版本。
- 转码、预取和删除租约。
- 幂等键和投递位点。

状态放置规则：

| 状态 | 位置 |
| --- | --- |
| 资产清单和小型索引 | TiKV |
| 媒体正文和不可变分段 | 对象存储 |
| 用户行为和反馈事件 | 事件流加对象存储归档 |
| 在线画像投影 | 画像服务加有界缓存 |
| 向量和倒排索引 | Qdrant 或专用索引服务 |
| 任务租约和幂等状态 | TiKV 条件写 |
| 模型权重和版本 | 对象存储加模型注册表 |

## 四、分布式任务模型

所有异步任务采用声明、租约、心跳、提交：

1. 控制面先写入唯一任务声明。
2. 工作节点使用条件写获取定时租约。
3. 工作节点定期续租并上报进度。
4. 产物先写不可变存储并完成校验。
5. 最后提交版本指针和业务状态。

任务重试必须幂等。工作节点失联后，其他节点可以接管，但不能重复发布未完成的
资产版本或画像版本。

## 五、分区键

| 对象 | 分区键 | 原因 |
| --- | --- | --- |
| 媒体分片 | `asset_hash` 加 `variant` 加 `segment` | 内容寻址，缓存稳定 |
| 用户在线请求 | `tenant_id` 加 `user_id` | 画像状态局部性 |
| 行为事件 | `user_id` 加 时间桶 | 长序列读取连续 |
| 内容索引 | `content_id` 或语义 ID | 召回分片 |
| 删除任务 | `subject_id` 加 依赖类型 | 全链路撤销 |
| 模型任务 | `model_id` 加 版本 | 可回滚和并行训练 |

分区键不能只使用自增 ID 或单一热门实体，否则会在爆款视频或大账号上形成热点。

## 六、多机扩容

扩容对象和动作：

| 扩容对象 | 动作 | 必须保持的不变量 |
| --- | --- | --- |
| API 节点 | 增加无状态副本 | 请求不依赖本地磁盘 |
| 推荐节点 | 按用户和场景分区增加副本 | 画像版本可重建 |
| 转码节点 | 加入工作池并消费任务分区 | 任务可租约接管 |
| 对象存储节点 | 加入复制环并再平衡 | 发布对象持续可读 |
| 向量索引节点 | 分片加副本迁移 | 查询结果版本一致 |
| 边缘节点 | 加入 DNS 或负载均衡权重 | 内容键稳定，回源可合并 |

## 七、降级顺序

系统压力上升时按以下顺序降级：

1. 关闭非关键在线实验和深层列表生成。
2. 缩短预取范围，保留当前观看分片。
3. 减少召回路数，保留内容向量、协同和热门兜底。
4. 使用缓存画像和上一版模型，停止近线刷新。
5. 进入只读播放和只读画像状态，暂停写入和重建索引。

不能为了维持推荐模型而牺牲删除、授权和审计路径。
