# 学习日志组提交

日期：2026-11-06。范围：降低决策采集的同步次数，采集默认关闭，提交默认single。

<重表述提示词为问题>如何让已经同时到达的推荐决策共用一次本地持久化同步，保持成功响应对应已同步记录，并限制排队、取消残留和故障代价？</重表述提示词为问题>

## 问题与选择

本轮保留三项：Q4-a采集成本、可信终端反馈、模型感知召回/部署。本轮只解决第一项。

S0：逐条同步的日志有可追溯输入，但每个采集请求都执行一次`sync_data`。
IFR：必要的确认语义不变，已有并发自然摊薄同步开销，不增加在线跨节点调用。
TC：更多合并减少同步次数，但主动凑批会增加低负载延迟。
PC：记录需要等待持久化确认，又希望不单独为每条等待一次同步。
采用条件分离：只合并已经排队的记录，无定时凑批；没有并发时正常单条提交。

比较三条路径：采样、异步先确认、同步组提交。采样会改变数据覆盖，异步先确认会改变成功语义，
本轮不采用这两项；组提交保持返回ID的确认边界，代价是每个启用日志新增一个本地写入线程、
队列和最大四条的内存暂存。没有将其扩成通用事件总线。

## 配置与边界

```powershell
$env:VS_LEARNING_JOURNAL = '<当前副本日志路径>'
$env:VS_LEARNING_SOURCE_ID = '<唯一副本标识>'
$env:VS_LEARNING_COMMIT_MODE = 'grouped'
```

`single`为默认，每条独立同步；`grouped`最多合并已经排队的四条。
孤立设置提交模式、无效模式或配置编码无效均拒绝启动。
已有`with_learning_journal`保持single；显式构造可用`with_learning_journal_mode`。
两种方式共用同一个写入执行结构，以隔离组提交本身的成本。

- 四个许可覆盖“已排队+正在写入”，取消HTTP等待后也由任务持有，直到实际结束。
- 写者顺序构造序号和前项指纹，预先检查整批时间、画像有效期、单条与日志总量。
- 校验通过后追加所有字节，执行一次`sync_data`，再更新内存进度并逐条确认。
- 配额或IO错误不会返回任何本批成功ID，日志停止接纳；尾部不完整仍须人工处理。
- 普通数据校验错误拒绝当前批次，不把整批校验当成文件系统事务。
- 故障期间完整但未确认的尾部可能被重启读到；没有网关曝光与明确反馈就不会进入训练。
- 写者异常退出释放排队通道和许可；退出信号在队列锁下发布，避免错过唤醒导致关闭卡住。
- 正常排空等待所有许可回收。系统调用永久阻塞、掉电和文件系统持久性仍不在本轮证明范围。

默认关闭采集时不创建写入线程，不改变推荐输入或返回候选。
日志仍为`learning-decision-v1`，离线来源关联无需迁移。
来源ID和分片记录不同会改变具体决策ID，不应跨实例用客户端请求ID猜测它。

`/v1/metrics`与就绪响应增加`learning_journal`：
mode、sync_calls、committed_batches、committed_records、failures、max_batch_records、usable。
计数随进程重启清零；failures计失败批次；快照逐字段读取，不具事务一致性。
少同步不代表少逻辑日志字节、少出口或更好的推荐。

## 验证

机制合约覆盖：四个已排队请求在grouped下共用一次同步，single下四次；
成功ID与独立解析的日志链逐项对应；取消不释放实际任务预算；
整批配额或只读文件IO失败时不确认、不推进内存序号。
现有双副本导出夹具同时使用single和grouped，校验旧离线导出契约保持。

`learning_commit_cost`使用256个公开候选、同一授权投影，在并发1和4下，
对off/single/grouped各跑两轮，每单元64条请求，保留全部耗时样本、同步计数和日志指纹。
请求结果跨采集方式必须完全一致，每个成功决策ID必须在停写后的记录中找到。
该对照顺序只按轮次旋转，没有宣称随机盲测。

```powershell
cargo build --release --locked --offline -p vs-service --example learning_commit_cost
./labs/recommendation/run-commit-cost.ps1
```
