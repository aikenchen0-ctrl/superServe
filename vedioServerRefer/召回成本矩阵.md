# 召回成本矩阵

日期：2026-11-06。结论：分组收益取决于候选数、组数和过滤；保真通过不等于更省资源。
默认后端未改变，没有依据本次合成结果设置自动选择阈值。
后续已复制改造 Qdrant 局部 Top-K 限制组头空间，见 [上游TopK复用评估](上游TopK复用评估.md)；
下文为全组头历史对照，退化与内存数据保留。

<重表述提示词为问题>在完全相同的排序输出下，分组复用何时抵消索引构建、组遍历、堆头与最终排序的代价？</重表述提示词为问题>

## 输入和门禁

新增 Rust 核心示例 `recall_cost_matrix`，不依赖 HTTP 服务、Qdrant 或额外基准运行时。
只有开发依赖复用锁文件中已有的 `serde_json`、`sha2`；生产运行依赖没有增加。

完整矩阵要求 release 构建，共 64 个单元：

- 候选数：256、1024、4096、10000。
- 目标组占比：1%、10%、50%、100%；实际组数向上取整并校验。
- 每个目录分别测全可见和场景/拒绝标签/隐藏过滤。
- K 为 10、50；每单元先预热 8 对，再测 64 对。

总计 4096 对样本，每对都比较元数据、结果顺序、亲和度位值、场景和媒体路径，允许
`considered` 不同。计时覆盖完整的进程内推荐函数；分组路径包含上下文、选择和最终排序，
不能用各阶段中位数相加代替总耗时。样本按 ABBA 顺序交替，保存纳秒原始数据。
门禁对故意改变的顺序、分数和画像版本有负对照测试。

负载是固定 8 标签、大量同分的合成模板，包含三种推荐场景。组标记改变组数，但不贡献用户
亲和度；它是重复计算与归并成本探针，不是真实内容分布，不提供用户满意度结论。
未模拟并发、HTTP、画像 RPC、视频播放或网络字节，也未固定 CPU 频率或隔离主机负载。

## 两轮结果

两轮目录指纹和全部排序结果一致；每轮 38 个单元的分组 P50 更快，26 个更慢。
第二轮仅修正静态检查写法并加入门禁负对照，不是算法优化；不把两轮速度差归因为代码收益。

以下为第二轮一万候选、K=50、无过滤结果。比值为分组总 P50 / 全量总 P50：

| 组数 | 全量 P50，毫秒 | 分组 P50，毫秒 | 比值 | 索引对象与向量容量，KiB | 查询堆头容量，KiB |
| --- | ---: | ---: | ---: | ---: | ---: |
| 100 | 1.2353 | 0.0591 | 0.048 | 102.4 | 5 |
| 1000 | 1.2573 | 0.1955 | 0.155 | 148.5 | 40 |
| 5000 | 1.2617 | 0.7452 | 0.591 | 273.5 | 320 |
| 10000 | 1.2200 | 1.2779 | 1.047 | 546.9 | 640 |

一万组加过滤的分组 P50 为 1.6847 毫秒，全量为 1.0522 毫秒，比值 1.601；
首次运行同一单元比值为 1.529。小目录也可能退化，不能只用组占比决定后端。
这里“更快/更慢”仅描述本次样本的中位数，不是显著性检验。

同样输出 128 个候选，不代表只处理 128 项：一万独立组的无过滤请求会检查、评分一万组，
保留的全部组头容量达到 655360 字节。最终排序还会重新计算所选候选的亲和度。

构建成本也保留：第二轮一万候选的索引构建约 9.0～17.5 毫秒。报告以构建耗时除以配对中位
节省估计摊销请求数；一万组没有正节省时返回 null。它不包含内存、更新流量和调度成本，
不能据此确定真实更新频率或生产阈值。

## 内存口径

`allocation_layout()` 只统计索引对象大小、组向量容量和成员向量容量。共享目录通过 `Arc`
复用，不重复计入；分配器元数据、Arc 控制块、构建临时键和最终排序容器不在此口径。
`head_buffer_bytes` 和 `output_buffer_bytes` 是选择器实际向量容量，不是整次请求峰值。

Windows 驱动另启动独立进程，按固定协议暂停后采样：

```text
ready -> catalog -> indexed -> queried -> index_dropped -> exit
```

每轮在 100、1000、10000 组上各启动两次新进程，记录工作集、私有字节、累计峰值工作集
和 CPU 时间，并核对探针 PID。仅读取和结束本脚本拥有的进程。

例如第二轮一万组的一次探针：索引对象与向量容量为 560032 字节；构建后工作集为
11165696 字节，进程累计峰值为 15691776 字节。它们包含不同内容，不能相减当作精确索引开销。
释放索引后部分内存仍由分配器保留，不能据此判为泄漏；累计峰值包含目录加载和构建，
不是单次查询峰值。该核心探针也不代表含网络栈和画像状态的服务进程总内存。

## 复现

```powershell
cargo build --release --locked --manifest-path vedioServer/Cargo.toml `
  -p vs-core --example recall_cost_matrix
& ./vedioServer/labs/recall-cost/run-matrix.ps1 `
  -Samples 64 -Warmup 8 -MemoryRepeats 2
```

仅做调试冒烟时，使用调试二进制和 `-Quick -Samples 8 -Warmup 2 -MemoryRepeats 1`；
调试结果不用于性能结论。矩阵保真失败退出 2，参数或运行错误退出 1，完成且保真通过退出 0。
脚本对版本、样本数、release 类型和退出码逐一校验，并保存二进制、源码和锁文件指纹。

## HMM 决策

`S0`：排序保真已闭合，但此前只在高重复小目录上测过调试耗时。
`IFR`：复用有用计算，不为无用组头和过量预留容量付费。
当前 `Sg`：建立能暴露退化的成本矩阵，保留相同输出下的快慢边界与内存证据。

技术矛盾：更多候选特征区分有助于表达不同内容，却会增加组数并消除复用。
参数矛盾：需要检查足够多的组以保证前缀完整，同时又希望只保留少数组头以节省工作空间。
本轮只测量，不根据单一模板把边界硬编码进生产。

下一轮可独立验证：

1. 保留最多 128 个可能贡献前缀的组头；核对完整性并比较额外筛选 CPU 与堆内存。
2. 压缩只读成员索引的预留容量；比较启动构建代价和常驻内存。
3. 使用独立分布与真实匿名行为复验，再推进多副本目录发布、重建和失败回退。

Qdrant 的原固定预算同分路径尚未通过相同保真门槛，本轮不把它与等价路径做生产成本替代比较。
画像授权撤销、学习排序、媒体存储修复、视频编码与播放器 QoE 仍独立开放。

验证：76 项全目标测试通过，包含真实 Qdrant 合约；最终成本工具三项测试复查、Clippy 零警告
和 fmt 通过。调试完整矩阵、非平衡样本数、越界内存探针均按约定退出 1 且无部分报告。
