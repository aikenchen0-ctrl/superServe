# 画像知识库与治理

## 一、四层画像

用户画像分为四层，不能把它们混成一个无限增长的文本摘要：

| 层 | 内容 | 生命周期 |
| --- | --- | --- |
| 实时状态层 | 当前会话、设备、网络、即时行为 | 秒到分钟 |
| 短期偏好层 | 近期兴趣、当前任务、临时意图 | 小时到天 |
| 长期画像层 | 稳定习惯、长期偏好、场景权重 | 天到月 |
| 知识图谱投影层 | 经授权的事实、关系和主题摘要 | 按授权和有效期 |

推荐请求只读取当前场景需要的最小投影，不读取原始资料。

## 二、证据和冲突

每条长期画像事实至少记录：

- `fact_id`
- `subject_id`
- `predicate`
- `object`
- `source_id`
- `evidence_ref`
- `authorization_ref`
- `valid_from`
- `valid_until`
- `confidence`
- `version`

冲突处理分三类：

| 冲突 | 处理 |
| --- | --- |
| 来源更新 | 新证据替代旧值，旧值保留审计记录 |
| 上下文冲突 | 两个值并存，按场景和有效期选择 |
| 证据不足 | 不写入长期画像，只保留短期候选 |

向量距离不能证明事实正确，只能作为召回信号。事实覆盖、冲突、过期和引用完整
性必须单独评估。

## 三、更新链路

画像更新分为在线、近线和离线三段：

1. 在线：记录行为事件、短期状态和反馈，不直接改写长期事实。
2. 近线：聚合事件、提取候选事实、进行证据和冲突检查。
3. 离线：训练长期表示、重算画像摘要、评估删除失败路径。

长期画像写入必须经过选择性门禁。习惯型用户优先使用聚合画像，探索型用户才
增加生成式画像权重。任何画像更新都要保留旧版本和回滚入口。

## 四、知识图谱边界

个人知识图谱只保存经过授权的事实和关系，不保存推荐模型生成的推测为真事实。
图谱构建流程：

```text
原始资料
-> 清洗和去重
-> 事实候选
-> 来源和权限校验
-> 冲突消解
-> 图谱版本提交
-> 推荐投影生成
```

推荐系统访问图谱时使用主题或能力接口，不允许任意遍历完整私人图谱。

## 五、删除与撤销

删除必须沿依赖链传播：

1. 标记原始事实墓碑。
2. 找到依赖该事实的画像投影和向量。
3. 使相关缓存和索引版本失效。
4. 记录删除任务和完成证据。
5. 对无法原地删除的训练样本进入下一轮重训基线。

授权撤销后，推荐服务不能继续使用旧投影，即使模型服务或缓存尚未完成重建。

## 六、隐私和越权防护

- 原始资料默认不离开所属设备。
- 推荐请求不包含手机号、精确位置、聊天原文和文件正文。
- 画像服务按租户、设备、场景和数据域授权。
- 日志默认只记录 id、哈希、计数和错误，不记录画像正文。
- 模型提示、向量和特征不得包含未授权的跨用户资料。
- 所有敏感操作都有审计记录和过期策略。

## 七、评估

画像系统需要同时评估：

| 维度 | 指标 |
| --- | --- |
| 覆盖 | 有证据的长期偏好比例 |
| 正确性 | 事实冲突率和过期使用率 |
| 删除 | 撤销传播延迟和残余投影数量 |
| 延迟 | 画像读取 P50、P95 和 P99 |
| 存储 | 每用户有效画像字节和版本增长 |
| 推荐价值 | 真实个性化增益和全局参数对照 |
| 长期影响 | 多样性、内容深度、留存和用户负担 |

个性化门控必须对照全局参数、打乱绑定和固定容量基线，不能把额外算力带来的
效果误报为画像收益。
