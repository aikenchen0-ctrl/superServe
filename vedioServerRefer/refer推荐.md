## 一、结论

当前没有单一算法在所有短视频场景中同时赢得效果、算力、延迟、带宽和可解释性。

截至当前公开资料，最强形态是分层组合：

```text
多模态内容理解
-> 多路召回，包括向量、协同、生成式语义 ID、图谱和新鲜内容
-> 轻量预排序与长行为序列压缩
-> 大排序或列表级生成
-> 多目标融合、多样性与安全约束
-> 在线反馈写入、离线画像更新、下一次请求检索
```

对低性能开销、低带宽、低体感延迟的目标，建议优先级如下：

1. 多模态内容向量和语义 ID，解决冷启动、长尾和跨语言理解。
2. HSTU、MTGR 或 Mamba4Rec 路线，压缩长行为序列并提高 GPU 利用率。
3. RankMixer 路线，提高排序阶段 MFU，在不增加延迟的前提下扩展模型。
4. HEGM 或 PTPM，分别预测跳过、短看、继续看、长看，而不是只预测平均观看时长。
5. LIGE-GR 或 OneRec-V2 路线，作为下一阶段的列表级生成与偏好对齐。
6. 用户画像采用短期状态、长期压缩记忆、个人知识图谱和按需检索四层结构。
7. 列表重排与混排应优先考虑 OneTrans-GSR 式统一生成，而不是继续堆叠两套手工规则。
8. 生成式召回的线上延迟要同时优化约束解码，ZeroGR 式先过滤后打分更接近有效工作。

不建议第一阶段直接做端到端生成式替换。公开系统大多数仍保留召回兜底和成熟特征，原因是冷启动、延迟、成本和回滚都更可控。

### 2.2 当前判断

- 生成式召回已经不是纯研究概念，Snapchat、快手等系统已有生产结果。
- 端到端生成式系统仍需要成熟召回、内容和特征体系提供兜底。
- 列表级生成比逐条预测更符合短视频连续消费场景。
- 真正的收益常来自列表一致性、时长偏差修正和多目标对齐，不只来自更大的模型。
- 统一链路的主要价值是减少计算碎片、通信和存储，但也提高训练、回滚和故障定位门槛。
- 列表级生成已经不只覆盖排序，还能统一重排、混排和商业约束。
- 生成式召回的主要线上成本不只是模型前向，还包括无效语义 ID 的过滤和索引重构。
- 短视频长序列已有十亿级生产证据，关键不是把全部历史塞入注意力，而是分层层级压缩、候选感知检索和请求级复用。
- 生成式推荐的服务成本可以明显低于传统成长方式，前提是预填充、近线刷新、在线预测和数据移动被解耦。
- 多场景统一并非简单共享模型，而是共享语义物品空间、行为接口和部分骨干，同时保留场景输出。
- 语义 ID 的质量应作为独立生命周期管理，包含构建、碰撞、负载均衡、版本升级和在线回滚。
- 生成式推荐会重复忘记长尾，原因是束搜索的子树概率与最终似然共同偏向热门项；恢复共现记忆比单纯增大 beam 更有效。
- 解码阶段的读历史和写 SID 可以解耦，宽 beam 成本不需要每次都经过完整大骨干。
- 召回索引需要与排序目标共同学习，否则结构分群与业务相关性会长期错位。
- 短视频观看行为是用户偏好的噪声测量，时长、位置和会话环境必须与真实偏好解耦。
- 只看观看时长会把测量伪信号放大，长期满意度需要显式不确定性建模。
- 推理成本的最大结构杠杆之一是让请求级特征只计算一次，而不是对每个候选重复计算。
- 模型扩容可以使用参数继承，不必须每次从零训练。
- 生成式语义嵌入不一定优于判别式视觉嵌入，极端冷启动和检索空间稳定性要单独验证。
- 大规模推荐训练的主要瓶颈可能同时在稀疏特征、嵌入通信和稠密计算，不应只优化其中一段。
- 训练与服务使用不同物品表示会产生结构性误差，模型内缓存可以把两者统一为一个表示源。
- 列表生成可以改变生成原子，而不必逐物品自回归；成对生成可减少 token 数和累计误差。
- 服务时语言模型不是推荐的默认必要条件，必须通过同信息、同候选的恢复式审计证明其增量。
- 生成式推荐不应只比较单次解码速度，还要比较训练成本和质量；多 token 并行预测只在吞吐上占优时并不值得替换。
- 物品历史表示本身应个性化，否则同一物品对所有用户使用相同初始语义。
- 生产监控和偏差校正可以独立于主模型上线，且应覆盖语义失败而不只监控行为指标。
- 生成式召回的束评分应包含下游效用，否则高收益候选会在重排前被错误剪掉。
- 语义缓存不能只比较请求相似度，多轮会话必须根据历史共同判断复用是否安全。
- 量化前后模型偏好可能显著变化，安全审计必须使用实际部署精度。

## 三、推荐算法候选

### 3.1 长行为序列

#### HSTU

论文：`Actions Speak Louder than Words: Trillion-Parameter Sequential Transducers for Generative Recommendations`

公开信息：

- 面向高基数、非平稳的流式推荐数据。
- 把多个推荐任务统一为序列转导。
- 公开摘要称在部分数据集 NDCG 提升最高 65.8%。
- 8192 长度序列比 FlashAttention2 Transformer 快 5.3 到 15.2 倍。
- 报告了万亿参数级路线和线上 A/B 提升。

【论文】【工业部署】

适用：

- 有多月到多年的行为序列。
- 需要在不线性增加延迟的情况下扩大模型。
- 希望将召回、排序特征和用户历史统一成序列事件。

风险和代价：

- 数据清洗、事件时间对齐和负采样要求高。
- 训练基础设施复杂，不能只替换一个模型文件。
- 不能直接丢掉经过验证的交叉特征和业务规则。

#### MTGR

论文：`MTGR: Industrial-Scale Generative Recommendation Framework in Meituan`

公开信息：

- 基于 HSTU。
- 保留传统 DLRM 的交叉特征。
- 使用用户级压缩提高训练和推理效率。
- 使用 Group-Layer Normalization 和动态掩码。
- 单样本前向 FLOPs 约为 DLRM 的 65 倍，但成本未同比例恶化。

【论文】【工业部署】

适用：

- 现有系统已有大量高价值人工特征和交叉特征。
- 需要逐步升级，不能一次性拆除旧链路。

#### Douyin 10K Long Sequence

论文：`Make It Long, Keep It Fast: End-to-End 10K Long User Behavior Sequence Modeling for Billion-Scale Douyin Recommendation`

公开信息：

- 使用 Stacked Target-to-History Cross Attention，将历史注意力复杂度从序列长度的二次降为线性。
- 使用 Request Level Batching，让同一用户和请求的多个目标共享用户侧编码，降低序列存储、通信和计算。
- 使用短窗训练、长窗推理的长度外推策略，在训练成本不明显增加的情况下扩展到 1 万历史。
- 在抖音全流量部署，历史长度和模型容量提升带来可预测的单调收益，并满足生产延迟。

【论文】【工业部署】

判断：

- 这是短视频长历史最直接的生产参考。
- 对 Rust 在线面，关键是请求级批处理接口、用户编码缓存和超长历史的存储布局。
- 不应只复刻网络结构，还要同步实现用户级复用和长度外推训练。

#### ECHO

论文：`ECHO: Efficient Cascade with Homogeneous Operators for Distillation-Guided 100K-Sequence Modeling`

公开信息：

- 终身行为序列最长达到 10 万条，直接全历史计算不可承受。
- 蒸馏选择器保留部分原始事件，候选感知检索器为每个目标取更小的相关集合。
- 10 万序列下，在线序列分支 FLOPs 相比代表性端到端模型降低约 160 倍。
- 三个部署优化降低内存、存储和数据移动。
- 快手和快手极速版线上 App 使用时长提升 0.240% 和 0.373%。

【论文】【工业部署】

适用：

- 用户终身行为很长，但单次候选只需极少数相关事件。
- 能接受离线教师模型和在线选择器的级联结构。

#### MuSeR

论文：`MuSeR: Scalable Long-sequence Recommendation with Multi-interest Modeling`

公开信息：

- 近期行为保持全分辨率，较旧行为逐层池化，使 1 万到 10 万级历史适配固定服务预算。
- 使用正交正则的多查询兴趣抽取，避免多兴趣坍缩。
- 用 LLM 文本摘要增强稀疏物品 ID 的多模态语义。
- 使用异步用户表示刷新、自适应缓存和分层 beam search。
- 百度 App 多个场景线上日活提升 0.26%，总会话时长提升 0.89%，同时降低服务延迟和成本。

【论文】【工业部署】

判断：

- 对 Rust 系统很有参考价值，因为收益来自缓存、压缩和检索工程，不只是模型。
- 多兴趣与长历史应共用一套用户表示刷新机制。

#### Semantic-Native Long Sequence

论文：`Beyond Item IDs: Scaling Short-Form-Video Recommendation via Semantic-Native Long Sequence Modeling`

公开信息：

- 面向十亿用户规模的短视频生产系统。
- 使用深度截断的粗粒度语义 ID 替代传统正交 Video ID，缩小嵌入表并让冷启动内容共享语义前缀。
- 使用全局感知压缩 Transformer，通过非参数时间折叠和统一全局查询压缩长行为序列。
- 峰值内存降低一个数量级，计算开销显著下降，从而支持更长序列并取得线上满意消费增益。

【论文】【工业部署】

判断：

- 短视频长序列不宜继续依赖巨大正交 ID 表。
- 语义前缀既要服务内容泛化，也要控制截断造成的细粒度损失。
- 该路线可作为 HSTU 类序列模型的低成本产业替代或补充。

#### PRISM

论文：`PRISM: Personalized Item Representations in User History`

公开信息：

- 传统序列推荐给同一物品在所有用户历史中使用相同初始表示，忽略用户与物品的关系差异。
- PRISM 重用上游排序计算，为每个用户与物品对生成个性化历史表示。
- 使用自编码器联合压缩用户塔、用户物品塔和同请求候选混合中的层状态。
- 在十亿级推荐表面，NE 平均改善 0.15%，高于 VISTA 的 0.07%。
- 在 26 到 240 条历史上，NE 增益呈指数约 0.468 的幂律增长。

【论文】【工业部署】

判断：

- 用户画像不应只压缩用户，还需要表达物品在用户自身语境中的含义。
- 个性化历史表示可作为新扩容维度，不必只增加序列长度。
- Rust 服务可把上游层状态压缩与请求级缓存分开。

#### TransX

论文：`TransX Technical Report: Scaling Sequence Transduction for Recommendation`

公开信息：

- 将序列编码、行为记忆和候选条件融合拆成可独立扩展的组件。
- 训练阶段摊销因果轨迹计算，把记忆状态展开给候选。
- 服务阶段拆分为批量预填充、近线刷新和在线预测。
- 核心模型线上点击率提升 6.02%，转化提升 4.45%。
- 训练基础设施将有监督目标吞吐提高 84%。
- 服务解耦使总成本降低近 80%；同成本下请求 FLOPs 约为 HSTU 风格生产基线的 5 倍。
- 相同单请求 FLOPs 下，每台 H200 的请求吞吐约高 4 倍。

【论文】【工业部署】

判断：

- 这条路线最适合三低目标，因为它把模型容量增长与在线成本增长解耦。
- Rust 在线面应显式实现预填充、记忆刷新、候选融合三段式接口，而不是只包一层模型推理。
- 行为记忆是否可复用、何时刷新，是比推理框架更重要的设计变量。

#### 统一多场景生成

论文：

- `OneMall: One Architecture, More Scenarios`
- `TGR: Advancing Industrial Recommendation from Generative-Paradigm Ranking toward Unified Generation and Reasoning`

公开信息：

- OneMall 统一商品卡、短视频和直播场景。
- OneMall 使用电商语义 tokenizer、Query-Former 长序列压缩、多行为交叉注意力和稀疏 MoE。
- OneMall 报告快手电商短视频订单提升 15.32%，服务超过 4 亿日活。
- TGR 将排序、生成召回、列表生成和离线推理统一到一套框架。
- TGR 的 BARGE 报告点击率提升 0.60%，阅读时长提升 1.70%。
- TGR 的 HiGR 报告观看时长最高提升 1.22%，视频播放提升 1.73%。

【论文】【工业部署】

判断：

- 多场景统一适合共享用户、语义和行为，不适合强制所有场景共享目标函数。
- 在线需要保留场景级输出头、约束和回滚开关。
- 统一模型的真正收益来自训练和服务复用，而不是单次请求少调几个模型。

#### Mamba4Rec

论文：`Mamba4Rec: Towards Efficient Sequential Recommendation with Selective State Space Models`

公开信息：

- 面向长行为序列的推理效率问题。
- 使用选择性状态空间模型，目标是在效果和效率之间同时胜出 Transformer 与 RNN 基线。

【论文】

适用：

- 序列非常长。
- 每次请求重算注意力太贵。
- 希望降低内存增长和长序列延迟。

风险：

- 公开生产部署证据少于 HSTU。
- 与现有特征系统融合复杂度未知。
- 不能只凭复杂度从二次降到线性就认定整体更快，端到端瓶颈常在特征、网络和存储。

### 3.2 排序与模型扩容

#### RankMixer

论文：`RankMixer: Scaling Up Ranking Models in Industrial Recommenders`

公开信息：

- 用多头 token mixing 替代二次自注意力，适合 GPU 并行。
- 使用 Per-token FFN 保持特征子空间和交叉空间建模。
- 支持稀疏 MoE 扩展。
- MFU 从 4.5% 提升到 45%。
- 参数扩大约 100 倍，推理延迟基本不变。
- 线上用户活跃天数提升 0.3%，总使用时长提升 1.08%。

【论文】【工业部署】

适用：

- 排序模型受 CPU 时代结构和低 MFU 限制。
- GPU 已部署，但算力利用率低。
- 希望扩展参数而不增加请求延迟。

#### LWR

论文：`Read More, Reason Deeper: Latent Workspaces for Long-Sequence Recommendation`

公开信息：

- 将可寻址证据和历史传播状态分离。
- 历史长度与推理深度可以分别扩张。
- 在 1 万长度历史上，NE 相对 HSTU 改善 0.19%，前向 GFLOPs 降低 69.6%。
- 在两个十亿级排序场景中优于现有基线。

【论文】【工业部署】

适用：

- 需要保留超长历史，但不想让每条事件都经过完整模型深度。
- 在候选局部工作区中反复读取持久证据。

#### PFA

论文：`PFA: Attention Can Be Progressively Focused in Long-Sequence Generative Recommendation`

公开信息：

- 观察到生成式推荐解码中的注意力逐步聚焦，且重要度排名跨解码步骤较稳定。
- 首步保留全注意力，后续复用共享重要度排序，并逐步减少 token 预算。
- 7 天电商广告线上 A/B 报告业务提升并保持低推理延迟。

【论文】【工业部署】

适用：

- 生成式召回的 beam search 在长历史上延迟过高。
- 静态压缩会丢语义，动态 top-k 的重复选择开销又太大。

#### LoopRec 与自适应递归

论文：

- `Think Harder Where It Matters: Item-Level Adaptive Recursion for Sequential Recommendation`
- `Candidate-dependent residual routing trades top-of-list accuracy for recall in sequential recommendation`

公开信息：

- 同一用户历史中的不同物品计算需求差异很大，大多数物品浅层处理即可收敛，少数关键物品需要完整深度。
- LoopRec 递归复用权重共享块，并在每次递归边界决定单个物品继续或退出。
- 学习到的计算分配让低频物品和近期交互自然获得更深处理。
- 候选相关残差路由可能提高前十召回约 1.81%，但同时降低首个相关物品的 MRR 约 1.09%，新增命中多落在第六到第十位。

【论文】

判断：

- 固定深度会同时浪费已收敛物品算力，并低估关键长尾物品。
- 自适应递归适合探索，但必须同时看列表头部准确率和召回，不能只看平均 NDCG。
- Rust 服务可把递归深度作为请求内预算调度信号。

#### EMER

论文：`An End-to-End Multi-objective Ensemble Ranking Framework for Video Recommendation`

公开信息：

- 用端到端多目标融合替代人工设置权重公式。
- 使用 Transformer 建模候选之间的比较关系。
- 快手线上 App Stay Time 提升 1.39%，7 日用户留存提升 0.196%。

【论文】【工业部署】

适用：

- 短期点击、观看时长、完播、互动和长期留存存在冲突。
- 人工调权无法持续覆盖复杂用户群。

风险：

- 单目标离线指标不能代表用户满意度。
- 需要防止时长最大化伤害内容多样性和长期留存。

#### UAME

论文：`Uncertainty as Remedy: Mitigating Satisfaction Label Bias in Short Video Multi-Objective Ensemble Ranking`

公开信息：

- 点击、观看时长等行为只是用户真实满意度的部分、碎片化且互相冲突的代理。
- 确定性多目标融合忽略这种不确定性，会放大满意度标签偏差。
- UAME 预测高斯评分变量，用均值表示满意度，用方差表示预测不确定性。
- 使用概率成对排序损失和样本权重缓解标签偏差。
- 在工业短视频系统改进了 EMER 和 EASQ，并与问卷满意度更一致，已进入生产。

【论文】【工业部署】

判断：

- 多目标融合不应把每个行为信号当成同等可信的满意度标签。
- 不确定性应参与训练权重和排序决策，而不是只做事后排位调整。
- 对时长较短或上下文异常的曝光，应降低满意度监督强度。

### 3.3 观看时长预测

#### HEGM

论文：`Hierarchical Exponential-Gaussian Mixtures for Watch-Time Distribution Prediction`

公开信息：

- 观看时长分布具有零膨胀、长尾和多峰特征。
- 原 EGMN 存在方差塌缩、组件冗余和失效组件。
- HEGM 使用跳过和观看的层级分解、结构化初始化和方差正则。
- 论文报告 1.5 个月生产 A/B 有统计显著增益。

【论文】【工业部署】

适用：

- 推荐系统错误地把所有用户建模为只看均值时长。
- 需要区分立刻跳过、短看、继续看和长时间停留。

#### FLVM

论文：`Mend the Measurement Gap: Latent User Preference Modeling for Short-Form Video Recommendation`

公开信息：

- 同一种行为可能来自真实享受、被动消费或注意力缺失。
- 短视频观看时长受视频时长、用户倾向和会话上下文等测量混杂影响，比例指标会系统性偏向短视频。
- FLVM 把异质行为当作低维潜在价值状态的噪声测量。
- 受限基线路径吸收可预测的测量混杂，路由潜路径估计偏好相关价值优势。
- YouTube Shorts 线上 A/B 中主观看享受指标提升 2.67%。

【论文】【工业部署】

判断：

- 推荐目标应从原始参与代理转向潜在用户价值。
- 时长预测、满意度预测和偏好测量应分别建模，不能互相替代。
- 应持续审计短视频时长偏好导致的系统性内容偏差。

#### EASQ

论文：`Towards End-to-End Alignment of User Satisfaction via Questionnaire in Video Recommendation`

公开信息：

- 点击和时长只是满意度的间接代理，问卷反馈更直接但极端稀疏。
- EASQ 为问卷信号建立独立参数通路，使用多任务架构和轻量 LoRA 隔离参数。
- 使用面向在线学习的 DPO 目标实时对齐主模型输出与稀疏满意度反馈。
- 已在生产短视频推荐部署，多个场景取得稳定满意度提升。

【论文】【工业部署】

判断：

- 满意度信号必须参数隔离，否则会被海量行为信号淹没。
- 问卷不是训练一次的离线标签，应支持在线持续对齐。
- 对齐目标需要限幅和回滚，防止少数反馈主导全局排序。

#### MOSS 生产语义监控

论文：`MOSS: A Production Framework for Monitoring and Diagnosing Semantic Failures`

公开信息：

- 行为指标滞后数天，人工审核无法扩展，离线评测框架不适合持续运行监控。
- MOSS 在循环监控中嵌入 LLM 相关性评分，并加入定向采样、策略感知提示、结构化告警和诊断追问。
- 在大型零售推荐、搜索和优惠场景持续运行六个月以上，发现两个已确认服务缺陷。
- 对回填混合缺陷，离线量化修复可使告警率相对降低 76.4%。

【论文】【工业部署】

判断：

- 生产推荐需要独立于训练指标的语义健康监控。
- 告警应带根因分类和可回放证据，而不只是一条分数下降。
- LLM 审核只负责发现和诊断，不应直接修改排序结果。

#### Instagram 去偏算子

论文：`Baseline and Incremental: User, Item, and Request Debiasing in Instagram Feed Ranking`

公开信息：

- 预测信号同时包含基线值和候选相对基线带来的增量价值。
- 不应简单移除基线，而应保留原始预测，并加入单独加权的增量项。
- 用户习惯、物品热度和请求上下文三类去偏可以统一为一个参数化算子。
- Instagram 四臂消融中，两项同时保留在 13 个受评指标对中的 11 个点估计最优。
- 该算子已在 Instagram Feed 生产使用近一年，并扩展到 Meta 多应用、多排序阶段。

【论文】【工业部署】

判断：

- 去偏不应只做减法，需区分“本来会发生”和“候选额外带来”的价值。
- 用户、物品和请求偏差应由统一算子管理，同时保留独立开关。
- 离线诊断适合筛选信号，不适合直接给信号排序。

#### PTPM

论文：`Personalized Tree-Based Progressive Regression Model for Watch-Time Prediction in Short Video Recommendation`

公开信息：

- 将观看时长离散成有序区间。
- 使用个性化、数据驱动的二叉树，而不是全局固定树。
- 报告已服务每日超过 4 亿用户。

【论文】【工业部署】

适用：

- 用户对时长的感知差异很大。
- 单纯回归平均值丢失有序区间信息。

#### FlowTime

论文：`FlowTime: Towards Continuous Generative Watch Time Prediction via Flow-based Personalized Priors`

公开信息：

- 直接回归因单峰高斯假设容易均值坍缩。
- 离散生成回归有量化误差、推理延迟和词表设计问题。
- FlowTime 使用一步生成变分自编码器，避免迭代去噪延迟。
- 使用基于流的个性化先验对用户历史条件分布塑形。
- 配套开源 TimeRec 观看时长预测库和个性化指标。

【论文】

判断：

- 是 HEGM 之外的另一条强路线，目标同样是多峰时长分布。
- 一步生成比多步扩散更符合低延迟。
- 需复测其线上效果和模型稳定性。

### 3.4 重排、混排与列表生成

#### OneTrans-GSR

论文：`OneTrans-GSR: A Generative Slate Ranking Paradigm Unifying Reranking and Mix-Ranking with One Autoregressive Transformer`

公开信息：

- 将候选重排和异构内容混排统一为一个列表生成问题。
- 使用单个 decoder-only 策略直接生成曝光列表。
- 训练阶段使用奖励模型评价完整列表，在线解码阶段显式执行业务约束。
- 线上 GMV/u 提升 2.63%，广告主价值提升 2.06%，复购率提升 2.03%。
- 重排和混排的端到端延迟降低 13%。

【论文】【工业部署】

判断：

- 对短视频与商品、直播、广告混合的信息流尤其有价值。
- 用统一学习策略替代两套手工规则，仍然保留业务约束硬门禁。
- 与 OneRec 的端到端替换不同，该路线可以直接接在成熟候选生成之后。

#### Refiner

论文：`Latent Residual Reasoning for Ranking in Generative Recommendation`

公开信息：

- 使用潜空间残差推理逐步修正排序分数。
- 使用压缩历史查询支持候选相关推理。
- 使用 LoRA 低成本适配预训练模型。
- 在公开数据集、工业离线数据和线上 A/B 中均优于直接预测。

【论文】【工业部署】

适用：

- 生成式排序首轮预测不够细，但直接引入文本思维链成本过高。
- 希望通过少量额外推理计算换取更细的候选比较。

#### SaFRO

论文：`SaFRO: Satisfaction-Aware Fusion via Dual-Relative Policy Optimization for Short-Video Search`

公开信息：

- 面向短视频搜索中的多任务融合。
- 构建查询级满意度奖励，超越单条内容交互。
- 使用组内和跨批相对偏好更新融合策略。
- 显式建模不同目标之间的依赖关系，实现上下文相关权重调整。
- 快手短视频搜索线上实验同时改善短期排序质量和长期留存。

【论文】【工业部署】

适用：

- 短视频搜索与推荐共用多目标融合服务。
- 点击、观看、互动和满意度目标存在上下文冲突。

#### ZeroGR

论文：`ZeroGR: Filtering-First Constrained Decoding for Generative Recommendation`

#### ReuseGR

【论文】【工业部署】

- 希望用离线大模型提升候选质量，同时把在线模型压到小模型。
- 能把请求级个性化与查询级规划拆开。

#### GR4AD-X

论文：`Towards Reliable, Scalable, and Value-Aligned Generative Recommendation for Large-Scale Advertising`

公开信息：

- 确定性 SID 分配对语义边界敏感。
- 传统加宽加深在严格服务约束下收益递减。

#### WeGR

论文：`WeGR: Towards Unified Generative Retrieval via Behavior-aware Tokenization and Preference Alignment`

公开信息：

- 传统语义 ID 分词难以同时保留协同信号和平衡码本利用率。
- CoCo-VAE 在量化前把查询到物品、物品到物品的协同信号注入连续表示。
- 通过首层码本刷新和抗坍缩正则缓解冷码本和深层碰撞。
- 动态视野策略优化逐步扩展奖励评估范围，缓解正样本未命中造成的奖励稀疏。
- 六周电商搜索线上 A/B 中订单提升 2.539%，点击率提升 1.508%，转化率提升 1.381%，CPU 和 GPU 使用分别降低 25.5% 和 26.1%。

【论文】【工业部署】

判断：

- 语义 ID 不能只来自内容，必须保留行为协同关系。
- 冷码本和深层碰撞需要独立监控，不能只看总体召回。
- 偏好对齐应从 SID 前缀逐步扩展到完整物品，而不是只奖励最终精确命中。

#### UAGR

论文：`Utility-Aware Generative Recommendation: Utility-Enriched Semantic Codes and Utility-Guided Decoding`

公开信息：

- 传统 SID 主要反映内容语义，无法区分语义相近但分享、长看、完播等效用不同的物品。
- UAGR 在不增加 SID 长度和词表规模的情况下，把物品效用编码进语义码。
- 束评分融合多种曝光后收益预测，避免高价值路径在生成后被错误剪掉。
- 在快手全量部署，线上视频观看时长提升 0.206%。

【论文】【工业部署】

判断：

- 生成式召回的目标不能只是匹配历史，还要在解码阶段保留高收益候选。
- 效用信息应支持增量更新，不能每次变化都重建全部索引。
- 束评分需要受控权重，避免商业效用压过长期满意度和多样性。

#### SSR 生成范式对照

论文：`Personalized LLM Recommendation with Semantic IDs: Autoregressive Beam Search vs. Multi-Token Prediction`

公开信息：

- 同一工业流媒体目录上比较单头自回归束搜索与多 token 并行预测。
- 单头束搜索在大多数产品关键指标上持续优于多 token 预测。
- 在 Qwen3-8B 规模上，单头束搜索训练成本约低 2.6 倍。
- 多 token 预测只在原始推理吞吐上占优。
- 相对非 SID 基线，物品冷启动排序提升 77%，内容问答准确率提升 22%，训练加速 2.8 倍。

【论文】【工业部署】

判断：

- 解码形式不能只用吞吐选择，必须同时比较训练成本、排序质量和问答能力。
- 语义 ID 词表扩张可能损害语言能力，需要单独回归测试和 RL 后训练修复。
- 短视频场景应保留单头自回归束搜索作为质量基线，再评估并行解码。

#### 语义 ID 生命周期

论文：

- `Beyond Static Collision Handling: Adaptive Semantic ID Learning`
- `MERGE: Next-Generation Item Indexing Paradigm`
- `SPAR: Stepwise Personalized Autoregressive Recommendation`
- `PIT: A Dynamic Personalized Item Tokenizer`

公开信息：

- AdaSID 区分应抑制的碰撞和语义兼容的共享，报告公开基准 Recall 和 NDCG 平均提升约 4.5%，快手短视频检索线上 GMV 提升 0.98%。
- MERGE 动态监控簇占用并自底向上合并，改善分配精度、簇均匀度和分离度。
- SPAR 在每个解码前缀读取压缩长期记忆，并平衡兄弟分支历史负载；优酷线上观看时长提升 3.95%。

【论文】【工业部署】

判断：

- 语义 ID 不是离线一次性产物，应支持版本、迁移、回滚和灰度。
- 需要监控碰撞率、码本利用率、最大分支占比、冷启动覆盖和版本切换损失。
- 在线解码时，前缀个性化比整段历史编码更能影响最终物品，PFA、SPAR 和 ZeroGR 应组合评估。

#### OneShot

论文：`OneShot: Index-in-Ranking with Neural Scoring for Large-Scale Retrieval`

公开信息：

- 检索负责从数十亿候选筛到数千，但排序准确率与索引效率传统上目标错位。
- OneShot 把索引学习放入模型内部，与排序目标端到端对齐。
- 使用神经打分突破点积检索的表达能力瓶颈。
- 已在 Instagram 短视频推荐部署，提升日会话、互动和时长。
- 运营排序量下召回提升 20%，等效召回水平下效率提升 10 倍。

【论文】【工业部署】

判断：

- 向量索引不应只按几何邻近构建，必须吸收下游排序监督。
- Rust 在线面可把索引管理、候选扩展和神经打分拆开优化。
- 需验证索引重建期间的一致性和回滚。

#### CAPE

论文：`Generative Recommenders Forget the Long Tail: Restoring Memorization in Retrieval and Ranking`

公开信息：

- 生成式推荐把检索与排序压缩为同一个似然分数，导致长尾物品被两次遗忘。
- 束搜索按子树概率保留前缀，会在早期剪掉长尾路径；扩大 beam 的补救有限。
- 即使长尾物品进入候选，生成模型似然仍通常排在热门物品之后。
- CAPE 是免训练插件，用共现记忆补充束外长尾候选，并把生成似然与共现证据校准融合。
- 在两个生成骨干、商品和音乐数据上显著改善长尾准确率，整体准确率不降或提升，延迟只增加少量。

【论文】

判断：

- 短视频长尾作者和长尾内容会受同类机制伤害。
- 纯生成召回应保留协同共现通道或外部候选池，不能只依赖生成似然。
- 评估必须单列长尾命中，而不能只看总体 AUC 或观看时长。

#### NAU

论文：`Neighborhood-Aware Unlearning for Generative Recommendation`

公开信息：

- 语义 ID 在相关物品间共享 token，删除某条交互会意外改变邻居物品概率。
- 这种副作用可能被总体指标掩盖，但在被遗忘物品的 SID 邻域内明显。
- 邻域感知遗忘显式控制被遗忘物品邻域的概率质量。
- 方法使垃圾信息曝光恢复到接近重训参考，同时保留超过 95% 的重训效用。

【论文】

判断：

- 用户删除记录、撤销授权或举报内容时，不能只做全局近似删除。
- 需要验证被删除物品、相邻语义桶和相关用户兴趣是否发生异常漂移。
- 删除能力必须作为生成式推荐的上线前置条件。

#### Deco

论文：`Separating Thinking from Spelling for Efficient Generative Recommendation`

公开信息：

- 标准自回归接口同时为历史 token 和每个 beam 解码重复支付骨干计算。
- Deco 让骨干一次性把历史压缩成下一个物品概念，再由轻量 KV 缓存解码器执行整个束搜索。
- 语义 ID、trie 约束和自回归分解保持不变。
- 在 50ms p95 延迟预算下，吞吐相对标准生成器和完整骨干教师提升 3.2 到 8.6 倍。
- 1.5B 骨干加 Deco 可达到 69M 教师吞吐，并取得更高准确率。

【论文】

判断：

- 宽 beam 不等于必须让大模型做每一次前缀评分。
- Rust 在线面适合承接概念缓存、前缀状态和轻量束搜索调度。
- 需重点验证概念压缩是否损失新兴兴趣和长尾语义。

#### OneLatent

论文：`OneLatent: Latent Reasoning for Efficient Foundation Recommendation Models`

公开信息：

- 显式思维链会产生长推理轨迹，延迟高且依赖人工模板。
- OneLatent 将多视角思维链压缩为可学习潜空间 token。
- 相比 Think 和 No-Think 基础模型，SID@64 分别提升 17.44% 和 9.33%。
- 在线推理吞吐提升超过 17 倍。
- 快手本地生活广告线上 A/B 估计收入提升 9.6%。

【论文】【工业部署】

判断：

- 推荐推理应停留在潜空间，不应在线生成大段自然语言解释。
- 显式解释可离线生成，在线只保留可审计的原因引用和潜空间状态。
- 该结果是广告场景，应用到短视频内容推荐仍需独立验证。

#### SID 拓扑保持

论文：`Don't Rewrite the SID Map: Topology Preservation for Generative Retrieval in Dynamic E-Commerce Search`

公开信息：

- 基于 67 天大规模电商搜索日志，更新 SID 映射会使已学习的检索路径失效。
- 束大小会掩盖漂移：束大小为 1 时命中率下降 41.78% 到 62.05%，束大小为 1000 时仅下降 8.33% 到 10.85%。
- 重映射比例越高，检索质量单调下降，最高可达 42.66%。
- 部署原则是新增物品、冻结旧物品 SID、可行时热启动，否则冻结；不要改写模型已学习的 SID。
- 天猫线上 A/B 中 UCTCVR 提升 0.29%，GMV 提升 1.16%。

【论文】【工业部署】

判断：

- 语义 ID 更新应以追加为主，避免周期性全量重写。
- 需要用低 beam 指标监控真实拓扑损失，不能被宽 beam 的冗余候选掩盖。
- 对个人知识库中的动态主题和内容，也应采用类似版本化、追加式标识。

### 3.7 多模态冷启动

论文：`Short-Form Video Recommendations with Multimodal Embeddings: Addressing Cold-Start and Bias Challenges`

公开信息：

- 沉浸式信息流有位置偏差和时长偏差。
- 即使已有足够交互数据，微调多模态视觉语言模型做视频检索仍可能优于常规监督学习。
- 电商平台在线实验验证了该路线。

【论文】【工业部署】

适用：

- 新视频、新作者、新用户缺交互。
- 视频文本弱，主要信息在画面、语音和节奏中。
- 需要语义相似性召回而不是只依赖协同过滤。

#### VCG

论文：`VCG: A Multimodal Retrieval Framework for E-Commerce Video Feeds under Extreme Cold-Start Conditions`

公开信息：

- 新短视频没有足够协同过滤历史，形成极端冷启动。
- 沉浸式信息流会放大位置和时长偏差。
- VCG 使用领域适配的 CLIP 视觉语言模型，把用户和视频映射到共享语义空间，实现零行为召回。
- 对比发现生成式模型擅长属性预测，但在检索任务中会出现嵌入空间坍塌。
- 线上 A/B 中深度视频完播率提升 50%。

【论文】【工业部署】

判断：

- 极端冷启动优先使用判别式多模态嵌入，不应默认依赖生成式语义嵌入。
- 生成式模型适合生成属性、原因和查询，判别式模型更适合稳定检索空间。
- 冷启动评估应单列零行为视频和零交互用户。

#### RGCD-Rep

论文：`Bridging Short Videos and Live Streams: Reasoning-Guided Multimodal LLMs for Cross-Domain Representation Learning`

公开信息：

- 短视频流量和行为丰富，直播转化强但行为稀疏、冷启动严重。
- RGCD-Rep 使用教师 MLLM 生成结构化跨域推理知识，蒸馏给轻量学生模型。
- 将物品表示拆成可迁移部分和领域残差，离线计算后接入召回。
- 在快手直播推荐部署，服务超过 4 亿日活，多个业务指标显著提升。

【论文】【工业部署】

判断：

- 教师推理可离线，学生表示在线低成本使用。
- 适用于短视频、直播、商品卡和广告之间的用户兴趣迁移。

### 3.8 带宽、缓存与长期价值

#### SILC

论文：`SILC: Lookahead Caching for Short-form Video Delivery Systems`

公开信息：

- 推送式短视频推荐能提前看到后续可能播放的视频，这是普通按需视频不具备的条件。
- 短视频热度高度偏斜，地域和时间上存在显著重叠。
- 使用真实用户研究、100 名 TikTok 用户捐赠轨迹和 1 万并发用户仿真评估。
- 相比 10 种启发式或学习型缓存淘汰策略，CDN 中间层成本降低 11.1% 到 111%。

【论文】【仿真】

判断：

- 推荐服务应把后续播放序列作为缓存预取输入，但预取深度必须由带宽和收益门控。
- 这对“低带宽”目标比单独优化编码器更有系统价值。
- Rust 分发面适合承接前瞻缓存、分片索引和预取决策。

#### 内容深度风险

论文：`Content Depth Matters in Short-Video Recommendation: Rethinking the Attention Economy`

公开信息：

- 构建 15 万条短视频的内容深度标注和 SCOPE-Bench。
- 评估 13 个代表推荐算法，发现普遍偏好浅内容。
- 能推荐认知深内容的算法仅略优于随机选择。

【论文】

判断：

- 只看即时停留会系统性放大浅刺激内容。
- 推荐目标应加入内容深度、长期满意度和心理负担，不应把观看时长当作唯一收益。
- 该指标不能直接作为强制权重，否则可能损害用户自主选择。

### 3.9 生成式推荐服务运行时

#### FLAME

论文：`FLAME: A Serving System Optimized for Large-Scale Generative Recommendation with Efficiency`

公开信息：

- 生成式推荐模型单请求 FLOPs 可达到传统 DLRM 的数个数量级以上。
- 使用 CPU-GPU 异构硬件，拆分特征预处理和模型计算。
- Proximal Data Accelerator 获得 1.9 倍吞吐和 1.7 倍延迟改善。
- Fused Kernel Engine 获得 4.6 到 6.1 倍加速和 4.7 到 6.3 倍吞吐增益。
- Dynamic Stream Orchestrator 在非均匀候选分布下获得 1.3 倍吞吐和 2.3 倍加速。

【论文】

判断：

- Rust 在线面适合承接特征预取、内存布局、请求编排和降级控制。
- 不能只优化 GPU 前向，CPU-GPU 数据搬运和上游候选不均匀同样决定尾延迟。

#### FP8 OneRec-V2

论文：`Quantized Inference for OneRec-V2`

公开信息：

- OneRec-V2 的权重和激活分布比传统推荐模型更接近大语言模型。
- 使用 FP8 训练后量化和优化推理基础设施。
- 端到端推理延迟降低 49%，吞吐提升 92%。
- 在线 A/B 未观察到核心指标退化。

【论文】【工业部署】

判断：

- 生成式推荐进入稳定期后，量化是降低算力和能耗的高收益路径。
- 前提是模型结构、数值分布、校准集和回滚门禁都已成熟。
- 先在影子流量验证数值稳定性，再逐步切量。

#### ROCS

论文：`ROCS: Request-Oriented Compute Sharing for Efficient Large-Scale Recommendation`

公开信息：

- 推荐请求中用户侧特征被大量候选共享，传统模型却重复计算请求与候选交互。
- ROCS 尽量推迟请求与候选交互，隔离候选相关表示，使大部分模型每请求只计算一次。
- 使用广义层掩码保证候选隔离，使用深度交叉注意力扩展到序列模型。
- 配套 GPU 内广播优化。
- 生产检索模型最高提升 3 倍 QPS；短视频排序模型 LogLoss 相对改善 0.5%，同时 QPS 提升 50%。
- 已跨广告、自然流量、召回和排序部署。

【论文】【工业部署】

判断：

- 该路线对 Rust 在线服务最关键：先优化计算图共享，再考虑更大模型。
- 接口需要区分请求级、用户级和候选级特征，避免候选级逻辑污染共享缓存。
- 请求级批处理、层掩码和 KV 复用应成为核心性能指标。

#### DADF

论文：`DADF: A Distribution-Aware Debiasing Framework for Watch-Time Regression`

公开信息：

- 观看时长预测可能在整体校准时仍高估短观看、低估长观看。
- DADF 对冻结的一阶段时长预测器做乘法纠偏，无需替换主模型。
- 使用分组变换稳定长尾纠偏目标，并按视频时长路由纠偏专家。
- 视频时长只用于索引异质残差分布，不直接视为因果原因。
- 在生产排序系统 MAE 降低 12.57%；全排序、粗排和降级服务三类线上实验均提升设备时长，最终切到 100% 流量。

【论文】【工业部署】

判断：

- 可先给现有时长模型加低成本校准层，暂不重训主模型。
- 纠偏专家必须按残差分布路由，不能把视频时长本身当成偏好原因。
- 全排序、粗排和降级链路需要分别校准，接口一致不代表分布一致。

#### Inherit4Rec

论文：`Inherit4Rec: Parameter Inheritance for Efficient Scaling of Recommendation Models`

公开信息：

- 反复从零训练新模型会消耗大量数据和算力。
- 支持稠密到稠密扩容，以及稠密到稀疏 MoE 转换。
- 稠密扩容使用混合生长和非对称训练，保持扩展时前向函数兼容和更新连续。
- 稀疏转换按共同激活划分专家并增加负载均衡。
- 在 KuaiRand-1K 和工业短视频数据集上优于现有继承基线。

【论文】【工业部署判断】

判断：

- 模型迭代应采用参数继承和增量扩容，而不是周期性重建。
- 扩容必须监控新旧前向一致性、专家负载和动态分布漂移。
- 对 Rust 推理接口，模型版本切换应保持特征和输出契约稳定。

#### G-W-L 训练稳定性

论文：`Understanding and Mitigating Training Instability in Large-Scale Recommender Systems: A Cascade Perspective`

公开信息：

- 十亿级短视频交互和快速分布漂移容易触发训练发散。
- 发散通常按梯度爆炸、权重爆炸、损失爆炸的级联顺序出现。
- 提出梯度控制、权重和激活稳定、损失塑形三类对应干预。
- 在大型工业短视频推荐系统上验证。

【论文】【工业部署】

判断：

- 持续训练稳定性是生产推荐的前置能力，不是训练工程附属项。
- 监控应分别覆盖梯度、权重、激活和损失，并设置自动降级。
- 连续训练应支持回滚到已验证检查点，而不只是保住进程。

#### SparseLift

论文：`SparseLift: Automatically Optimizing Opaque Sparse Paths in Industrial-Scale Recommendation Model Training`

公开信息：

- 大规模推荐训练的稀疏算子和集合通信常被视为不可分析的不透明节点。
- SparseLift 把不透明节点重建为可分析子图，恢复稀疏计算和通信的资源语义。
- 使用增量成本模型和约束感知规划器生成可复用执行计划。
- 在含 1000 亿稀疏参数的工业视频推荐任务上，稳态吞吐提升 16.5%。
- 在 DLRM 上相对原生实现和 TorchRec 分别加速 1.60 倍和 1.26 倍。

【论文】【工业部署】

判断：

- 训练优化不能只盯稠密网络，稀疏算子与通信同样决定吞吐。
- 执行计划应稳定复用，避免每个训练步重复规划。
- Rust 训练控制面可负责图重建、计划缓存和资源约束检查。

#### RecIS

论文：`RecIS: Unifying Sparse and Dense Computation for Efficient Recommendation Training`

公开信息：

- 现代推荐模型同时扩展万亿级嵌入和大型 Transformer 稠密网络。
- 碎片化特征变换、设备负载不均、同步等待和 GPU 资源气泡共同限制训练吞吐。
- RecIS 自适应融合特征变换，使用哈希分片 GPU 嵌入引擎和分层通信降低冗余传输。
- 使用多阶段流水线把下一迭代输入准备与当前稠密计算重叠。
- 相对 PICASSO 和 TorchRec 最高提升 2.62 倍和 1.15 倍吞吐，步延迟最多降低 61.5% 和 12.9%。

【论文】【工业部署】

判断：

- 训练优化应以端到端数据流为目标，而非分别优化嵌入和稠密网络。
- 哈希分片、分层通信和流水线重叠应进入统一资源模型。
- Rust 训练控制面可管理分片、检查点、流水线状态和故障恢复。

#### Memory Layer

论文：`Memory Layer: Train the In-Model Cache for Recommendation Models`

公开信息：

- 早期排序阶段常在服务时植入物品嵌入缓存，但缓存处于训练循环之外，导致训练和服务表示不一致。
- Memory Layer 把物品 KV 嵌入缓存与模型联合训练，服务时直接读取同一表示源。
- 常驻嵌入覆盖尚未入缓存物品，保证所有物品都有预测。
- Instagram Reels 生产部署中覆盖率从 96% 提升到 100%，表示新鲜度从约 5 分钟降到约 20 秒。
- 训练服务归一化熵差距最多缩小 86%，最新内容召回超过 2 倍，冷启动互动提升 5% 到 6%，训练与发布计算成本降低 30%。

【论文】【工业部署】

判断：

- 物品缓存不能被当作训练之外的工程附属物。
- 缓存写入、常驻兜底和批量发布应统一为一个生命周期。
- 对 Rust 服务，物品 KV 缓存需要版本、新鲜度和回滚一致性协议。

#### SequenceO1

论文：`SequenceO1: End-to-End Ultra-Long (100K) Sequence Modeling in Recommendation with Low-Rank Caching`

公开信息：

- 10 万级行为序列不仅受注意力复杂度限制，还受特征存储、传输和重复处理限制。
- Sketch Attention 使用可学习原型和按原型归一化，把原始历史压缩为固定大小的目标无关表示。
- 目标条件交叉注意力同时使用近期 1 万后缀和长期草图。
- 低秩用户表示缓存、多请求用户级批处理、流水线提升和融合内核摊销存储、通信和计算。
- 已在抖音全流量部署，接近直接端到端扩展到 10 万序列的大部分收益。

【论文】【工业部署】

判断：

- 超长行为历史的核心是压缩后推理，不是让每条事件都进入完整模型。
- 用户表示缓存需要跨请求复用，才能同时降低训练和服务成本。
- 近期高分辨率与长期低分辨率压缩应组合，而不是二选一。

#### 多轮语义缓存

论文：`Multi-Turn Semantic Caching for Low-Cost LLM Serving`

公开信息：

- 多轮场景下，缓存回答是否可复用同时依赖双方会话历史，请求或历史的嵌入相似度预测性较差。
- 从评审反馈学习复用风险，在生成节省成本与错误复用代价之间做预算选择。
- 在一千缓存项下，避免 35% 到 41% 的生成成本，而基线最多为 22% 到 25%。
- 估计服务延迟降低 19% 到 35%。

【论文】

判断：

- 推荐解释、对话编排和多轮画像助手可使用多轮语义缓存。
- 缓存键必须包含会话状态，不能只包括当前请求。
- 错误复用代价高时，应退化为重新计算而不是追求命中率。

#### NEZHA

论文：`NEZHA: A Zero-sacrifice and Hyperspeed Decoding Architecture for Generative Recommendations`

公开信息：

- 主模型内置轻量自起草头，避免额外草稿模型和模型式验证器。
- 使用哈希集合的无模型验证器抑制幻觉。
- 已在淘宝部署，服务数亿日活。

【论文】【工业部署】

判断：

- 生成式召回需要同时解决解码速度和无效 ID 幻觉。
- 自起草、约束过滤和哈希验证应作为运行时组合，而不是模型训练后再补。

#### RcLLM

论文：`RcLLM: Accelerating Generative Recommendation via Beyond-Prefix KV Caching`

公开信息：

- 推荐提示在用户历史和物品上下文上的复用通常不连续，普通前缀缓存收益有限。
- 将提示拆成可复用块，对用户历史缓存复制，对大规模物品缓存做相似性感知分片。
- 使用亲和性调度和选择性注意力修正近似误差。
- 首 token 时间相比现有前缀缓存系统降低 1.31 到 9.51 倍。

【论文】

判断：

- 生成式推荐的缓存单位应是用户块、场景块和物品块，而不是整段提示。
- 分布式缓存布局应同时考虑命中率、数据局部性和误差修正。

#### MiniOneRec

论文：`MiniOneRec: An Open-Source Framework for Scaling Generative Recommendation`

公开信息：

- 提供语义 ID 构建、监督微调和推荐强化学习的完整开源流程。
- 基于 Qwen 0.5B 到 7B，验证规模增长时训练和评估损失持续下降。
- 使用全过程 SID 对齐、约束解码和混合奖励。

【论文】【开源复现入口】

判断：

- 适合作为生成式推荐的最小可复现基线。
- 不能把 Amazon 数据结果直接外推到短视频。
- 适合先验证语义 ID、训练、约束解码和评测链路。

#### FlashRec

项目：`FlashRec`

公开信息：

- CUDA 图引擎，面向 3 到 5 步语义 ID、50 到 512 以上 beam 宽度。
- 使用 trie 约束目录，支持进程内 FP8 服务和 beam 排序接口。

【厂商自述】【开源项目】

判断：

- 宽 beam 生成式推荐的瓶颈在约束、调度和显存管理。
- 值得跟踪，但项目成熟度低于 OpenOneRec 和 Meta 仓库。

#### DuoLM

论文：`DuoLM: Fast and Effective Personalized Recommendation with Language Models`

公开信息：

- 编码器语言模型离线学习紧凑物品表示，个性化排序语言模型组合物品表示、用户历史和反馈。
- 使用虚拟 token ID 访问嵌入、共享历史计算和 CUDA Graph 回放降低在线成本。
- 推荐质量接近专家教师模型。
- 单张 H100 每秒约评分 2.64 万候选，约为启用前缀缓存的教师模型吞吐的 60 倍。

【论文】

判断：

- LLM 推荐应拆成离线物品编码和在线个性化排序，避免每次重复编码物品全文。
- 共享历史计算、虚拟 token 和静态图回放是低延迟运行时的核心。
- 需验证该吞吐在短视频多模态和长历史下的衰减。

#### OneLA

论文：`OneLA: Scaling Linear-Attention Decoding to Large Beams in Generative Recommendation`

公开信息：

- 大 beam 生成会迫使线性注意力系统为每个 beam 保存完整循环状态或重复回放历史。
- OneLA 用单一共享提示状态和紧凑、只追加的分歧转移记录表示所有 beam。
- 使用祖先索引跟踪每条束的转移记录，避免移动或复制已有状态。
- 融合 GPU 内核复用共享状态，端到端解码提升 1.54 到 2.46 倍。

【论文】

判断：

- 宽 beam 优化的核心是共享状态和增量分歧记录，不只是提高单次矩阵计算速度。
- 适合与 Deco、ZeroGR 组合形成低延迟宽 beam 路径。

#### SPRINT

论文：`SPRINT: Single-Step Generative Recommendation via Average Probability Velocity`

公开信息：

- 自回归和非自回归生成通常都需要多次前向。
- SPRINT 将语义 ID 生成视为概率流，用平均概率速度一次预测全部 token 概率。
- 使用双层流对比目标恢复物品内 token 一致性。
- 相比第二快的自回归或非自回归方法，生成速度提升 8.39 到 10.04 倍，平均准确率提升 7.77%。

【论文】

判断：

- 若一次前向可生成完整候选，在线成本结构会显著改变。
- 需要验证一次生成对复杂语义、多兴趣和长尾候选的覆盖。

#### Beyond the Beam

论文：`Beyond the Beam: Constructive Repair and Candidate Completion for Generative Recommendation`

公开信息：

- 有效物品标识可能因目录扩张而落到 beam 外。
- 使用输出不变性证书识别所有可允许分配都存在的失败。
- 通过积分流构造最小替换修复，并在推理时结合生成似然与协同证据。
- 在三个 Amazon 类目上，平均 Recall@10 提升 15.5% 到 46.3%，NDCG@10 提升 15.2% 到 44.4%。

【论文】

判断：

- 生成式召回应具备候选补全和可验证停止条件。
- 新物品持续进入时，不能假设历史 beam 永远覆盖有效目录。

#### 连续查询生成

论文：`Beyond Semantic IDs: Finite-Beam Reachability and Continuous-Query Generation in Generative Recommendation`

公开信息：

- 有限 beam 离散语义 ID 会限制未命中目标进入返回列表。
- 连续查询生成保留自回归建模，但移除离散物品 token、码本查找和离散束扩张。
- CQG-Single 在七次运行中均超过 TIGER 风格基线，可训练参数为 55.3%。

【论文】

判断：

- 物品输出接口不必固定为离散语义 ID。
- 连续查询加近似最近邻检索可作为生成式路线的 A/B 替代方案。
- 需要防止连续生成失去目录约束和无效候选过滤能力。

#### 语义索引与训练目标

论文：

- `A Systematic Study of Semantic ID Spaces`
- `Training with Missed Targets`
- `Structure-Aligned History Learning`
- `Where Beam Search Loses Top-Ranked Items`

公开信息：

- 语义 ID 设计存在非单调效应，没有普遍最优的量化方案。
- 训练时追加未召回目标可能与推理候选竞争概率，反而破坏返回列表排序；部分设置中不追加可把 FT-NDCG 改善 7.8% 到 22.2%。
- SAHL 用量化形成的 token、子空间和物品层级重建历史，NDCG@10 相对 RPG 提升 18.6% 到 30.0%。
- 束搜索的主要损失集中在第一步覆盖；重新分配不同 SID 位置的保留预算，可在不训练的情况下用约一半前缀预算复现更宽束排序结果，并节省约 6.4% 解码延迟。

【论文】

判断：

- 语义 ID、训练目标和束预算必须联合设计，不能简化为码本越大越好或 beam 越宽越好。
- 缓解长尾不能把未召回目标直接混入推理候选的竞争集合。
- 束预算应优先覆盖第一解码步，而不是平均增加所有前缀宽度。

#### PSG

论文：`PSG: Pair-Space Generation for Efficient Generative Reranking`

公开信息：

- 列表重排通常由生成器逐物品生成候选列表，再由评价器选择。
- PSG 把生成原子从单个物品提升为有序物品对，列表长度不变时只需生成一半 token。
- 物品对表示由预训练模块在线生成，避免二次方词表带来的数据稀疏。
- 理论速度提升约 2 到 4 倍，工业环境提升 1.83 倍。
- 快手部署后人均停留时间提升 0.178%。

【论文】【工业部署】

判断：

- 长列表生成不一定逐物品展开，成对或分段生成可同时降低延迟和累计误差。
- 成对词表需要专门的表示模块，不能直接枚举二次方组合。
- 部署时必须验证成对顺序表达力和列表内相对关系是否足够。

#### GRACE

论文：`GRACE: Generative Recommender Acceleration Engine for Real-Time Ads Retrieval`

公开信息：

- 广告生成召回需要同时满足广告主定向资格和严格延迟。
- 在有效物品约束解码上增加基于位掩码和 Bloom 过滤器的个性化前缀过滤。
- 目标匹配通过率从 23.55% 提升到 40.42%。
- 针对宽束、短序列的解码器优化覆盖注意力内核、KV 缓存和束搜索。
- 在 GH200 上交叉注意力延迟降低 68.0 倍，自注意力降低 23.4 到 25.8 倍，解码器总延迟降低 11.1 倍。

【论文】【工业部署判断】

判断：

- 生成召回不只是有效 ID，还要满足业务资格和受众规则。
- 约束应尽量作用在前缀层，避免生成完整列表后再大批丢弃。
- 宽束短序列与普通长文本生成的服务内核需求不同。

#### 服务时语言模型必要性审计

论文：`Is Serving-Time Language-Model Inference Necessary for Recommendation?`

公开信息：

- 使用恢复式机制审计，检验去掉语言模型在线推理后，独立替代方案能否保持精度。
- LIME-Rec 组合序列、协同和离线语义信息，不使用自回归语言模型解码。
- LIME-Rec 在三个 Amazon 数据集的 12 个数据集指标组合中均取得最高均值，Recall@10 相对 GRAM 提升最高 15.2%。
- DART-Rec 使用确定性融合和固定专家选择替代 LM 工具控制，Recall@10 相对微调 LM 控制器提升 16.7%。
- 最多两次工具调用时，固定专家选择在 18 个对照中的 17 个达到与 LM 控制器相同的结果。

【论文】

判断：

- 强结果不能证明服务时必须调用语言模型。
- 所有语言模型推荐方案都应设置同信息、同候选、同工具预算的恢复式基线。
- 离线语义、协同证据和确定性编排可以承担大部分当前收益。

## 四、用户画像与偏好算法

### 4.1 核心结论

用户知识库、全部历史信息和历史行为不能直接拼成一个超长提示词。

应拆成以下结构：

```text
原始事件
-> 可审计事实
-> 短期工作记忆
-> 长期偏好画像
-> 个人知识图谱
-> 场景化检索
-> 推荐模型特征
```

每条画像和事实至少应携带：

```text
来源
时间
置信度
敏感级别
有效期
可撤销标识
证据引用
```

推荐模型只消费经过授权的最小必要投影。

### 4.2 多层画像

#### 实时状态层

内容：

- 当前会话主题。
- 最近几次观看、跳过、回滑和停留。
- 设备、网络、时间和位置等授权上下文。

特征：

- 秒级到分钟级更新。
- 不作为长期事实。
- 请求结束后可快速衰减。

#### 短期偏好层

内容：

- 最近数天到数周的兴趣变化。
- 新出现的创作者、话题和内容形式。
- 临时负反馈。

特征：

- 使用序列模型或滑动窗口。
- 允许与长期画像冲突。
- 冲突本身可作为探索信号。

#### 长期画像层

内容：

- 稳定兴趣和厌恶性。
- 内容深度、节奏、时长、语言、画质偏好。
- 创作者和主题的长期关系。

特征：

- 增量更新，不反复重建全部历史。
- 必须支持遗忘和证据撤销。
- 不以单次行为覆盖稳定结论。

#### 个人知识图谱层

内容：

- 人物、地点、事件、设备、关系、时间和主题。
- 事实来源、置信度、时间和冲突关系。
- 跨短信、相册、文件和 IM 的关联。

特征：

- LLM 擅长从多源材料提取压缩语义。
- 知识图谱擅长扩散关联和保持一致性。
- 原始私人资料不进入推荐请求链路。

#### 检索投影层

内容：

- 当前请求最相关的少量事实、摘要和向量。
- 当前可用的负约束和隐私边界。

特征：

- 在线只检索和拼装，不实时生成长期画像。
- 设定严格 token、字节和延迟预算。
- 不允许历史文本改变权限。

### 4.3 代表工作

#### PersonaX

论文：`PersonaX: A Recommendation Agent-Oriented User Modeling Framework for Long Behavior Sequence`

公开信息：

- 将完整行为分段并聚类。
- 选择兼顾典型性和多样性的子行为序列。
- 离线生成多人物画像并缓存。
- 在线按需检索画像，而不是实时生成。
- 仅使用 30% 到 50% 的行为数据时，报告 AgentCF 提升 3% 到 11%，Agent4Rec 提升 10% 到 50%。

【论文】

判断：

- 非常适合低延迟系统。
- 思路与“离线画像、在线检索”一致。
- 需自行验证对短视频行为是否同样有效。

#### HARP

论文：`HARP: Training-Free Dual-Profile Agentic Communication for LLM-Based Recommendation`

公开信息：

- 当前 LLM 推荐常只给用户侧结构化画像，物品侧没有对称画像。
- 画像常被塞进带宽有限的精排提示词，而没有进入召回。
- 用户画像在预热后冻结，缺少持续同步规则。
- HARP 使用对称物品画像、召回侧画像同质性门控和单次反思更新。
- 无需训练，四个公开基准 Hit@1 相对最强已发表基线提升 6.9% 到 24.0%。

【论文】

判断：

- 用户侧和物品侧双向画像比单向用户提示更完整。
- 画像入口应放在召回阶段，而不是只占精排上下文预算。
- 免训练方案适合先验证画像价值，但高百分比提升仍需在短视频真实流量复测。

#### LLM-TUP

论文：`Temporal User Profiling with LLMs: Balancing Short-Term and Long-Term Preferences for Recommendations`

公开信息：

- 分别生成短期和长期偏好文本。
- 使用 BERT 编码，再用注意力动态融合。

【论文】

判断：

- 短期与长期画像不能只做一个平均向量。
- 自然语言画像适合解释和审计。

#### RECAP

论文：`RECAP: Feedback-Driven Streaming Semantic User Profiles for Short-Video Recommendation`

公开信息：

- 面向快手短视频，用户行为持续流入，画像必须在有限容量下增量更新。
- 维护有界结构化记忆，结合 LLM 语义更新和确定性生命周期控制。
- 用标签一致行为对训练双塔评价器，将其匹配分数作为 GRPO 奖励。
- uAUC 提升 0.0084，Recall@2000 提升约 4.9%。
- 7 天线上 A/B 中，用户平均 App 使用时长提升 0.139%。

【论文】【工业部署】

判断：

- 直接回答了“画像更新是否应闭环优化未来推荐”，答案是应当。
- 有界结构化记忆比无限追加摘要更符合存储和延迟目标。
- 确定性生命周期控制应优先于让模型自行决定删除。

#### 画像策略适用边界

论文：

- `When LLM-Based User Profiling Adds Value in Production Streaming Recommendation`
- `When LLM-Inferred User Context Adds Value in Production Streaming Recommendation`

公开信息：

- 数值聚合画像生成成本明显低于 LLM 自然语言画像。
- 在真实生产流式推荐中，习惯型消费用户约占总体八成，聚合画像持续更强。
- 对行为语义明显偏离历史、探索性更强的用户，LLM 生成画像更有价值。
- LLM 画像有热门吸引力效应，列表内多样性略升，但目录覆盖和新鲜度可能下降。

【论文】【工业部署】

判断：

- 不应给所有用户统一使用昂贵 LLM 画像。
- 在线应按消费模式选择聚合画像或生成画像。
- 三低目标下，LLM 画像主要服务探索性用户和冷启动场景。
- 必须同时监控目录覆盖、新鲜度和热门偏置。

#### 不确定性校准的用户分层策略

论文：`Uncertainty-Calibrated Recommendations for Low-Active Users`

公开信息：

- 低活跃用户需要可靠性，高活跃用户更需要多样性，二者不应使用同一探索策略。
- 模型不确定性可表示预测错误风险，以及模型当前知识的边界。
- 对低活跃用户采用风险规避的降权策略，抑制不可靠推荐。
- 对高活跃用户采用风险偏好的上置信界探索。
- 在生产直播平台提升低活跃用户留存和优质观看时长比例，同时提升高活跃用户兴趣多样性和类目覆盖。

【论文】【工业部署】

判断：

- 不确定性不仅能修正标签，还能决定探索和利用的用户分层策略。
- 低活跃用户应优先避免错误推荐，高活跃用户才适合扩大探索。
- 该策略可迁移到短视频，但需验证低频用户是否因降权进入更小候选池。

#### SPW-Gate

论文：`Prediction Is Not Memory: Dual-Timescale Gated Profile Writing`

公开信息：

- 区分预测下一次交互和决定该交互是否写入长期画像。
- 盲目全部写入会使约 22.45% 测试样本的远期画像对齐变差。
- SPW-Gate 使用长期、短期和候选画像漂移特征控制写入风险。
- 远期受损比例降至约 14.5%，同时保留约 77% 写入覆盖。
- 下一次物品预测置信度不能替代持久写入有效性判断。

【论文】

判断：

- 看到行为不等于应形成长期偏好。
- 临时探索、误触、推广曝光和短时情绪必须与稳定偏好分开。
- 在线应先进入短期状态，经过时间、重复性和证据一致性判断后再晋升长期画像。

#### TokenMinds

论文：`TokenMinds: Pretrained User Tokens and Embeddings for User Understanding in Large Recommender Systems`

公开信息：

- 编码器输出稠密用户状态，解码器生成多面向未来兴趣的离散用户 token。
- 物品语义 ID 统一长短视频和跨场景行为。
- 共享词表使上游训练和服务计算分别降低 50% 和 31%。
- 文本搜索查询可与观看历史交错输入，表达显式意图。
- 在 YouTube 主要排序面进行线上 A/B，离散用户 token 与稠密向量增益可叠加。

【论文】【工业部署】

判断：

- 用户表示应采用稠密状态加离散多兴趣的双输出，而不是二选一。
- 离散用户 token 有缓存、压缩和跨场景复用优势。
- 用户 token 必须绑定来源和行为时间，避免长期漂移不可追踪。

#### BLUE

论文：`Bridging Textual Profiles and Latent User Embeddings for Personalization`

公开信息：

- 文本画像可解释，但难以直接优化下游推荐收益。
- 潜空间用户向量适合检索，但缺少可读性。
- BLUE 用强化学习让 LLM 生成文本画像，同时用嵌入模型提供正负样本奖励。
- 在跨域零样本序列推荐中提升，并改善跨域迁移。

【论文】

判断：

- 文本画像和向量画像不应分别维护两套互不一致的事实。
- 可把文本作为权威解释层，向量作为同一画像的可检索投影。

#### 行为画像落地

论文：`Behaviorally Grounded User Profiles from the Wild for Personalized Alignment and Multi-Perspective Reasoning`

公开信息：

- 从真实、匿名化社交内容提取开放式高保真画像。
- 行为画像优于合成角色画像。
- 同时验证训练时微调与非参数测试时多视角推理。

【论文】

判断：

- 画像不能只由标签或人口属性拼接。
- 对个人知识库，应优先保留可追溯到真实行为、事件和表达方式的证据。

#### 画像评估

论文：`GISTBench: Evaluating LLM User Understanding via Evidence-Based Interest Verification`

公开信息：

- 不只看下一物品命中，而是验证模型抽取的兴趣是否有证据。
- 评估兴趣有据率、精确率、召回率和兴趣特异性。
- 数据来自全球短视频平台的真实用户交互，包含隐式和显式反馈。
- 当前 LLM 在异构交互类型的计数与归因能力上仍有明显瓶颈。

【论文】

判断：

- 画像评估必须同时测幻觉兴趣和漏掉兴趣。
- 推荐效果提升不能掩盖画像证据错误。

#### 画像路由门控

论文：`Routing Between Generative and Collaborative User Profiles: A Serving-Time Gate for Controllable Novelty`

公开信息：

- LLM 用户画像生成成本高，不适合所有用户统一部署。
- 在真实流媒体数据上训练服务时路由门控，按用户选择协同序列模型或 LLM 画像模型。
- 门控只使用服务时特征，并学习识别哪些用户能通过画像路由提升 Novelty@10。
- 在总体 NDCG 损失不超过 5% 的预算下，仅路由 12.5% 用户即可把 Novelty@10 提升 6.5%。
- 结果优于启发式和随机路由，且非生成式语义画像也有部分收益，说明关键是选择性路由。

【论文】【工业部署】

判断：

- 最便宜的 LLM 画像是“不用 LLM 画像”，只在可能有增量价值的用户上调用。
- 路由目标应是新颖度、相关性和成本的显式帕累托边界。
- 路由决策必须可回滚，并持续监控热门偏置和目录覆盖。

#### MATE

论文：`MATE: Adaptive Long- and Short-Term User Memory for LLM-Based Recommendation`

公开信息：

- 语义表示不能判断哪些历史反映持久偏好，哪些只代表近期兴趣。
- 新交互同时根据历史重复支持和近期一致性评估。
- 长期记忆保守保存持久偏好，短期记忆快速适配近期兴趣。
- 推荐时由近期上下文动态决定两类记忆的贡献强度。
- 在线只更新用户记忆，共享模型保持固定；在 MovieLens-10M、Amazon 和 KuaiRec 上 NDCG@10 相对最强外部基线提升 7.0% 到 13.2%。

【论文】

判断：

- 用户画像更新应是双记忆、双时间尺度，而不是单一向量滑动平均。
- 在线不重训全局模型，只更新用户状态，更适合三低目标。
- 需要防止短期热点永久污染长期偏好。

#### CoVeMem

论文：`When Memory Takes Gradients: Collaborative Vector Memory for Agentic Recommender Systems`

公开信息：

- 文本记忆每次更新都要重写，且协同相似度难以完整转成句子。
- 使用冻结 LightGCN 用户和物品状态构建向量记忆库。
- 候选集合本身检索相关历史状态，作为软 token 进入 LLM 上下文，并配轻量文本画像。
- 在四个指令推荐基准的 20 个指标格中，19 个达到或超过最强协同文本记忆智能体。
- 除共享静态画像外，记忆维护不需额外 LLM 调用。

【论文】

判断：

- 个性化记忆应同时保留离散文本和可训练协同向量。
- 候选相关的历史状态应在请求时动态检索，不应全部文本化。
- 对 Rust 服务端，可把向量记忆库、软 token 组装和 LLM 推理拆分。

#### Textual User Taste

论文：`Textual User Taste: Natural-Language User Context for Foundation-Model Recommender System at Scale`

公开信息：

- 从听歌行为、互动、内容元数据和可选反馈生成结构化自然语言品味画像。
- 已部署到数百万 Spotify 用户。
- 品味画像独立携带用户预测信号；与行为嵌入组合后，未来歌曲预测 MRR 提升 0.6%，搜索排序 NDCG@7 提升 2.2%。
- 支持自然语言用户转向，但否定和短期时间适配仍困难。

【论文】【工业部署】

判断：

- 自然语言画像是可解释和可操控接口，不是行为嵌入的替代品。
- 必须单独评估“正向偏好表达”和“否定偏好表达”。
- 短期变化不能只依赖文本画像，需与序列模型和短期状态配合。

#### MAP

论文：`Memory Assisted LLM for Personalized Recommendation System`

公开信息：

- 建立历史画像。
- 推荐时按相似性提取相关记忆，而不是注入全部历史。
- 历史越长，按需检索相对直接提示的优势越明显。

【论文】

#### PURE

论文：`LLM-based User Profile Management for Recommender System`

公开信息：

- 从评论中抽取偏好和产品特征。
- 增量更新画像。
- 使用当前画像做推荐。

【论文】

判断：

- 可迁移为“事件抽取 -> 画像更新 -> 投影生成”。
- 关键是更新规则和撤销机制，不是抽取提示词本身。

#### PersonaAgent with GraphRAG

论文：`PersonaAgent with GraphRAG: Community-Aware Knowledge Graphs for Personalized LLM`

公开信息：

- 从文档构建 LLM 图索引。
- 对相关信息社区做摘要。
- 组合个人历史画像和全局交互模式。
- 在 LaMP 基准上报告新闻分类 F1 提升 11.1%，电影标签 F1 提升 56.1%，商品评分 MAE 降低 10.4%。

【论文】

判断：

- 适合个人知识库。
- 社区摘要可作为长期画像的压缩层。
- 图检索结果必须保留证据和时间，避免旧事实覆盖新事实。

#### SPiKE

论文：`Enriching Semantic Profiles into Knowledge Graph for Recommender Systems Using Large Language Models`

公开信息：

- LLM 为知识图谱实体生成语义画像。
- 将画像并入知识图谱传播。
- 使用成对画像偏好匹配训练。

【论文】

判断：

- 该路线明确区分 LLM 的语义压缩和知识图谱的传播能力。
- 适合把手机知识库转成可检索的个人图，而不是只存向量。

#### 个性化 LLM Agent 综述

论文：`Toward Personalized LLM-Powered Agents: Foundations, Evaluation, and Future Directions`

公开信息：

- 将个性化拆成画像建模、记忆、规划和行动执行。
- 强调跨组件传播用户信号。

【论文】

判断：

- 推荐系统不应自己管理全部私人资料。
- 推荐只应调用画像、记忆和授权服务。

### 4.4 长期记忆的更新与修复

#### KITE

论文：`KITE: Retrieval as a Decision Procedure for Long-Term Conversational Memory`

公开信息：

- 不把相似度排序等同于记忆是否满足问题条件。
- 用受治理主题词表组织多会话知识，并把查询编译成可检查的检索计划。
- 在 LoCoMo 和 LongMemEval-S 报告 93.5% 和 86.0% 准确率，每题仅约 1.6k 读者上下文 token。

【论文】

判断：

- 适合个人知识库，因为长期偏好不能只靠向量相似度。
- 检索计划可解释，便于审计私人事实为何进入推荐。
- 主题词表的演进、合并和访问控制是主要工程成本。

#### EvoMemState

论文：`EvoMemState: Evolving Memory State for Personal Agents`

公开信息：

- 不把记忆当成独立事实集合。
- 用关系状态维护事实有效期、范围和相互关系。
- 用推理状态决定当前请求应如何应用这些事实。
- 在长期对话和记忆使用基准上提高检索完整性和有据回答准确率。

【论文】

判断：

- 直接对应旧偏好是否仍有效、是否被新事实推翻的问题。
- 推荐画像应采用状态化事实，而不是只追加文本摘要。

#### MemShift

论文：`MemShift: Separating Detection from Repair in LLM-Derived Personal Memory`

公开信息：

- 将个人记忆维护拆成变更检测和值修复。
- 覆盖来源修订、删除、重新定义、写作者切换和导出五类变化。
- 检测只有在修复能力允许时才有价值。
- 由 LLM 为类型化记录生成程序，比直接让 LLM 重新推导更接近精确重算。

【论文】

判断：

- 删除和修订不是后台清理任务，而是画像正确性的前置条件。
- 应保存事实依赖，删除上游事实时级联撤销下游结论。

#### StateGraph

论文：`A State Change Is Local, Its Consequences Are Not: Dependency-Aware State Revision for Long-Term Agent Memory`

公开信息：

- 上游事实变化后，依赖该事实的信念、计划和动作也必须重新验证。
- 使用反事实验证区分支持依赖和语义相关。
- 在多跳依赖深度增加时，影响识别相对基线优势扩大。

【论文】

判断：

- 个人知识库应维护事实依赖图。
- 推荐画像的更新必须能回答这条偏好结论由哪些证据支撑。

#### Scalaris

论文：`Scalaris: A Scalable Enterprise Memory Architecture for Conversational AI Assistants`

公开信息：

- 分开处理用户交互和助手回复。
- 用户交互跨会话保留，助手回复只检索当前查询相关信息。
- LongMemEval-S 准确率 92.2%，LoCoMo 90.77%。
- 检索上下文 token 约为对照系统的十分之一。

【论文】

判断：

- 用户事实和模型回复不能使用同一套存储策略。
- 对三低目标，记忆检索应优化有效上下文 token，而不是召回越多越好。

#### AgentMemRec

论文：`Agent Memory as Recommendation: Recommender-System Design for Long-Term Memory of LLM Agents`

公开信息：

- 把长期记忆选择形式化为预算化列表推荐。
- 请求视为用户，记忆视为物品，上下文窗口视为列表。
- 使用候选生成、学习排序和列表构造，选择记忆时不需要调用 LLM。
- 在 LongMemEval 多会话问题上，相对 A-Mem、HippoRAG 2、DynamicRAG 和 T-Mem 提升 10 到 31 个百分点。
- 匹配每查询调用 64 次的 LLM 重排器，同时服务成本降低 3.2 倍。
- 在 LoCoMo 上优于 Mem0 和 Zep，且写入阶段没有 LLM 调用。

【论文】

判断：

- 这是个人知识库与推荐系统最直接的交汇点。
- 记忆选择可以直接复用召回、粗排、精排和列表构造，不需要另造一套检索栈。
- 该路线适合三低目标：写入便宜、在线无 LLM、能控制上下文预算。
- 必须保证多会话问题所需的全部证据能同时进入列表，而不是只要单条高相似记忆。

#### Gated Memory

论文：`Gated Memory: Admission-Controlled Memory Formation for Conversational AI`

公开信息：

- 记忆形成阶段是长期记忆质量的约束点。
- 永久用户属性与临时情境的区别只存在于原始表达中，抽取成三元组后不可恢复。
- 在抽取前设置准入门，并做条件化富化。
- 每条事实标注直接陈述或推断来源、适用范围、时间和地点。
- 不允许断言上下文中不存在的实体；在 LoCoMo-10 上总体准确率相对提升 2.6%。

【论文】

判断：

- 不应先把所有内容抽成事实再判断是否长期有效。
- 准入时应同时保留原始表达、来源和推断标记。
- 对手机知识库，实体范围必须绑定授权域，不能让跨应用推断无限扩散。

#### BehaviorMem

论文：`BehaviorMem: Building and Evaluating User Memory from Real-World E-Commerce Behavior Streams`

公开信息：

- 同时研究从行为日志记住具体证据，以及推断未直接写出的需求和偏好。
- BehaviorMemBench 来自真实电商日志，包含 1194 名用户、17462 个行为批次和三年以上数据。
- BehaviorMem 将显式行为事实和推断特征组织在长期、短期两轴状态中。
- 使用证据有据的形成、持续维护和查询无关读出，在记住与推断两类任务上领先现有智能体记忆。

【论文】

判断：

- 行为画像必须把“记住发生过什么”和“推断意味着什么”分开评估。
- 用户画像投影不应依赖某个查询结构，否则难以稳定复用。
- 该结构适合手机行为日志与个人知识库的离线统一。

#### CGM-Rec

论文：`Continual Graph Memory for Adaptive Recommendation under Intent Drift`

公开信息：

- 传统知识图谱增强推荐把图当作静态检索底座，难以适应意图漂移、噪声元数据和重复失败。
- CGM-Rec 把图状态视为可写记忆，分为保守更新的语义图记忆和快速反应的情景经验记忆。
- 测试时模型参数保持冻结，适应只通过记忆写入完成。
- 在 Bundle 场景相对最强 LLM 基线 HR@1 最多提升 29.58%；在元数据丰富数据上 HR@5 达到 0.5941，对比基线为 0.4746。

【论文】

判断：

- 个人知识图谱不应只在离线重建，应支持带有质量门的持续写入。
- 稳定关系知识与近期失败经验应分开存储，避免高频反馈污染长期图。
- 冻结参数、只写记忆是低风险画像适应路径。

#### OMEGA

论文：`Collaborative Memory Augmentation for Generative Recommendation`

公开信息：

- 传统生成式推荐只在单个用户序列和模型参数内建模，没有显式利用跨用户协同信号。
- OMEGA 使用可学习查询 token 压缩序列行为，聚合成协同记忆库。
- 目标感知检索同时考虑序列级和目标级相似性。
- 门控交叉注意力组合协同记忆与本地用户上下文，并抑制噪声模式。

【论文】

判断：

- 生成式模型需要外部协同记忆补足参数内无法覆盖的跨用户模式。
- 协同记忆必须目标相关，不能只按用户相似度整体注入。
- 跨用户记忆应保存模式而不是原始用户数据，降低隐私和删除成本。

#### LoopMemGR

论文：`LoopMemGR: From Behavior Logs to Evolving Memory for Generative Recommendation`

公开信息：

- 传统生成式推荐记住用户行为，却丢弃系统过去推荐了什么以及反馈结果。
- LoopMemGR 增加推荐经验日志，记录推荐与反馈轨迹。
- 近期视图捕获短期动态，频率视图总结重复模式，全局视图提取跨用户可迁移规律。
- 多视图经验压缩成固定数量 token，在固定输入预算下条件生成。

【论文】【工业数据】

判断：

- 推荐系统需要记住“我推荐过什么”，不仅记住“用户做过什么”。
- 曝光历史、负反馈和探索结果应作为独立记忆证据。
- 经验记忆必须有界，不能随请求无限累积。

#### MEMOIR

论文：`MEMOIR: Temporal Behavioral Memory for Recommendation Across the Preference-Drift Spectrum`

公开信息：

- 按时间窗口切分用户历史，为每个时期生成语义行为记忆。
- 将当前状态、演变方向和预测未来聚合成一个用户表示。
- 在低漂移和高漂移极端用户上，NDCG@10 和 MRR 表现更好。
- 单一组件消融都无法解释大部分相对收益，说明收益依赖时间、演变和互补信号的组合。

【论文】

判断：

- 偏好漂移不是异常，静态画像需要同时表达当前状态和变化方向。
- 画像评估应按漂移程度分层，总体均值会掩盖两端效果。
- 不能从组件消融微小差异推断某个单独模块是主因。

#### ReMem

论文：`ReMem: Rethinking Perception and Memory in Long-Context Recommendation Agents`

公开信息：

- 推荐智能体的物品感知常依赖噪声 HTML，多种页面结构导致脆弱。
- ReMem 使用截图和 OCR 抽取结构化多模态物品信息。
- 使用分块顺序记忆更新，以固定大小记忆处理任意长历史，线性推理复杂度且有界上下文。
- 多记忆 GRPO 将最终答案优势传播给中间贡献对话。
- 在搜索、排序和判断三类推荐智能体任务上平均提升 5.16%。

【论文】

判断：

- 智能体感知应按页面视觉结果处理，不应绑定特定平台 HTML。
- 固定大小动态记忆比把全部历史送入长上下文更可控。
- 中间对话贡献应获得信用，否则长期记忆更新会缺少有效训练信号。

#### AtomRec

论文：`AtomRec: Evolving Atomic Memory for Agentic Recommendation`

公开信息：

- 粗粒度摘要和标量协同链接难以保留细粒度偏好阶段和可解释证据。
- AtomRec 把用户和物品记忆表示为结构化原子单元，并建立语义链接。
- 新交互到来时更新相关历史字段，推荐时检索链接记忆形成多跳证据路径。
- 四个公开基准上相对智能体和记忆增强基线平均提升约 8.5%。

【论文】

判断：

- 画像事实应原子化，才能局部更新和撤销。
- 协同关系应通过可解释证据路径进入推荐，而不是单一相似度标量。
- 多跳证据需要控制路径数量和上下文预算。

#### TIDE

论文：`How Can Recommendation Feedback Evolve Agent Memory?`

公开信息：

- 曝光、点击、转化和负反馈延迟且有噪声，还受受众、位置和推荐策略混杂。
- TIDE 把记忆视为容量受限的经验种群，使用时间和语义信用分配估计上下文适配度。
- 根据生成时引用的记忆分配结果责任，再对记忆执行强化、交叉、变异或淘汰。
- 记忆演化收益衡量在严格未来任务上相对无记忆基线的提升，离线提升 7.75 个百分点，线上点击和激活率均提升。

【论文】【工业部署】

判断：

- 推荐反馈可以更新画像，但必须同时做时间归因、语义归因和责任归因。
- 过期或低价值记忆应被淘汰，不能只新增。
- 记忆效果必须在未来任务评估，不能回看已有标签。

#### ETAMem

论文：`ETAMem: Decoupling and Aligning Heterogeneous Memory for Long-Term Conversational Agents`

公开信息：

- 记忆系统常见信息纠缠和结构错配，语义相似并不覆盖事件、情绪和时间关联。
- ETAMem 将记忆拆到事件、情绪和时间三个层级视图，并提取原子记忆单元。
- 检索时按视图分配查询相关预算，并在每个视图内层级搜索。
- 在 LoCoMo 和 LongMemEval-S 上相对最强基线分别提升 12.46% 和 7.96%。

【论文】

判断：

- 长期画像不应只用一个语义向量或一张图。
- 情绪和时间视图需要独立预算，因为“何时”和“当时感受”经常决定推荐是否合适。
- 多视图必须共享来源证据，避免同一事实在不同视图产生冲突。

#### ReMind

论文：`Recall Begets Recall: Recurrent Memory Ranking for Personalized LLMs`

公开信息：

- 单轮记忆排序会漏掉与问题表面不相似、但对答案必需的间接记忆。
- ReMind 每轮把高分记忆并入下一轮查询线索，逐步形成更具体的复合线索。
- 使用充分性预测器判断当前记忆是否足够，从而自适应停止，而不是固定 top-K。

【论文】

判断：

- 长期画像检索应是逐步补全证据的过程，不应一次截断固定数量。
- 记忆选择数量应随请求复杂度变化。
- 充分性判断错误会造成过早停止，需要证据覆盖和冲突检查。

#### OMCE 经验元控制

论文：`Evolving Memory, Learning to Meta-Control: Test-Time Adaptation for Experience-augmented LLM Agents`

公开信息：

- 现有经验增强智能体依赖固定管线，没有学习何时、以何种格式使用经验。
- OMCE 使用轻量上下文老虎机，在 DIRECT、EPISODE、GUIDE、DISTILL 四类认知动作间路由。
- 在线根据任务反馈更新记忆库和路由策略。
- 四个在线适应基准上，首次成功最高提升 20.5 个百分点，单任务 token 使用相对强基线降低 5.7 到 62.5 倍。

【论文】

判断：

- 画像检索不应固定为“每轮都做相似度召回”。
- 有时直接回答、有时读取事件、有时生成指导、有时合并经验，应该由任务状态决定。
- 元控制策略可以持续学习，但不能直接改写长期事实记忆。

#### ResMem 检索知识固化

论文：`From Lookups to Lessons: Turning Retrieved Knowledge into Parametric Memory`

公开信息：

- 把历史检索信息蒸馏到参数记忆，可减少在线检索和存储成本。
- ResMem 让 LLM 离线读取证据并生成教师目标，参数记忆学习附加 logit 残差。
- 教师构建保留存储相对 kNN 管线减少 94.7%。
- 五个问答数据集中平均 token F1 从 32.83 提升到 34.48，破坏原有正确答案的比例减少 21%。

【论文】

判断：

- 高频稳定的个人事实可逐步固化到专用参数记忆，低频变化事实保留外部检索。
- 固化目标应优化对现有模型输出的增量，而不是单纯模仿检索器。
- 固化后的记忆必须继续支持来源追踪、修订和删除。

#### 长上下文压缩

论文：`You don't need long context`

公开信息：

- 后部 token 的生成成本显著高于前部，前沿开放模型成本差距最高可达 7 倍。
- 频繁压缩后，模型在大量长任务和长输入任务上保持短上下文几乎不损失准确率。
- 长程软件工程任务每次上下文只保留一个动作也不会直接崩溃。
- 由此提出语义状态空间模型方向。

【论文】

判断：

- 推荐与画像助手不需要持续保存无限长原始对话。
- 应把历史压缩为语义状态、证据指针和当前任务工作帧。
- 压缩不能只保摘要，还要保留可恢复原文的引用。

#### 记忆写入容量

论文：

- `Write What Matters: Disentangling Token Selection from Slot Allocation in Recurrent Memory`
- `The Price of Scale in Proactive Memory Recall`

公开信息：

- 固定槽位记忆必须先决定哪些 token 写入，再决定为它分配多少槽位。
- 密集事实场景中总是写入更有利，稀疏事实且干扰多时选择性写入更有利。
- 主动记忆召回会随存储规模增加而变成多重检验问题；在 2048 条记忆时，按 8 条记忆调优的相似度阈值可能产生 84% 到 100% 假警报。
- 在相同假警报预算下，经过校准的门控比原始余弦召回高 14 到 26 个百分点。

【论文】

判断：

- 画像写入要区分信息密度与干扰密度，不能使用固定策略。
- 主动提醒和主动推荐必须随存储规模重新校准触发阈值。
- 越大记忆库越需要背景校准或多重假设控制，否则用户会收到大量伪相关打扰。

#### Memora

论文：`From Recall to Forgetting: Benchmarking Long-Term Memory for Personalized Agents`

公开信息：

- 现有长期记忆评测多只测历史事实检索，忽略整合和更新。
- Memora 覆盖数周到数月对话，评估记忆、推理和推荐。
- 引入遗忘感知记忆准确率，惩罚继续使用过期或已失效记忆。
- 四个 LLM 和六个记忆智能体经常复用失效记忆，无法协调演化信息。

【论文】

判断：

- 画像评估不能只看命中率，必须单列失效记忆复用率。
- 推荐侧需要读取当前有效记忆投影，而不是历史全部事实。
- 删除、修订和替代应生成可测事件。

#### 可治理个性化

论文：`From Hidden Profiles to Governable Personalization`

公开信息：

- LLM 助手正在改变用户画像在哪里产生、向谁暴露以及如何被使用。
- 提出从隐藏平台画像转向可检查、可修订、可携带、可追责的个人化系统。
- 关注透明且保护隐私的用户建模、意图翻译、跨域记忆、可信商业化和访问责任。

【论文】

判断：

- 个人知识库不应成为不可见平台画像的复制品。
- 用户应能查看、纠正、导出、迁移和撤回关键画像结论。
- 访问责任、收益边界和审计记录应进入画像协议，而非事后补丁。

#### EPIC

论文：`From Volume to Value: Preference-Aligned Memory Construction for On-Device RAG`

公开信息：

- 端侧个人信息代理的内存预算很紧，核心问题是取舍存储内容。
- EPIC 优先保留偏好相关信息，并把检索对齐到偏好上下文。
- 四项基准中索引内存降低 2404 倍，偏好遵循准确率提升 18.79 个百分点，检索延迟降低 32.17 倍。
- 端侧三个平台内存低于 1MB，单次查询延迟 5.21 到 29.35ms，并支持偏好漂移下的流式更新。

【论文】【端侧实验】

判断：

- 手机知识库应优先保存可复用偏好和证据摘要，不应默认索引全部原始内容。
- Rust 端侧服务适合维护压缩索引、授权过滤和流式更新。
- 需要单独评估哪些非偏好原始资料必须保留，不能以压缩收益牺牲用户可追溯性。

#### LION

论文：`Self-Evolving Memory for Generative Recommendation`

公开信息：

- 直接持续更新共享生成模型会引发演化冲突。
- 不同用户的偏好变化在同一参数空间竞争，主导行为逐步覆盖弱势模式。
- LION 使用稀疏键值记忆隔离不同行为模式的演化，并用整合损失强化弱势偏好动态。

【论文】

判断：

- 用户偏好持续演化时，优先更新隔离记忆，不应频繁重训共享模型。
- 稀疏键值记忆适合承接长尾和少数兴趣，减少遗忘。
- 需监控不同人群的演化遗忘差异，避免全局指标掩盖弱势兴趣退化。

#### AgentWebRec

论文：`AgentWebRec: Compact Evidence Fusion over the Agent Web for Personalized Recommendation`

公开信息：

- 个人智能体之间形成用户、智能体网络和平台的新信息通路。
- 证据分散在互不透明的智能体中，只能通过有限查询获取。
- AgentWebRec 在有限证据预算下决定问什么、保留什么，并保持底层记忆本地。
- 仅当本地证据不足时，才条件化查询相邻用户智能体。

【论文】

判断：

- 跨用户协同不一定需要集中上传个人知识库。
- 可用局部证据加有限联邦查询替代全量画像汇总。
- 需要严格审计查询目的、最小化返回内容并防止成员推断。

#### Persona Learning from Feedback

论文：`Persona Learning from Feedback for Personalized AI Assistants`

公开信息：

- 人格描述本身不能告诉模型应改变什么、保留什么，也无法覆盖当前请求差异。
- PLF 把可复用偏好人格训练为共享冻结骨干上的独立 LoRA 适配器。
- 使用反馈门控把修正更新集中在需要改进的回答。
- 部署时由监督路由按请求或对话选择单个适配器或固定组合，无需用户级微调。

【论文】

判断：

- 人格画像适合表达为可组合行为适配器，而不是一段静态长提示词。
- 反馈应驱动“如何回应”，不能直接改写长期事实画像。
- 适配器路由必须可解释、可回滚，并监控通用能力退化。

#### 主动购买边界

论文：`Preference Is Not Permission: Personalizing the Auto-Purchase Line in Agentic Commerce`

公开信息：

- 商品适合度不等于已获得行动授权。
- 是否可自动购买依赖证据充分性、可逆性、价格相对于用户常态和紧急度。
- 输出应是三值状态：不购买、先确认、自动购买。
- 模型普遍越权承诺；仅几十条用户标签训练的浅层模型即可较稳定预测个人授权边界，且边界不跨域迁移。

【论文】

判断：

- 偏好画像与权限画像必须分离。
- 推荐系统可预测用户喜欢什么，不能据此推断用户可以替其执行什么。
- 购买、删除、发布和外部通信都应建立独立授权边界。

#### Heirloom

论文：`Heirloom: Carrying a Phone's Personalization Across Base-Model Generations`

公开信息：

- 手机端个性化适配器可能因基础模型升级而失效。
- 直接换成非个性化适配器会丢失大量个性化，重新训练又需要保留历史标签。
- Heirloom 用旧个性化模型作为教师，在无标签保存输入、厂商提示或新模型生成提示上迁移适配器。
- 迁移时始终只保留一个基础模型在内存中。
- 三次模型升级中，电影标签准确率与升级前持平，与有标签重训差距不超过 1.7 个百分点。
- 4B 模型在手机 NPU 上迁移约 38 分钟，端到端耗电约 20%，适合夜间充电执行。

【论文】

判断：

- 手机个人知识库应保存可迁移的画像证据和适配器，而不是把个性化锁死在某个模型版本。
- 迁移可以在本地完成，但必须有充电、温度、剩余存储和用户授权门禁。
- 原始标签不长期保留时，旧模型预测可作为蒸馏桥梁。

#### MemRevise

论文：`MemRevise: A Self-Revising Memory for Conversational Search`

公开信息：

- 用户会纠正误解、修改需求和返回旧主题，历史内容并非永久有效。
- MemRevise 使用可修订记忆图，记录每个主题的添加、放弃和重新激活操作。
- 被放弃主题保留事实，但状态标记为不当前生效，之后可以恢复。
- 在冻结检索器下，MRR@10 达到 0.701，最强对照为 0.589。

【论文】

判断：

- 长期画像应采用“保留事实、改变状态”，而不是物理删除或永久强压。
- 主题状态应具备添加、暂停、恢复、替换和过期。
- 推荐请求只使用当前有效投影，历史事实仍可审计和恢复。

#### PCDR

论文：`RALI@iKAT 2026: Retrieval-aware User Profile Denoising via Personalized Conversational Dense Retrieval`

公开信息：

- 用户画像随时间累积必然包含噪声和不再相关的信息。
- 先改写查询再检索，会把画像去噪压缩为稀疏词选择，和下游相关性脱节。
- PCDR 将对话历史和用户画像联合投影到检索专用潜空间。
- 只需少量个性化相关性标注即可训练。

【论文】

判断：

- 画像不是越完整越好，应与当前检索目标联合去噪。
- 画像投影的监督目标应是下游相关性，而不是摘要文本相似度。
- 对手机知识库，可保留完整原始事实，只对请求投影做去噪。

#### 偏好不确定性

论文：`Adaptive Personalization Under Preference Epistemic Uncertainty`

公开信息：

- 偏好可能继续保持、因上下文变化而变得不确定、或被用户明确修改。
- 人类研究确认，用户希望系统随偏好不确定性改变响应策略。
- 多语言基准覆盖 250 个人格、5 种语言和 2.5 万轮对话。
- 八个模型能识别合适策略，但在开放生成时策略校准下降 35% 到 46%。
- 模型系统性偏向“利用既有偏好”，忽略偏好的不确定性。
- 提示词干预无效，监督内部策略表示的训练可把分布外用户可接受度差距缩小三分之一。

【论文】

判断：

- 推荐系统需要显式区分稳定偏好、临时状态和未知偏好。
- 不确定性高时应探索、澄清或使用保守默认，而不是强行利用旧画像。
- 该状态应进入模型监督和决策接口，不能只在提示词中说明。

#### 人格是状态

论文：`Personas Are Not People: Identity as State, Not Attribute`

公开信息：

- 合成用户系统通常假设身份是固定属性，但人格研究显示行为跨情境变化大于人与人的差异。
- 行为可拆成稳定特质、情境激活身份和情境本身。
- 论文证明，任意固定人格模拟都无法复现人口行为中由其情境决定的部分。
- 在 Reddit 人格语料和临床试验招募调查中，情境人格仍不能完全匹配真实群体。

【论文】

判断：

- 用户画像不能只存固定标签，必须包含情境触发的身份状态。
- 冷启动模拟不能替代真实用户试验，尤其不能代表高度受情境影响的群体。
- 真实用户行为日志应优先于合成人格，用于长期偏好评估。

#### 记忆捷径与标注有效性

论文：

- `When the Text Is Silent: Memory Shortcuts and the Validity of LLM Annotation under Evidence Insufficiency`
- `The Right Source Is Not Enough`

公开信息：

- 文本没有证据时，模型会用自身已记住的知识补全，导致标注事实正确但方法无效。
- 激励和评估设置会进一步放大记忆捷径；名字提示和名字遮蔽可消除捷径，但会影响部分属性标注。
- 语音记忆实验中，即使检索到了目标事件，无关历史音频仍会改变答案。
- 错误不是单纯上下文过长造成，历史值会把答案推向特定竞争选项；来源角色正确也不够。

【论文】

判断：

- 画像与兴趣标注必须加入证据缺失和证据冲突测试。
- 只证明“检索到了正确来源”不足以证明系统正确使用了来源。
- 隐私敏感标注应优先使用本地证据，并要求模型在证据不足时弃权。

#### 量化审计对齐部署精度

论文：`Audit at the Precision You Deploy: Quantization Reshapes a Subliminally Learned Preference`

公开信息：

- 同一模型在 8 位下行为较稳定，但 4 位量化会因量化器不同显著放大或抑制隐藏偏好。
- HQQ 把植入偏好净强度放大约 1.3 倍，NF4 则压低到约 0.3 倍，尽管两者舍入误差规模接近。
- 仅是重新排列量化误差，就能使偏好净强度在 0.2 到 1.6 倍之间变化。

【论文】

判断：

- 画像、安全和内容偏好审计必须在实际部署量化权重上进行。
- 训练精度通过不能代表部署精度安全。
- 每次量化器、精度或权重版本变化都需要重新跑偏好和安全回归。

#### 记忆评估风险

论文：

- `The Geometry of Agent Memory`
- `Learning to Remember: Advances in Memory Mechanisms for Large Language Models`

公开信息：

- 记忆文本与查询的几何接近度不能可靠验证事实覆盖。
- 几何特征在 LongMemEval-small 的 pooled AUROC 为 0.640，低于问题难度基线 0.655。
- 控制难度和系统身份后，几何特征未显示稳定增益。
- 记忆综述把生命周期拆成构建、维护、检索、整合、遗忘、治理和评估。

【论文】

判断：

- 向量距离只应作为召回信号，不能作为“记忆足以回答问题”的判据。
- 画像与记忆必须单独评估事实覆盖、冲突、过期、删除和引用完整性。

## 五、面向三低的建议架构

### 5.1 在线请求链路

```text
客户端请求
-> 鉴权和网络状态
-> 读取短期会话状态
-> 并行发起：
   多模态向量召回
   生成式语义 ID 召回
   协同召回
   图谱和规则召回
   新鲜内容召回
-> 合并、去重、频率控制
-> 轻量预排序
-> 大排序或列表生成
-> 多目标融合、多样性和安全约束
-> 返回播放计划、预加载策略和降级候选
```

### 5.2 离线与近线链路

```text
原始事件和授权资料
-> 清洗、去重、时间对齐
-> 事实抽取和证据写入
-> 短期画像更新
-> 长期画像增量更新
-> 个人知识图谱更新
-> 多模态内容向量更新
-> 检索索引和缓存发布
```

### 5.3 Rust 的边界

适合 Rust：

- 召回、融合、特征读取和排序调度。
- 语义 ID、向量索引和缓存访问。
- 在线画像检索和授权投影。
- 推荐日志、反馈事件和状态机。
- 媒体分片、缓存、传输和低延迟网络路径。
- 推理运行时接口和资源隔离。

暂不建议只用 Rust：

- 大规模模型训练。
- GPU 分布式训练及实验生态。
- 依赖 PyTorch、TensorFlow 或最新论文实现的快速验证。

建议：

- 在线控制面和数据面使用 Rust。
- 训练面保持可替换，可继续使用 Python 生态。
- 模型通过 ONNX、TensorRT 或独立推理服务接入。
- 推荐状态、授权、证据和恢复逻辑不依赖某个训练框架。

### 5.4 分阶段建议

#### 阶段一：可测基线

- 多路召回。
- RankMixer 式高效排序。
- HEGM 或 PTPM 观看时长头。
- 短期状态、长期画像和知识图谱检索服务。
- 全链路延迟、MFU、带宽、缓存和反馈埋点。

#### 阶段二：长序列与冷启动

- 引入 HSTU、MTGR 或 Mamba4Rec 的长序列编码。
- 引入多模态向量和语义 ID。
- 用 PersonaX 式离线画像替换在线实时画像生成。
- 对高价值场景启用列表级重排。

#### 阶段三：生成式与持续对齐

- 灰度测试 SnapLGR 式生成召回。
- 灰度测试 LIGE-GR 式列表生成。
- 评估 OneRec-V2 式端到端生成是否具备足够数据、算力和回滚能力。
- 使用在线反馈做偏好对齐，但保留规则、安全和授权边界。

### 5.5 采用分层

#### 已具备生产证据，优先试点

- 多路召回。
- HSTU、MTGR、Douyin 10K、ECHO、MuSeR 式长序列。
- RankMixer 式高 MFU 排序。
- HEGM、PTPM、FlowTime 式时长分布预测。
- OneTrans-GSR、HiGR、LIGE-GR 式列表生成。
- SPW-Gate 式选择性画像写入。
- TokenMinds、RECAP 式有界用户表示。
- SILC 式前瞻缓存和 FLAME/FP8 服务优化。
- AgentMemRec 式记忆推荐化选择。
- SID 拓扑保持和追加式更新。
- OneShot 式索引与排序联合学习。
- FLVM、UAME 式偏好测量与满意度不确定性治理。
- ROCS 式请求级计算共享。
- DADF 式时长回归残差纠偏。
- Inherit4Rec 式参数继承扩容。
- PRISM 式个性化历史物品表示。
- MOSS 式生产语义监控和 Instagram 基线增量去偏。
- WeGR 式行为感知语义 ID 与偏好对齐。
- UAGR 式效用增强语义码和效用引导解码。
- SparseLift 式稀疏训练路径优化。
- RecIS 式稀疏稠密统一训练。
- Memory Layer 式训练服务统一物品缓存。
- SequenceO1 式十万级历史压缩与低秩缓存。
- PSG 式成对列表生成。

#### 有明确价值，但需要真实流量验证

- OneMall、TGR、TransX 式多场景统一。
- SnapLGR、ZeroGR、ReuseGR 式生成召回。
- SPAR、PIT、AdaSID 式语义 ID 生命周期。
- KITE、EvoMemState、StateGraph 式长期记忆治理。
- HARP、PersonaX 式双向画像与离线画像检索。
- CAPE 式长尾共现恢复和 NAU 式邻域感知遗忘。
- Deco、OneLatent 式读写解耦和潜空间推理。
- Heirloom 式手机画像跨模型迁移。
- NEXT 式下一意图视觉推理召回。
- 画像路由门控、MATE 双时间尺度记忆。
- Gated Memory、EPIC、LION 式画像形成与演化。
- EASQ 式问卷满意度在线对齐。
- VCG 式判别多模态冷启动召回。
- BehaviorMem、ETAMem、ReMind 式多视图记忆。
- Persona Learning from Feedback 式行为适配器路由。
- CGM-Rec、OMEGA、LoopMemGR、AtomRec 式生成推荐外部记忆。
- TIDE 式延迟反馈驱动的记忆演化。
- OMCE 式经验调用元控制与 ResMem 检索知识固化。

#### 研究跟踪，不作为首期主依赖

- OneReason、S2GR 式生成式推理。
- Mamba4Rec 等缺少大规模生产证据的长序列结构。
- 合成人格画像。
- 直接删除或物理重写原始历史。
- 完全取消判别式召回和传统排序兜底。

### 5.6 三低选型矩阵

## 七、社区争议与失败模式

以下条目中，前四类有论文或工程结构支撑，最后一项保留为待复现的社区问题。

1. 生成式召回可能产生无效 ID、语义 ID 冲突和热门码本偏置。SnapLGR 的工程重点正是码本利用率、冲突和协同信号。
2. 端到端替换会造成组织、基础设施和回滚风险。LIGE-GR 明确选择从已有排序系统平滑升级。
3. 生成式模型不能天然替代交叉特征。MTGR 报告直接放弃传统交叉特征会显著降低性能。
4. 大模型不保证更高性价比。多模态推荐研究提示，模型更大不一定更好，差异主要取决于场景、稀疏度和阶段。
5. 社区经常把长序列效率等同于端到端低延迟，但真实瓶颈可能在特征读取、网络、索引、日志和排队。需要按请求分段测量，不能只看模型 FLOPs。
6. 用户画像的最大风险不是召回不足，而是错误事实、过期偏好和越权使用。画像必须支持证据、有效期、删除和冲突消解。
7. 2026 年的新工作开始修正早期生成式推荐的三个盲点：确定性 SID 不稳、列表生成约束不足、用户画像单侧且冻结。
8. Reddit 与部分聚合接口在维护时仍有限流，当前社区证据主要来自 GitHub 公开问题、论文反例和可核对的开源实现。中文技术社区尚未完成系统抽样。
9. 短视频生产研究同时证明：长历史收益依赖请求级复用和候选感知检索，盲目增加历史长度会先压垮延迟与存储。
10. LLM 画像不是普遍优于聚合画像。习惯型用户使用聚合画像更便宜也更准，探索型用户才更适合生成画像。
11. 观看时长优化存在测量偏差和内容深度退化，必须加入长期满意度、覆盖、新鲜度和心理负担约束。
12. 语言模型推荐不一定需要服务时语言模型推理。缺少同信息、同候选和同工具预算的恢复式基线，会把语言模型收益误判为核心机制收益。
13. 列表生成的瓶颈不只在线性复杂度和束宽，训练服务表示错位、物品缓存陈旧和页面感知脆弱同样会放大线上误差。
14. 推荐结果反馈延迟且混杂，无法归因到具体记忆时，不应直接强化长期用户画像。

### 8.2 已知社区问题

以下是开源仓库公开问题中可以直接验证的模式：

- Meta HSTU 仓库存在 Triton 版本兼容、Hopper 融合注意力、TMA 布局和性能分析问题。长序列高效率依赖具体 GPU、内核和依赖版本。
- Meta 仓库的公开代码并不完整覆盖论文所有生产设定。维护者说明部分代码只用于公开数据集或效率实验，不能把仓库直接等同于生产系统。
- Snap GRID 有 RQ-VAE 分层训练、私有数据接入、推理语义 ID 映射、碰撞处理和文档不足等公开问题。
- OpenOneRec 有复现结果低于论文、训练流程适配和个人数据微调问题。高价值结论仍需独立复现。
- 其他新论文仓库普遍存在代码新、样本少、许可证不明和缺少生产压力测试的问题。

### 8.3 判别式检索反例

论文：`The Case Against Generation for Retrieval: Discriminative Language Models as Effective Retrievers`

公开信息：

- 把 LLM 作为语义表示骨干，而不是生成引擎，保留经典双塔检索结构。
- 使用共享 LLM 编码器、句尾池化、跨数据蒸馏和用户塔潜空间推理。
- 在三个公开基准上，交叉编码器优于当前生成式最强基线；高效双塔学生达到接近水平。
- 在生产系统上取得显著检索提升，并对模型陈旧和数据规模扩展更稳健。

【论文】【工业部署】

判断：

- 生成式召回不是所有系统的默认最优解。
- 如果语义 ID 维护、约束解码、索引更新和延迟成本过高，LLM 语义双塔可能是更低风险选择。
- 最合理方案是并行保留生成式和判别式双路召回，用在线收益决定权重。

### 8.4 个人化声明审计

论文：`Is Personalized Modality Weighting Actually Personalized?`

公开信息：

- 三个独立短视频语料审计用户级模态权重。
- 单一全局模态权重已经获得几乎全部收益。
- 逐用户权重没有稳定增加效果，少数正收益很小且跨数据集翻转。
- 部分实验中的所谓个性化增益来自门控读取共享协同嵌入，而非真实用户差异。

【论文】

判断：

- 任何用户级画像或门控都需要对照全局参数和打乱绑定基线。
- 不能只用离线提升证明个性化成立。
- 推荐服务应记录真实个性化收益和混杂容量收益。

## 九、待验证问题

- 在 100 万安卓装机规模下，生成式召回是否达到正收益。
- 手机全信息知识库的哪些事实可进入推荐画像，哪些必须只留在本地。
- 每条画像的授权粒度、有效期和撤销传播延迟。
- 语义 ID 的码本规模、冲突率和冷启动覆盖率。
- 长序列压缩率和排序效果在真实数据集上的曲线。
- 列表级生成的 P99 延迟、回滚成本和异常内容风险。
- 多目标融合中的用户幸福感、内容多样性和平台收益是否存在长期冲突。
- TransX 式预填充、近线刷新和在线融合在自有硬件上的成本曲线。
- 语义 ID 从全局 ID 迁移到个性化 ID 时的回滚损失。
- 选择性画像写入对长期留存和冷启动探索的真实影响。
- 全局模态权重是否已经足够，用户级门控是否值得额外复杂度。
- 生成式召回与 LLM 语义双塔并存时的最佳流量配比。
- CAPE 共现补池在未来兴趣和短视频长尾作者上的收益。
- SID 追加式更新在数周连续新增物品后的拓扑漂移。
- Deco 概念压缩对新兴兴趣、长尾内容和多语义视频的损失。
- AgentMemRec 式记忆选择在个人知识库隐私边界内的可用范围。
- Heirloom 式画像适配器迁移在非充电、低电量设备上的降级策略。
- OneShot 式联合索引在目录高频更新时的重建成本。
- NEXT 式视觉意图召回对系列内容和开放式兴趣的外推能力。
- UAME 与 FLVM 的潜在满意度和问卷结果长期是否一致。
- 画像路由门控在新用户、低频用户和跨语言用户上的误判率。
- Gated Memory 与 EPIC 对删除请求和偏好漂移的端到端传播延迟。
- ROCS 在自有请求分布和 Rust 服务框架中的实际 QPS 曲线。
- DADF 纠偏专家在跨语言、跨时长和跨设备上的稳定性。
- Inherit4Rec 扩容后对旧兴趣和长尾能力的遗忘幅度。
- EASQ 问卷稀疏反馈是否会放大特定活跃人群偏好。
- VCG 与生成式语义嵌入在不同冷启动阶段的组合边界。
- RGCD-Rep 跨域迁移是否会把短视频短期兴趣污染到直播长期画像。
- PRISM 个性化历史表示在用户长期兴趣和生产延迟上的稳定性。
- MOSS 语义监控在自有内容审核标准下的误报率和漏报率。
- 单头束搜索与多 token 预测在不同 SID 深度下的成本拐点。
- WeGR 行为协同语义 ID 在短视频长尾内容上的泛化。
- LoopRec 自适应递归在请求内预算紧张时的降级策略。
- ReMind 递归记忆排序是否会过度扩大上下文并增加冲突。
- 主动记忆召回随用户知识库规模增长后的误打扰率。
- Preference Is Not Permission 三值授权边界在不同应用域的迁移。
- 多轮语义缓存错误复用对推荐解释和画像助手的影响。
- UAGR 效用权重在观看时长、完播和满意度之间的稳定性。
- SparseLift 在图结构频繁变化时的计划失效和重编译成本。
- DeepMem 分尺度压缩在多模态视频历史中的语义保真。
- OMCE 元控制是否会把短期任务反馈误固化为长期画像。
- 部署量化后的模型是否改变内容偏好和安全边界。
- RecIS 在自有稀疏特征分片和网络拓扑下的吞吐收益。
- Memory Layer 在短视频多场景目录中的缓存一致性、回滚和删除传播。
- SequenceO1 十万历史压缩在长尾兴趣和突发兴趣上的召回损失。
- PSG 成对生成对列表顺序、业务约束和反事实表达力的影响。
- GRACE 广告资格过滤在规则频繁变化时的重建成本。
- LIME-Rec 与 DART-Rec 在同规模生产候选和工具预算下能否复现。
- CGM-Rec 只写记忆的适应策略是否会在数月后累积噪声。
- TIDE 责任信用分配在多人格、多场景和多设备画像下的准确性。

## 十一、维护规则

新增候选时必须记录：

1. 论文或官方来源。
2. 是否进入生产流量。
3. 线上基线、实验周期和指标。
4. 延迟、显存、训练成本和回滚方式。
5. 与现有 Rust 在线面的接口。
6. 对用户知识库的读取边界。
7. 新增代偿约束和可能副作用。
8. 不能复现的结论必须标注。
