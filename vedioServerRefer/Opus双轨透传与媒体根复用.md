## HMM边界与选择

S0：实时视频、权限与分配已闭合，直播没有音频；增加独立音频平台会引入第二套会话与生命周期。
IFR：客户端产生合适的音频，服务器低成本分发，退出或失权时音视频共同结束。
Sg：复用已有str0m，为原Rtc加入一条可选Opus音频，视频保持单轨和原编码限制。

E：发布者、观看者、媒体线程、权限发行者和房间控制面。
A：源轨道、解码能力、MID、媒体时基、授权期限、缓冲和发送资源。
F：有效音视频到达观看者；有害功能为无声、旧音频越权、视频阻塞音频及无界排队。
C：各端实现Opus RTP及轨道协商，源音频单声道，房间有必需视频，仍处在可信回环实验环境。

TC：补音频提高直播完整性，但增加排队、协商、发送与同步代价。
PC：音视频必须共享会话生命周期，又需要互相独立的轨道与缓冲资源。
操作子为整体/部分分离：一份凭据、Rtc和资源管理音视频，
各轨独立MID和有界队列，共同由原媒体线程执行。

本轮三个问题：

1. 双轨透传、解码证明和共同生命周期：本轮实施验证。
2. 原生音频会话、真实语音、弱网与时钟同步：开放。
3. 多码率/录制、推荐预取和总体三低：开放。

| 候选 | 本轮取舍 |
| --- | --- |
| 既有str0m Opus及帧级Writer | 选择，已在同一Rust内核提供协议与发送能力 |
| 视频保持无音频 | 保留单轨回归，但不能满足有声直播 |
| 独立音频/混音/转码进程 | 不选，当前没有混音/转码需求，新增生命周期和计算成本 |
| 另加完整媒体平台 | 保留未来评估，当前根可以完成这一有界子问题 |

这是当前约束下的实施根，不是生产跨候选性能最强结论。
没有把成熟项目的全部平台能力或性能宣传算成本项目成果。

- Writer的参数映射、编码数据发送；
- 官方chat示例的轨道/媒体分流机制。

不复制Opus编解码器、不手写RTP封包、不启动上游完整平台。

## 实施与代偿

原会话从固定一个媒体节扩展为必需单视频、可选单音频，媒体节顺序不限。
发布者带音频时可接受双轨或只看视频的订阅；
没有音频源时拒绝双轨订阅，不创造虚假音频。
SDP answer逐节标记end-of-candidates，仍不提供Trickle、ICE重启或在线加轨。

转发按视频与音频各自MID匹配源与订阅者，不复用源MID定位另一会话。
原视频统计保留，新增音频包、字节、丢弃与峰值统计。
视频队列8帧，音频另16包，音频满时舍弃旧包，视频满时丢新帧并请求关键帧。
每轮先排音频再排视频，有限缓冲防止视频挤占所有音频槽位；
不声称这个实验规则是所有负载下最优的调度。

音频入队上限最终为1KiB。上游OpusPacketizer按MTU切分大数据，
但Opus RTP包不能任意当作视频分片；4KiB初版逻辑预算因此被收窄。
固定上游默认MTU及SRTP预算另读源文件确认，1KiB降低通用大包覆盖，
换取当前默认封包路径不会任意拆分Opus包。
改变MTU、扩展、编码或上游版本需要重新验证，不能只增加缓冲上限。

没有解码、混音或服务端转码，编码数据Arc共享；
每观看者仍独立SRTP与发送。RTP时间与talkspurt保留，
用接收时间作为转发墙钟，没有实现发送端绝对时间/漂移校准；
因此不能从双轨成功推出严格音画同步。

契约见[live-opus-profile-v1](../vedioServer/contracts/live-opus-profile-v1.md)。

## 验证与反例

39项定向Rust函数：媒体库20、媒体HTTP15、协调4；
上游存储Suite仍计一个函数。覆盖音频参数、音频/视频顺序、
纯音频/重复轨拒绝、无音频源拒绝、视频单轨兼容、
不同音频PT、两路队列压力与大包边界、双媒体节HTTP和原权限生命周期。
全工作区all-targets Clippy以-D warnings通过。

浏览器实验使用440Hz合成音源，不调用用户麦克风，不输出到扬声器。
有效音频必须有实际audio/opus RTP、接收采样和非零PCM波形，
频率峰值接近440Hz，且视频保持640×360变化画面。
撤权/排空后检查音频收包/提交转发停止，未撤观看者的音频继续。

首轮h264-opus-initial未通过最终验收，不能计为成功：
Chrome的totalAudioEnergy为0，但实际PCM约0.071 RMS、频率峰值445.3125Hz，
媒体与音频包已正常收发；它是未传播音量元数据的统计边界。
验收改以实际解码采样、PCM幅度与频谱为依据，继续保留原能量字段，
没有伪造或抬高该值，也没有声称音量元数据已接入。
初轮失败及后续同二进制成功回执均保留；最终1KiB/无音频RTX边界另以新二进制完整验证。

最终同二进制三组实验通过：

| 场景 | 实测 |
| --- | --- |
| H.264＋Opus | 两观看端采样时已解码71520/53280个音频采样，PCM RMS约0.0706/0.0711，峰值445.3125Hz |
| 同时视频 | H.264两观看者已有35/11帧解码，640×360且变化像素通过 |
| VP8＋Opus | 两观看者已有69600/51360音频采样，同样波形/频谱通过，视频持续 |
| 原视频单轨 | 同一二进制VP8完整交接通过，音频接收/转发均0 |
| 续权 | H.264双轨原连接跨63.415秒，观看者音频波形仍非零 |
| 撤权/排空 | 被撤观看者音频停包，其他音频继续；发布者撤权、到期与排空后停止提交音频 |
| 交接 | A排空后B重新协商双轨，B失联仍阻止释放/重分配 |

上述是本机合成取样，不是音质、实时性或不同编码的效率比较。
