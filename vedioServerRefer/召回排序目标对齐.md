# 召回排序目标对齐

日期：2026-11-06。历史结论：混合兴趣与纯负兴趣中性遗漏已修复，Qdrant 同分校验仍失败。
后续可选本地分组后端已保留当前标签基线的全量排序前缀，见 [分组召回评估](分组召回评估.md)；
下述表格和中性路由收据保留为历史，不能作为生产质量或分布式准入。

<重表述提示词为问题>在个人候选 128、场景先验 64 的预算内，如何让召回保留最终排序所需候选，同时控制请求计算、传输和等待成本？</重表述提示词为问题>

## 问题与取舍

`S0`：索引查询只计算正兴趣，最终排序计算全部兴趣的标签均值。因此，同时包含喜欢和不喜欢
标签的内容会在召回阶段占用预算，最终更高分的内容可能根本没有进入排序。

`IFR`：只传输、计算影响最终结果的候选，不通过增加预算掩盖目标错位。
本轮 `Sg` 是可选带符号召回、独立反例和可复算测量，尚不是生产无损替代。

作用链是：画像权重 → 索引查询 → 截断候选 → 统一排序 → 结果。隐含条件是“召回次序近似最终
排序次序”；只对齐正兴趣会破坏这个条件。付费与决策方承担资源开销，使用者承担内容遗漏和等待，
评估者用固定时间切分和逐请求门禁检查，单一候选数量指标不能覆盖这些代价。

技术矛盾是减少排序候选可能损失正标签。参数矛盾是同一候选集合既要小，又要包含所有会影响
结果的内容。本轮先复用现有索引，在条件上区分正向和带符号评分，不扩展候选预算。
代偿约束是负权查询可能增加倒排遍历，且分数相同及零分候选仍有结构性缺口。

## 已实现

- `RecallScoring::Positive/Signed`；线上通过 `VS_QDRANT_SCORING=positive|signed` 选择。
- 默认仍为 `positive`；不配置 Qdrant 时继续全量排序。
- 带符号查询保留非零正负兴趣，候选向量继续使用标签数归一化。
- 远端显式过滤非正分，避免纯负兴趣返回被扣分候选却仍遗漏中性候选的额外传输。
- 场景、隐藏和拒绝标签过滤仍在请求和最终合并两侧执行。
- 带符号成功响应使用 `x-recall-mode: qdrant-signed-tags+prior`，故障仍为 `prior-degraded`。
- 回放支持五种模式、独立机制校验集、1–32 次逐请求重复测量。
- 任一样本发生 Recall、NDCG 或 MRR 退化，该请求门禁即失败；每次的指标均保留。
- 报告升级为 `recommendation-replay-report-v2`；脚本核验版本和样本数量，拒绝旧二进制结果。

没有改变目录格式或索引向量，因此切换评分不需要重建相同目录的集合。

两条剩余失败：

1. 纯负兴趣：稀疏查询不匹配中性内容；高先验负候选填满先验预算，零分内容仍可能遗漏。
2. 大量同分：超过 128 个候选具有同样亲和度，索引截断不使用最终排序的先验与稳定 ID。
   被裁掉的高先验候选无法由后续排序恢复。不能用先验乘一个随意小常数解决，否则会改变近分排序。

## 成本边界

固定上游提交 `222b2e44ab1c3f17e8246396ead6558e45041df7` 的
`lib/sparse/src/index/search_context.rs:70` 明确说明：查询含负值时不能使用当前依赖
`max_next_weight` 的剪枝。本轮通过固定本地克隆和官方原始源码复核，没有修改索引内核。

最终诊断集 `mixed-video` 的 16 个本机调试构建样本中，带符号召回含先验与 RPC 的中位耗时为
974 微秒，子集排序为 67 微秒；进程内全量排序为 108 微秒。此处远端调用成本高于减少排序的收益，
因此不能用排序候选下降宣称端到端低延迟。

逐请求保留 P50/P95/P99 最近秩统计；16 个样本的 P95/P99 都取最大值，不能估计线上尾延迟。
测量复用连接池，包含首次连接，没有独立预热；没有隔离整机负载，没有测服务器 CPU、RSS、
完整 HTTP、并发排队或真实网络字节。不同阶段和不同目录的计时不能直接相减归因为负权剪枝成本。

## 中性候选续验

<重表述提示词为问题>当所有兴趣权重非正时，如何在原有 64 个先验预算内优先保留零分内容，并省去不可能产生正分的远端查询？</重表述提示词为问题>

`S0`：负兴趣稀疏查询不能取回不匹配的中性内容，先验又可能被高先验负分内容填满。
`IFR`：有用中性内容自然进入候选，不为无结果的远端检索付费。
本轮 `Sg`：仅在 `signed` 且全部兴趣非正并至少一个为负时，先选中性先验，再按原场景轮询
补负分，跳过索引请求。条件来自非负候选向量与非正查询权重的点积必不为正，与具体候选 ID 无关。

没有新增候选预算、索引、数据库或配置开关。默认 `positive` 的先验策略保持原样；空画像、
全零兴趣、混合正负兴趣不进入新条件路。软负反馈仍不作为硬过滤。公开数据、授权投影、
场景、隐藏和拒绝标签边界不变。

排序与先验共同使用 `RequestContext::affinity`；空标签和极小权重可能产生 `-0.0`，已将数值零
统一为 `+0.0`，使所有中性结果按先验和稳定 ID 决定次序。该基础排序修复适用于各召回模式，
有单独的空标签、未知标签和显式负零回归验证。

响应头 `prior-nonpositive` 表示命中此条件路。报告和运行收据升级为 v3，增加：

- `prior_examined`：本地先验每次实际检查的候选，重复检查也计数。
- `neutral_prior`：是否使用中性优先。
- `remote_query_issued`：本次是否实际进入远端查询调用；逐样本保存。

输入目录与轨迹的 SHA-256 与上一轮一致，未改诊断集或独立校验标签。每请求仍测 16 次：

| 请求或范围 | 上轮带符号退化 | 本轮带符号退化 | 本轮索引调用 |
| --- | ---: | ---: | ---: |
| 原诊断集 | 0 | 0 | 依请求而定 |
| 独立混合兴趣 | 0 | 0 | 16 |
| 独立纯负兴趣 | 16 | 0 | 0 |
| 独立同分截断 | 16 | 16 | 16 |

独立纯负兴趣请求每次都保留了全量 Top-10，排序候选仍为 64 个；真实 Qdrant 所在实验中的
该请求没有发起 RPC。HTTP 协议夹具额外核对了零索引请求与 `prior-nonpositive` 响应头。
独立校验总退化从 2 条降为 1 条，完整门禁仍退出 2。
本地带符号精确对照的宏平均 Recall 从 1/3 升至 2/3；真实索引的同分边界仍不稳定，不以其
跨集合的同分命中差值估计本轮收益。

代偿成本必须保留：该请求扫描了 320 次候选，先前普通先验只检查 64 次。中性遍历可以扫描
所有所请求场景，补负分再扫描一次；最坏是这些场景候选数的两倍检查，标签均值计算也有成本。
本轮该请求先验与合并的 P50 为 89 微秒，子集排序为 45 微秒，全量排序为 120 微秒，
三个数是各阶段独立中位数，不能相加当作端到端请求中位数。没有测网络字节、服务器 CPU/RSS
或生产负载，跳过一个 RPC 不足以推出总计算量或用户等待时间下降。

仍未覆盖的失败空间：多场景轮询可能漏掉全局更高先验的中性内容；补位负分依旧按先验取候选，
不保证保留所有较少负分的内容；混合兴趣下的零分候选也尚未建立完整性保证。
因此“修复一类已验证遗漏”与“纯负兴趣全量等价”严格分开。

验证为 66 项全目标测试通过，含真实索引合约；Clippy 零警告、fmt 通过。CLI 验证诊断退出 0、
独立机制退出 2、非法测量次数退出 1 且无部分报告。所有本轮实验进程已退出。
