日期：2026-11-06。状态：本地实验路径通过质量门禁，生产准入未完成。
后续 release [成本矩阵](召回成本矩阵.md) 已发现高组数场景速度退化；下文调试计时保留为历史，
不用于默认后端或自动切换阈值。
再续已经将 Qdrant 缓冲 Top-K 复制改造成大组数选择器，详见
[上游TopK复用评估](上游TopK复用评估.md)；当前不再保留所有组头，索引成员布局尚未改变。

<重表述提示词为问题>在不把同分候选提前交给远端稀疏索引截断的情况下，能否复用完整目录中的共同标签亲和度，并按最终排序键取得固定数量候选？</重表述提示词为问题>

## 路径

本轮实现 `GroupedRecall`，作为与 `catalog`、`qdrant` 互斥的可选后端：

```text
目录快照
  -> (domain, ordered_tags) 分组
  -> 组内按 prior、id 排序
  -> 每组只计算一次标签亲和度
  -> 多组有序头归并
  -> 取最多 128 个候选
  -> 复用统一最终排序
```

分组键保留标签原始顺序，避免改变浮点加法顺序。组内标签相同，因此亲和度相同；
被隐藏或拒绝的候选会在组内继续检查，不会因为组首项被过滤就丢弃整个组。

该操作把“候选分数排序”和“候选搬运”分开：它不依赖远端稀疏索引，也不新增画像权限。
现有 API 原本就持有完整目录，本次通过 `Arc` 复用它，新增分组成员索引和每请求堆头。
代偿约束是目录版本变更时需重建这些分组；生产内存、全流程构建成本、跨节点发布和热更新仍未测量。

## 质量结果

输入是同一独立机制校验集：864 个候选、860 个有效场景候选、3 个查询、每个查询 16 次重复。
没有修改历史事件、查询标签或目录指纹。

| 模式 | Recall@10 | NDCG@10 | MRR | 退化请求 | 排序候选总量 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 全量排序 | 1.000 | 1.000 | 1.000 | 0 | 860 |
| 本地正向参考 | 0.000 | 0.000 | 0.000 | 3 | 384 |
| 本地带符号参考 | 0.667 | 0.667 | 0.667 | 1 | 321 |
| 真实 Qdrant 带符号 | 0.667 | 0.667 | 0.667 | 1 | 321 |
| 本地分组归并 | 1.000 | 1.000 | 1.000 | 0 | 384 |

分组路径覆盖：

- 混合兴趣：无退化。
- 纯负兴趣：无退化，不依赖中性特殊分支。
- 大量同分候选：无退化，保留最终 `prior -> id` 次序。
- 16 次重复中，三条请求均稳定得到相同结果。

这里的“排序候选总量”是回放中实际进入最终排序的候选总量，不等于完整目录扫描次数；
分组索引已经在请求外构建，单次查询仍需检查可见候选组头和候选边界。

## 成本观测

独立校验集的分组索引包含 864 个候选、10 个分组，最终运行构建约 1179 微秒。三条请求都
遍历 10 个组、对允许的 2 个组打分；组内候选可见性检查量为 128、128、129，
选择阶段中位耗时分别约为 19、17、31 微秒；子集排序中位耗时约为 100、76、83 微秒。
全量排序中位耗时约为 152、110、191 微秒。

这些是本机调试构建、16 次重复的局部计时，不含 HTTP 端到端、并发排队、内存峰值、目录发布、
节点间复制和真实网络。不能据此宣布生产 P95/P99、CPU/RSS 或三低收益。
各阶段独立中位数不能相加当作端到端中位数。复用率下降时，组数可能接近候选数，堆头和
分组索引会增加内存且不再节省多少打分，需通过规模与分组率矩阵确定边界。

分组路径的关键成本转移：

```text
请求内重复标签计算       -> 目录发布/索引构建时一次分组
远端召回网络等待         -> 本地组头归并
同分边界不确定           -> 本地稳定排序键
副本独立计算             -> 需要版本化目录发布和索引重建
```


`x-recall-mode: grouped-tags`，`/v1/metrics` 暴露 `recall_backend`、`grouped_queries`、

## HMM 取舍

`S0` 是远端稀疏召回的候选截断先于最终排序，导致同分边界和次排序信息丢失。
`IFR` 是只做必要的亲和度计算并稳定取得最终排序前缀。

分组归并解决了当前已验证的同分反例，但它改变了代偿约束：

- 从远端检索成本转为本地分组成员索引与请求堆头的额外内存，完整目录常驻是既有前提。
- 从请求级网络等待转为目录版本发布与索引构建。
- 从分布式索引扩展转为 API 副本目录一致性。

因此当前决策是：保留并交付为可选实验后端，不切换默认，不称为生产推荐算法完成。
下一轮要验证目录规模、更新频率、多个 API 副本的索引内存、版本切换和故障恢复；
真实行为质量、画像撤销、媒体编码、存储修复和播放器 QoE 仍是独立问题。

66 项基础回归在本轮扩展为 73 项通过，包含真实 Qdrant 合约、分组核心、分组 HTTP、
互斥配置和扩大矩阵测试；Clippy 零警告、fmt 通过。

## 契约和来源

完整前缀成立的条件：同一不可变目录、当前标签均值评分、组内同场景及相同有序标签、
所有组均参与过滤、完整的亲和度/先验/ID 排序键，以及返回 K 不超过 128。
每组是全局排序的有序子序列，过滤后仍保持有序；标准库 `BinaryHeap` 持有每组当前可见头，
每次弹出最优头再推进该组，得到全局前缀。请求 K 当前最多 50，因此保留 128 个足够。
增加逐候选模型特征或改变评分规则时，必须重新审查分组键，不能沿用此等价结论。

本轮直接读取 Qdrant 官方混合查询文档并核对固定上游 REST 查询结构：主查询重排预取候选，
因此公式重排不能独自恢复预取前截掉的候选。边界补取可作为远端分支，但超大同分组可能使
传输量越过原预算，本轮未实现或宣称该分支通过。未修改 Qdrant 内核，归并复用 Rust 标准库。
