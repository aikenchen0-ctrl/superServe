# 视频与推荐算法选型

## 一、统一优化公式

视频和推荐必须一起优化，因为推荐决定需要哪些字节，媒体层决定这些字节如何传输。

```text
源站出口
= 播放次数
 x 单条必要字节
 x 过拉系数 O
 x 重试放大 R
 x (1 - 字节命中率 H)
```

推荐系统可以直接影响：

- 哪些内容被请求。
- 请求顺序和预取范围。
- 候选是否具有时效和地域集中度。
- 列表级生成是否产生无效曝光。

媒体系统负责：

- 必要字节和编码兼容性。
- 分片、Range、缓存和回源合并。
- 首片延迟和取消取流。
- 存储层级和生命周期。

## 二、视频算法

### 2.1 编码

| 场景 | 默认编码 | 回退 |
| --- | --- | --- |
| 新 Android 设备 | AV1 | HEVC、H.264 |
| 苹果和旧设备 | HEVC | H.264 |
| 屏幕内容 | AV1 加屏幕内容参数 | H.264 |
| 缩略图 | AVIF | WebP、JPEG |

编码规则：

- 使用上游稳定 SVT-AV1，不使用已停更的社区分支。
- 质量门禁以 SSIMULACRA2 为主。
- 使用 VMAF 时必须关闭 motion 分量。
- 短视频不做逐条 per-title 全片凸包。
- 按口播、剧情、游戏、风景和屏幕等内容类簇生成档位表。
- 能够降低分辨率时优先降低分辨率，再调整码率。

### 2.2 分片和播放

- 默认 CMAF 分片长度为 2 秒，按真实数据调整到 3 或 4 秒。
- 分片 URL 使用内容哈希，不把签名参数放入缓存键。
- 播放器只请求当前观看窗口和动态预取范围。
- 快速滑动立即取消媒体请求，停止后经过短暂 debounce 再起播。
- 缩略图独立于视频分片缓存，避免列表滚动触发视频字节。

### 2.3 动态预取

固定深度预加载默认关闭。算法化预取使用推荐输出和当前播放状态动态决定：

```text
预取范围
= f(预测观看时长分布, 当前缓冲, 网络状态, 下一候选顺序, 带宽预算)
```

第一阶段先使用规则：

```text
range = min(预测剩余观看时长 x 0.6, 2 个分片)
```

只有在数据规模、分片埋点和在线推理稳定后，才引入 DRL 或更复杂策略。每次预取
都必须能归因到具体列表项、会话和缓存键。

## 三、推荐算法

### 3.1 总体结构

推荐采用分层组合，不直接做端到端生成式替换：

```text
多模态内容理解
-> 多路召回
-> 轻量预排序
-> 长序列用户表示
-> 大排序或列表生成
-> 多目标融合、多样性和安全约束
-> 预取计划、反馈写入和下一轮更新
```

### 3.2 召回

第一阶段至少保留五路召回：

| 召回路 | 作用 | 冷启动价值 |
| --- | --- | --- |
| 多模态内容向量 | 理解画面、语音、文本和节奏 | 高 |
| 协同过滤 | 利用相似用户行为 | 中 |
| 语义 ID | 支持生成式和跨域迁移 | 高 |
| 知识图谱投影 | 使用授权的个人关系和主题 | 高，但需严格授权 |
| 新鲜内容和热门兜底 | 保证目录覆盖和系统可用 | 中 |

召回结果必须去重、限流、记录来源，并保留热门、长尾和新内容的配额。

### 3.3 长行为序列

首选路线是分层压缩、候选感知检索和请求级复用。

可选结构：

- HSTU 或 MTGR 风格：长序列转导，保留高价值交叉特征。
- Douyin 10K 风格：目标到历史交叉注意力和请求级批处理。
- ECHO 风格：终身行为的蒸馏选择器和候选感知检索。
- MuSeR 风格：近期全分辨率、历史分层压缩和多兴趣。
- TransX 风格：序列编码、行为记忆和候选融合拆开扩容。
- Mamba4Rec：线性序列模型，但生产证据少于上述路线。

不能把全部历史直接塞进注意力。在线序列接口必须支持预填充、近线刷新和请求级
复用，否则模型 FLOPs 下降不一定转化为端到端低延迟。

### 3.4 排序和列表生成

| 阶段 | 首选方向 | 目标 |
| --- | --- | --- |
| 排序 | RankMixer 风格 | 提高 MFU，扩大模型不增加尾延迟 |
| 观看时长 | HEGM、PTPM、FlowTime | 区分跳过、短看、继续看和长看 |
| 多目标 | EMER 或等价融合 | 统一短期收益和长期留存 |
| 列表生成 | OneTrans-GSR、LIGE-GR、HiGR | 统一重排、混排和业务约束 |
| 生成召回 | SnapLGR、ZeroGR、ReuseGR | 先过滤再约束解码，控制延迟 |

观看时长不是唯一目标。必须同时监控内容深度、多样性、新鲜度、长期留存和用户
负担，防止推荐系统只优化容易测量的短期指标。

### 3.5 通用用户画像推荐

这套系统不只推荐短视频，还可以覆盖 IM、音乐、文档、任务、通知和商业内容。
跨域推荐需要共享语义物品空间和部分用户表示，但保留场景级输出头：

| 共享层 | 场景独立层 |
| --- | --- |
| 内容语义和物品 ID | 场景目标和展示约束 |
| 用户长期表示 | 场景权重和排序头 |
| 行为事件格式 | 业务安全规则 |
| 反馈写入协议 | 场景级回滚开关 |

多场景统一的目标是减少训练和服务碎片，不是强制所有场景使用同一个目标函数。

## 四、推荐与缓存协同

推荐结果可以输出预取计划，但必须服从以下约束：

- 当前播放的下一分片优先。
- 预测观看不足一个分片时不预取完整视频。
- 低带宽网络下的预取范围更保守。
- 用户快速滑动时立即撤销未完成预取。
- 预取命中率和预取浪费率必须同时监控。

推荐系统不得为了让内容更容易缓存而牺牲长期覆盖率。缓存命中率只是结果指标，
不是推荐目标。

## 五、分阶段落地

第一阶段：

- 多路召回。
- 轻量排序。
- HEGM 或 PTPM 风格的观看时长分布。
- 画像投影服务和动态预取规则。
- 全链路字节、延迟和资源埋点。

第二阶段：

- 长序列编码和请求级复用。
- 多模态向量和语义 ID。
- 列表级重排。
- S3-FIFO 或 SIEVE 缓存策略。

第三阶段：

- 生成式召回和列表生成灰度。
- 多场景统一骨干。
- 偏好不确定性、长期满意度和选择性画像写入。
- 端侧超分和高级媒体算法只在独立实验通道评估。
