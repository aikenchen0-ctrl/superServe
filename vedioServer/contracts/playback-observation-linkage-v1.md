# 播放联合观测契约

2026-11-07。该契约把推荐决策、播放授权、媒体请求和客户端消费放进同一条可复算链路。

## 关联链

```text
recommendation request_id
    -> durable decision_id + returned candidate_id
    -> signed playback-decision receipt
    -> playback grant playback_id + decision_id + request_id
    -> CMCD sid=playback_id, cid=candidate_id, vs-rid=request_id
    -> client-consumption interaction_id=playback_id
```

推荐接口只有在学习日志已接收决策后，才返回`X-Playback-Decision-Receipt`。
收据绑定目录指纹、主体摘要、决策标识、推荐请求、实际返回候选列表和短期过期时间。
客户端不能生成或修改收据，播放授权服务校验收据后才回传决策关联字段。
直接播放授权不带决策字段，保持兼容。

## 客户端声明与可信事实

- `playback_id`是服务端随机播放实例，不是用户身份。
- CMCD字段和浏览器帧回调属于客户端观测声明，不是观看证明。
- `WebVideoFrameCallback`只说明浏览器产生了帧回调，不能证明物理屏幕出光。
- XHR正文累计字节只表示浏览器可见的应用层响应正文，不含协议头、TLS、重传或系统缓存。
- 暂停/停止先停止加载，再等待在途请求结束，随后封存消费批次，避免把取消时的尾部字节丢失。
- 首帧、进度、卡顿和字节进入`client-consumption-v1`规范化器；默认实验入口不持久化。
- 2026-11-09新增显式本机合成模式：`VS_LAB_FEEDBACK_CONFIG`可转交原反馈持久化接口，
  仅接受当前服务器登记的播放实例，检查点和尾批可进入固定原始快照与重建。
  该模式不是生产消费JWT入口，详见`playback-consumption-persistence-v1.md`。
- 消费批次仍需可信网关签发的消费JWT才能进入正式反馈入口；浏览器实验的`subject`和来源只用于本机验证。

## 当前实现边界

CMCD复用固定hls.js 1.7.4控制器提供的`sessionId/contentId`结构，
只设置第一方`vs-rid`扩展并继续使用现有Rust `sfv`子集解析。
没有引入CMCD v2事件、逐分片服务端控制、浏览器日志持久化或推荐质量自动回写。
推荐候选的真实性来自服务端决策日志和签名收据，不来自CMCD。

## 媒体层关联校验

播放授权令牌当前有两个版本；默认仍签发`v1`，只有签发端显式设置
`VS_PLAYBACK_LINKAGE_V2=1`才签发`v2`。须先升级媒体读取端再启用签发；
升级后的媒体端兼容两版令牌，HLS子引用保持收到的令牌版本：

- `v1`：旧格式仍可读取，但不宣称具备联合观测绑定；
- `v2`：在令牌签名负载中增加一个16字节的HMAC联合摘要，绑定播放实例、候选标识和可选的推荐请求标识。

媒体层收到CMCD后，只在以下条件同时满足时计入`verified_playback_linkages`：

1. `sid`经固定哈希后对应令牌中的播放实例；
2. `cid`和`vs-rid`的组合与令牌联合摘要一致；
3. 令牌仍在有效期内且签名校验通过。

直接授权没有推荐请求标识，只能计入直接播放关联；带决策收据的授权才可能计入
`verified_recommendation_linkages`。不匹配的客户端声明只计入
`unverified_linkage_claims`，不会改变授权结果。

CMCD不是跨端硬依赖。对不发送CMCD、关闭CMCD或不支持完整`cid`的原生客户端，
媒体层仍可根据成功响应携带的已验证v2播放能力计入`capability_authorized_requests`。
该计数只证明请求使用了有效v2能力，不从令牌摘要推断它是否来自推荐。
只有CMCD请求标识与能力摘要一致时，才计入`verified_recommendation_linkages`。
这些计数按成功媒体HTTP请求计算，不是用户数、去重播放数或消费事实；
CMCD匹配计数和能力计数必须分开报告，不能把两者相加。

推荐或Feed响应在存在合法请求上下文时可返回`x-vs-trace-id`，Web、Android和iOS客户端
可将其带到后续媒体请求，供交付观测关联。它不是`traceparent`，不创建span，也不参与
授权、缓存键、播放能力摘要或CMCD验证；未发送或非法时保持未知。当前已用Web Chromium
与固定hls.js点播实验验证清单和媒体请求携带同一值，Android/iOS仍未实测。

处理器完成令牌、资源范围和媒体读取校验后，通过响应扩展交给观测层复用已验证对象，
不重复验签。被拒绝或响应头前被取消的请求不会计为已验证关联。
计数在请求生命周期结束时更新；请求仍在途或并发读取多个原子计数时，快照并非一致事务。
结构化交付日志只写关联结果类别及数值遥测，不写CMCD会话摘要、候选标识或推荐请求标识。

摘要中不包含主体或推荐请求明文，且播放实例参与摘要以减少跨播放关联；
现有令牌仍含随机播放实例和带密钥的主体摘要，编码不是加密，完整路径仍须按凭据保护。
校验只证明声明与已签发能力一致；持有者可重复发送声明，故计数不是去重播放数、
观看事实、屏幕出光或推荐质量。v2的令牌段从216增至238字符，须检查代理、原生客户端
和访问日志的长度兼容；关闭签发开关后，存量v2在到期前仍可读取，不能直接降级读取端。

这是成本归因基础，不是三低收益结论。需要同一trace比较无预取、固定窗口和动态窗口，
并同时记录首帧、卡顿、实际消费字节、服务端产出字节、CPU/RSS和推荐覆盖。
