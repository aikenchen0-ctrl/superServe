# 可信推荐访问凭据 v1

## 边界

`POST /internal/v2/feed`是面向可信用户网关的可选内部入口，必须同时通过服务级Bearer和
`X-Feed-Identity: Bearer <token>`。服务端只接受固定发行者、受众和Ed25519公钥验证的短期
`vs-feed+jwt`。入口默认关闭；仅`api`和`all`角色可配置。终端客户端不得直接调用推荐服务。
旧`POST /v1/feed`保持原服务级Bearer契约，供已有可信内部调用方继续使用。

凭据发行者必须先完成用户身份认证，并把稳定的跨端内部假名映射到`sub`；不得将邮箱、手机号等
直接身份信息放入声明，因为开启学习决策日志时主体会写入受控本地证据。该服务不提供登录、密钥
托管、凭据签发或主体映射。客户端不得自行签发令牌；发行私钥不得部署到推荐API进程。

## 请求与授权

请求正文只含`request_id`、`domains`和`limit`，不接受`subject`、画像或实验分组字段。
有效身份由签名声明`sub`提供，允许领域由签名声明`domains`提供；请求所需领域必须是令牌授权领域
的子集。令牌有效期最多300秒，授权范围最多16个领域。

```json
{
  "request_id": "feed-2026-001",
  "domains": ["video", "article"],
  "limit": 24
}
```

外层`Authorization: Bearer <service-token>`用于服务间认证；`X-Feed-Identity`只接受单个短期用户身份断言。
两个凭据不能互换：服务令牌不声明终端用户，身份令牌不能调用其他内部服务接口。TLS由可信网关到推荐服务
的部署链路提供，代理访问日志不得记录`X-Feed-Identity`。

成功响应沿用现有推荐响应、无缓存策略、学习决策日志和播放收据链。开启学习日志时，决策记录中的
主体来自已验签声明，而不是请求正文。响应不暴露主体或令牌内容。

## 多副本

验证无服务端会话状态；所有API副本须使用相同issuer、audience和公钥集合。轮换时允许最多4个
已知`kid`短暂并存。密钥配置不一致会造成副本间不一致拒绝，因此须作为同一版本的部署配置管理。
轮换和撤销依赖配置发布及令牌最长300秒的自然到期；本版本不承诺即时撤销。

## 非目标

该能力不生成实验分组、不记录分组概率、不做随机探索或IPS/DR。JWT身份稳定性是后续跨端实验的
必要输入之一，但不是实验随机化或无偏评价证据。它也不替代TLS终止、登录、授权撤销和网关限流。

## 上游复用

复用`jsonwebtoken`公开解码/校验接口和本仓库`vs-auth`中的Ed25519验证适配；不复制JWT解析器，
不引入运行依赖。算法、类型、发行者、受众、有效期及密钥标识均采用固定白名单校验。
