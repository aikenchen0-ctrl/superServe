# 画像事件备份与封存恢复演练 v1

## 目的与选型

给现有画像事实日志提供**离线**备份和恢复校验，不更换画像算法、权威存储引擎、
HTTP协议或默认入口。不只针对视频，日志与冻结特征继续覆盖目录中的任意受支持领域。
本轮复用固定Qdrant的“恢复前校验摘要、暂存后发布”机制、
原`atomic_create`和原CQRS事件重放；不复制数据库/压缩/归档解包内核。

redb适用于既有协调存储，但当前画像权威是有界JSONL；
引入另一引擎不能自动解决当前备份与写者fencing问题。
Iggy subject分区与物理多机仍为独立候选，当前备份不代替它们。

## CLI

先加载`D:\CodexVideoTools\enter.ps1`并按锁文件构建`vs-service`的
`profile_backup`示例。所有输出和临时文件须遵守工作区O盘约束。

```powershell
profile_backup create <固定目录JSON> <已停止日志> <新归档>
profile_backup verify <固定目录JSON> <归档> <固定SHA256> <已存在暂存目录>
profile_backup restore <固定目录JSON> <归档> <固定SHA256> <新恢复日志>
```

返回有界JSON收据，不含主体、事件正文或路径。
失败退出非0，不在stdout伪造成功收据；发布阶段失败时输出状态可能不确定，
应独立核对已经出现的归档或封存标记，不能自动重试覆盖。
目录JSON上限8MiB，归档最大为原32MiB日志加4KiB头及12字节前缀。
CLI是可信本机运维工具，输入路径不是远程API，暂存目录需预先存在且访问受控。

## 原始数据与校验

归档为8字节magic `VSPRBK1\n`、大端4字节JSON头长度、严格JSON头及原始日志字节。
头包含版本、当前目录指纹、原历史水位、主体数和确定性投影指纹。
不使用tar/zip，不从归档读取文件路径，不能指定任意解包文件。
原日志逐字节保存，包含主体标识、事件、历史目录指纹和冻结特征。

校验层次必须同时成立：

1. 调用方从可信记录取得**整份归档SHA256**，不是仅信任归档内自报摘要。
2. 头/目录指纹、长度、原历史水位和载荷摘要匹配。
3. 使用原严格事件解析器核对单主体序号、事件ID/正文冲突、冻结特征及预算。
4. 重放原`ProfileState`，比较主体数与确定性投影指纹。

归档二次读取再绑定同一个外部摘要，不靠共享锁保证所有外部程序都合作。
确定性投影比较固定排序、空scopes和固定到期值，只用于恢复校验，
不会发放授权投影，也不改变真实投影的到期/权限规则。
更换目录标签不回写历史特征，历史Hide仍由原事件重放保持。
摘要只证明内容一致，不证明授权、匿名性、加密、业务正确或外部来源可信。
重算所有摘要也不能绕过严格事件序号与领域规则。

## 源只读与并发

备份只读打开现有源，取得共享文件锁；与原画像写者的独占锁互斥，
活动写者未回收则失败，不从活动写者复制半截状态。
新增只读路径不创建源、父目录，不chmod或截尾，不加封存标记，不推进源版本。
输出禁止占用源日志及原路径/规范路径的`.sealed.json`保留名，
不能以备份归档意外封存仍可重启的原写者。
归档输出也禁止使用`.sealed.json`后缀，防止误占其他画像日志封存路径；
这不能替代受控目录和可信本机操作者约束。
断尾、重复ID、非法事件等不自动修复；原常规启动的独立尾部修复语义保持不变。
已经封存的源仍可备份，但不会解除其封存状态。

原32MiB日志、16KiB单记录、1万主体及原投影预算保持。
重放仍使用原日志的内存事件集；64KiB复制缓冲不代表全过程只占64KiB内存，
原日志字节上限也不等于Rust结构膨胀后的RSS上限。
文件锁约束只覆盖遵守锁的本机进程，不证明网络文件系统或多机锁语义。
不在请求热路径增加备份工作，不提供在线快照、增量或持续复制。

## 恢复演练与写者权威

`restore`先将原始载荷写到指定父目录的临时文件，
严格校验与重放通过后才发布；既有目标或既有封存标记拒绝覆盖。
沿用现有封存格式，**先发布封存标记，再不可覆盖发布恢复日志**。
恢复日志目标也禁止使用`.sealed.json`后缀，不允许恢复载荷占用其他日志的封存名。
进程在两者之间崩溃可能只留下标记，不能把该目标启动为写者；
遇到失败不自动删除标记或启用日志。收据明确`restored_writer_enabled=false`。

恢复日志不能经正常`AppState`启动为画像权威。可再次严格备份或校验，
用于演练原始事实与投影重建；不会生成新的用户事件，也不激活备份副本。
正式灾后切换仍需证明旧权威已被全局fence、客户端历史水位一致及权限/撤回治理有效。
原`handoff_profile_log`仍是独立运维操作，其本机标记不是物理集群的全局fence。
**不提供删除封存/强制启写开关，不声称仅凭本地备份可安全完成灾后升主。**

## 安全与证据边界

归档与恢复日志含敏感画像原始数据。已有日志Unix权限0600、
tempfile私有暂存及文件同步继续适用，Windows ACL继承与目录访问须由部署者管理。
没有实现生产加密密钥、保留期、用户删除/撤回传播、异地复制或备份访问审计。
不可因在线画像删除而假设离线备份已删除，未满足治理门之前不接生产画像。
原子发布沿用`persist_noclobber`及Unix目录同步；可能留下临时链接，
Windows掉电与跨盘目录持久性不由本机测试证明。

本轮仅解除单节点离线备份/恢复演练的机制缺口，
不解除物理独立故障域、分片在线扩容、生产灾备、三低或真实跨域推荐效用门。
