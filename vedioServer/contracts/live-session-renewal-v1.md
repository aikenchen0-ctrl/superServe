# 直播会话续权契约

版本v1，2026-11-07。Web、Android、iOS共用HTTP契约。
当前实现与实验仍限回环、本机VP8，不提供原生SDK或生产发行者。

## 入口与职责

仅配置VS_LIVE_ACCESS_CONFIG时注册以下扩展：

```text
POST /whip/sessions/{id}/renew
POST /whep/sessions/{id}/renew
Authorization: Bearer <new-live-token>
```

正文必须为空；OPTIONS允许发现POST和Authorization。
这些地址是本项目扩展，不能把它们当作WHIP/WHEP标准能力。
原Location仍支持GET/DELETE，PATCH仍为405，不占用ICE片段语义。

客户端先向可信发行者取得更新的vs-live+jwt，再向原媒体目标续权。
媒体服务只持有验签公钥，不自行生成令牌、不信任用户指定的发行者URL。
外部发行者须重新核对主体、角色和当前房间分配，不能无条件按旧令牌续签。
现有实验Node签发工具不提供这项生产保障。

## 接受条件

现有验签继续检查类型、算法、公钥、发行者、受众、主体、时间、
租户、房间、角色、节点和启动代次。媒体线程进一步要求：

1. 目标会话仍存活，角色与所有者匹配。
2. 新旧assignment_revision完全相同；受控模式还要匹配当前活动分配。
3. 新凭据尚未到期，不能用其恢复已到期、已删除或已排空的会话。
4. 新exp大于已接受exp才更新期限；同一凭据、相同exp只返回现状。
   相同exp但不同凭据及较旧exp拒绝，避免只读重试偷偷切换授权身份。

首次会话单调期限为min(当前时间+60秒，授权到期)。
新授权上限取“旧单调授权上限+新旧exp差”与“当前时间+新凭据剩余期”的较早者，
本次会话期限再取当前时间+60秒与该上限的较早者。
因此每次续权仍最多60秒，重复或乱序请求不能重置已接受期限，
墙钟回拨也不能把同一授权凭空延长；墙钟前跳仍可能提前回收。
受保护执行进一步使用[不可回退的授权时间水位](revocation-reclamation-v1.md)，
已失效授权不会因后续墙钟回拨重新生效；水位不替代单调媒体租期。

续权、排空和到期清理由同一媒体线程串行执行。
排空先发生时续权被拒绝；续权先发生时后续排空仍清除连接。
不重建Rtc、不重新SDP协商、不增加逐帧或逐观看者共识读取。
这是用户会话授权，不是房间所有权租约或失联接管证明。

## 回执与失败

成功为200、application/json、no-store：

```json
{
  "lease_milliseconds": 59840,
  "expires_unix_seconds": 1794039000
}
```

lease_milliseconds表示媒体线程处理时的剩余会话期限，上限60000；
expires_unix_seconds是已接受凭据的exp，并不承诺连接一定存活至此。
客户端计时应从发请求前开始，扣除往返与重试预算，提前取得下一凭据。
200只证明处理时接受，不保证其后未排空或断开。

| 状态 | 含义 |
| --- | --- |
| 400/413 | 非空、读取失败或超限正文 |
| 401 | 凭据缺失、无效、过期或越范围 |
| 404 | 没有可续权的所有者/角色匹配会话 |
| 409 | 旧exp、分配不符或已排空 |
| 503 | 原有4条控制队列、4个验签许可或媒体线程不可用 |

保留8秒HTTP总期限。HTTP超时后结果未知，可以向同一续权地址重试同一凭据；
这不会滑动已接受期限，也不能据失败自动重新创建发布者。
409需重新确认授权/分配；404需取得新授权并显式重新协商。
GET/HEAD只查询，DELETE只释放，都不延长媒体期限。

## 客户端与限制

实验网页提供liveRenewSession(name, token)，成功后更换资源管理凭据；
并发旧回执不能覆盖较新凭据。本轮不添加常驻签发器、自动重连或按钮。
Android/iOS须在各自生命周期中绑定同一契约，仍待原生验证。
停止续权或发行者不可用时按原期限回收；发布者到期会清空本实验房间。
执行端已提供[逐令牌撤权](live-token-revocation-v1.md)，仅受控模式启用。
主体/刷新令牌撤销、切网/ICE恢复、TLS、物理多机及总体三低收益仍待验收。
