# 跨批消费证据重建

## 目的与入口

`consumption-replay-v1`对一份固定`feedback-evidence-v1`归档重建消费交互，
供后续成本核验使用，不是在线画像更新、训练标签生成或生产准入。

```text
replay_consumption <固定配置JSON> <新报告JSON>
```

配置：

```json
{
  "schema": "consumption-replay-v1",
  "evidence": {
    "path": "evidence.json",
    "sha256": "替换为64位小写SHA256"
  }
}
```

路径必须位于配置目录内，为普通相对路径；沿用原`read_pinned`解析、
共享文件锁和摘要检查。配置最多4KiB，证据最多8MiB。
成功退出0并输出`consumption-replay-receipt-v1`摘要回执；
无效输入或目标已存在退出1，不覆盖既有文件，不发布部分报告。

## 重建规则

1. 复用原始证据的范围、连续消息偏移、载荷摘要和批次语义验证，不复制第二套解析规则。
2. 在同一来源内，以`interaction_id + generation`归组。
   同代次主体、决策、候选、平台必须一致；不同代次独立建基线。
3. `event_id`在来源内唯一。内容和完整交互绑定相同才算重试；
   同ID改内容或改代次拒绝，不以哈希摘要相同代替事件等价。
4. 同代次不同事件不能占用同序号。去重后按序号排序；
   批次到达乱序不等于客户端单调时间倒退。
5. 排序后再次复用原消费归一化，检测跨批时间、计数和累计时长冲突。
   在线批次上限64项保持，离线总原始事件最多8192项。
6. 首个已知累计值只建基线；第二个及以后已知点计算`末值 - 首值`。
   中间`null`不补零、不插值。零差值、单点未知增量、完全无观测分别报告。
7. 同代次累计值倒退拒绝；不自动假设重启或静默建立新基线。
   活动/等待各自的观测增量不得超过该观测区间的单调时间。
   同时具有两个计数的观测点之间，二者增量之和也不能超过该区间时间。
8. 首序号大于1和中间缺序号以半开区间报告，不逐项展开巨大缺口；
   不补事件，也不推测最后一个已见序号之后是否有丢失。
9. 旧学习批次只计入`legacy_batches`，不拿Visible/Like等事件补QoE。
   整份归档无消费批次时拒绝，不输出看似有效的全零报告。

累计求差局部转写自固定OpenTelemetry Collector Contrib
`b83eb00d069d77f9bd77c6c247dfcdaa3628cdc9`的`MetricTracker.Convert`：
采用`InitialValueDrop`首点策略和单调整数差值，
本地新增显式窗口、严格重置拒绝和时长检查。
未引入Collector、Go运行时、后台状态过期或新增外部Rust版本。

## 报告

`consumption-replay-report-v1`包含输入证据摘要、数据类型、覆盖统计及逐交互结果。
回执只含报告摘要、字节数和计数。

| 字段 | 含义 |
| --- | --- |
| `coverage.input_events` | 原始消费事件出现次数，包含重试 |
| `coverage.unique_events/duplicate_events` | 去重后的事件数与重复出现次数 |
| `coverage.streams_with_missing_sequences` | 有已知前缀或中间缺口的交互代次数 |
| `interaction_ref` | 来源及完整交互身份序列化后的SHA256；不是匿名化证明 |
| `platform/generation` | 测量平台声明和独立计数代次 |
| `missing_sequences` | 已知缺口的`from/until_exclusive`列表 |
| `first_presentable_elapsed_ms` | 已见最早呈现声明，不保证是完整生命周期首帧 |
| `last_position_ms` | 最后已知位置，允许seek，不当作活动时长 |
| `visibility_declarations/explicit_preferences` | 去重后的声明次数，不当作观看证明或独立训练标签 |
| `byte_scope` | 原平台字节口径，不能跨平台当同一线路计量 |
| `active_ms/rebuffer_ms/transferred_bytes` | 各自独立的计数观测窗口 |
| `*.samples` | 该计数的已知观测点数 |
| `*.baseline/last` | 窗口的第一个和最后一个已知累计值 |
| `*.observed_delta` | 两个及以上已知点才有差值，单点或无观测为`null` |
| `*.first_sequence/last_sequence` | 该计数而非全部事件的观测序号 |
| `*.from_elapsed_ms/to_elapsed_ms` | 该计数的观测起止时间 |

报告最多4MiB，内部最多1024个交互代次，无常驻状态。
当前证据协议最多128个批次，实际可含的交互数还受该上界约束。
同固定输入两次发布结果确定；改变分批会改变输入摘要与批次数，
但未改变事件时，重建的交互观测保持相同。

## 不可扩大解释的边界

- 单文件内跨批，不是跨归档、跨分区或跨收集器去重，不可直接叠加重叠快照的报告。
- 首点以前和末点以后的计数未知；即使序号连续也不证明完整交互生命周期。
- 序号缺口不必然使两个累计值之差无效，但其中间事件细节未知，不能插值。
- 各计数可能使用不同起止窗口，不能直接拼成同时间范围的卡顿率或总成本。
- `observed_at`沿用原UTC声明；单调时间只在相同交互代次可比较。
- 检查两个同时已知计数点之间的联合时长，不证明不同计数窗口之间没有时段重叠。
- 原始事件的授权和真实性仍依赖来源；内部摘要可重算，不是不可伪造证明。
- 报告不输出原主体、候选、决策及交互ID，但散列和平台仍可能敏感，需访问与保留策略。
- 客户端字节声明不是线路计费，呈现声明不是采集到屏幕延迟。
- 不计算真实用户效用，不读取CPU，不宣称三低收益、原生真机、物理集群或生产容量已验。
