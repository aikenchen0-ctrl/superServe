# 协调节点双向TLS实验契约

日期：2026-11-08。仅扩展独立`vs-coordination`的协调通信，
不把媒体HTTP/UDP、媒体排空连接器或`media-admin`自动升级为跨机接口。
后续`media-admin`已独立接入可选运维mTLS，见
[客户端契约](media-admin-client-v1.md)；不是服务端开关自动带来的能力。
媒体到协调面的只读核验也已单独接通，见
[media-authority-mtls-v1](media-authority-mtls-v1.md)；不开放媒体监听。
配置结构见`coordination-mtls-v1.example.json`；其中地址、路径、凭据和指纹均为占位，
不是可直接连接的部署。此契约不签发证书，也不开放公网服务。

## 模式与材料

- 未配置`tls`时保持原回环HTTP；配置后为TLS 1.3和HTTP/1.1，不接受明文降级。
- 每个监听/名册地址必须是明确回环、RFC1918 IPv4或ULA IPv6；拒绝零端口、
  通配、公网、链路本地和组播。私网地址不等于可信身份，仍必须通过下列验证。
- 节点固定名册1至5项。`server_names`、`peer_sha256`必须与全部`peers`键一致；
  名称为唯一小写DNS名称，不接受IP、URL、路径或通配名称。
- 三个材料文件路径必须绝对，每文件1至65536字节。CA集合、节点链各1至4张；
  节点leaf必须与本节点DER的SHA256一致，私钥必须匹配。
- 本节点证书通过配置CA、有效期、DNS SAN和ServerAuth/ClientAuth双用途检查。
  入站客户端由同一CA验证，再按真实leaf指纹分配角色；不启用系统额外根。
- 指纹为64位小写十六进制，只计算leaf证书DER，不计算PEM文本。
  节点指纹唯一；运维身份1至4个，不与节点混用。私钥不得提交仓库或输出日志。
- 出站按配置DNS名校验服务端，用`.resolve`固定到名册地址；不查外部DNS、
  不经代理、不重定向、不自动HTTP重试。服务端信任依据是CA和名称，
  不是额外自定义的服务端leaf验签器。

## 请求权限

所有角色仍须携带原内部Bearer；此凭据不得下发Web、Android或iOS用户。
`Host`必须匹配本节点名称和端口，拒绝`Origin`和重复Authorization。

| 证书身份 | 允许范围 |
| --- | --- |
| 固定节点 | 仅`/raft/*`；投票/追加/快照中的发送者必须匹配证书节点ID |
| 固定运维 | 管理、房间业务和本地观测接口；不能调用`/raft/*` |
| 显式只读媒体 | 仅GET分配视图，当前owner须为其绑定逻辑节点；不能调用管理、Raft或观测接口 |
| 同CA但未列指纹 | TLS后403 |
| 无证书、错误CA、过期证书 | 握手失败，不进入HTTP权限判断 |

不从自报HTTP头、网络来源或Bearer内容推导证书角色。
Raft RPC还携带原`x-vs-room-policy`；业务或传输模式不一致时409。
超时、断开或失去多数派仍是未知写入，不证明未提交，不新增写重试。

## 持久状态与换证

业务策略摘要对TLS模式使用：

```json
{"media_control": null, "transport": "coordination-mtls-v1"}
```

`media_control`实际值参与摘要；明文模式保持原序列化字节，不增加空TLS字段。
`pin_policy`继续拒绝同一数据目录静默降级或改变业务策略。
既有明文库不能直接加`tls`绕过策略锁；受控迁移协议另验，禁止删库“解决”。

CA、名称和指纹属于可更新运行身份，不永久散列进房间数据库。
启动回执增加`tls_identity_policy_sha256`，记录有效CA指纹集合、节点名称/指纹及
运维指纹的序列化摘要，用于审计，不代表各节点自动配置同步。
明文回执不新增此字段。

已验证的换证方式：停止节点，同CA/同DNS名签发新节点证书及私钥，
受控更新身份文件和名册指纹，使用原数据目录重启；权威记录、版本和重复命令结果保留，
旧leaf被拒绝，新leaf可调用Raft。不得给所有节点共用同一节点证书。
当前每节点只有一个指纹，未实现双指纹重叠窗口、热轮换、CRL/OCSP或自动签发。
多节点换证必须另行设计一致配置与多数派可用性，不承诺无损滚动轮换。
旧进程存活期间仍使用已加载身份，修改磁盘文件不会立即撤权。

## 预算与停机

最多32个TLS连接，超额连接直接关闭；握手2秒，HTTP头2秒/32KiB，
连接最长30秒；停机排空最多3秒，剩余连接任务有界回收。
共识客户端连接500ms、请求1200ms、每host最多2条空闲连接。
原2MiB正文、8请求、4个未确认提案及持久预算保持。
资源限制不是吞吐或RSS结论，TLS有额外握手、加密和连接重建成本。

配置仍通过`VS_COORDINATION_CONFIG`读取；实验运行期限30至900秒，默认300秒，
不是常驻生产服务契约。TLS不改变初始化和成员管理权限。
新成员必须预先进入所有相关节点的固定名册/身份配置，再以learner追平并变更成员；
名册外在线发现、任意无限扩容和自动移除均未实现。
3到4投票成员只验证变更机制，不推荐把偶数投票规模作为生产最终拓扑。
