# 画像共识负载诊断契约

日期：2026-11-09。状态：同机、合成、小容量诊断，不是生产压测准入。

## 复用与目标

调度与计划起点计时局部改编自固定 `hatoo/oha` 提交
`43c7cf207fa7153ff1dbb566b0a9d60b3741d0d6` 的
`work_with_qps_latency_correction`、`RequestResult::duration`。
保留MIT许可及变更说明，不引入其CLI、HTTP内核、TUI、无界队列或新依赖。
HTTP仍复用当前reqwest，服务仍使用原OpenRaft/redb实验模式。

目的不是选出“最快数据库”，而是区分：

- 客户端调度滞后；
- 服务请求耗时；
- 客户端满载丢弃；
- 服务总请求预算拒绝、写提案预算拒绝；
- 未知写入结果；
- 已核验成功的事件、重复确认和投影。

## 固定工作负载

每单元新建隔离目录和1或3个投票进程，仍只有1个Raft组和1个物理宿主。
16个合成主体，固定视频、文档、服务目录，分2个逻辑分片。
预填16或128个事件，每主体已有一次document Hide。
每单元计划192个请求：64个新事件、64个原事件重复确认、64个线性投影读取。
即使全部新事件成功，也不超过原256事件/32主体实验上限；不改变服务预算。
计划请求速率40或800次/秒，最大32个客户端在途请求，无等待队列、不自动重试。
第二轮矩阵逆序执行；独立单元不共享历史，预填/连接预热不计入请求延迟。

输出必须标明构建配置。当前实际矩阵为debug，不能当release容量数据。
800次/秒只是计划到达速率，不是完成速率或独立用户数。

## 计时与拒绝

到达时刻为运行起点加上 `序号/计划速率`，不根据上一个请求完成时刻延后。
每个实际请求记录：

- 计划偏移；
- 实际开始相对计划时刻的滞后；
- 实际开始到响应正文读完的耗时；
- 计划时刻到正文读完的总耗时。

本地实现进一步把Windows定时器/调度滞后纳入计划起点耗时，
不把原工具实现与本实验称为逐行等价。
客户端许可不足时记录 `client_dropped`，不排队、不重发；
该样本保留在总数中，但不混入HTTP成功延迟分位数。
服务返回503/504保守记为未知/未确认，按正文附加预算分类，
即便当前正文说明未接纳，也不据此重发同一逻辑写入。
所有HTTP响应和正文都受原客户端4秒期限、禁重定向/重试及64KiB响应预算约束。

分位数按全部原始样本精确排序、nearest-rank计算，分别列实际尝试和已核验成功。
不平均多个单元的P99，不把快速拒绝算成成功，不做直方图插补或伪造缺失延迟。
每类最多64个成功样本，P99等于最大值；不能据此估计总体尾部分布或置信区间。

## 正确性优先

响应验证固定目录、主体、范围、Hide、版本、当前writer owner/epoch和事件结果。
伪响应、错误主体、丢隐藏、错epoch、非法版本、超大正文和重定向不算成功。

测量后对两个逻辑分片各提交一次写者换代屏障。
屏障与在途事件进入同一Raft顺序，屏障后旧epoch不能再提交；
随后逐主体核对最终版本：

```text
预填版本 + 已确认新事件 <= 最终版本
最终版本 <= 预填版本 + 已确认新事件 + 未确认新事件
```

全部主体的版本之和须等于权威事件总数，且document仍隐藏。
未知写在屏障前可能提交，不能声称“未看到确认”等于“没有发生”。
屏障失败则整单元失败，不以丢弃报告掩盖。

## 进程与资源

Rust探针只接受调用方显式指定的服务二进制绝对路径和新实验目录。
PowerShell运行器限制结果目录为本项目O盘 `.artifacts` 下的新目录。
采样器接收探针报告的服务PID，核对真实二进制路径后通过父stdin握手，
服务才能开始预填/测量，避免短单元先结束引发PID识别竞态。
常规收尾由Rust持有Child并kill/wait，随后验证所有TCP端口可重绑。
运行器失败时只回收自己创建探针的子树，保留stdout/stderr和实验目录，不删除文件。

每约20ms采集各服务/探针的累计CPU、工作集、私有字节和进程历史峰值。
累计CPU差包含准备、预填、测量及核对；短高负载与长低负载不能直接比较总CPU优劣。
逐进程峰值不是集群同时峰值；采样可能遗漏尖峰。
不采Windows内核IO，不声称设备写放大、线路计费、功耗、客户端QoE或联合三低收益。
服务器和压测器同机争用CPU/磁盘/调度，是实验代偿，不能视为独立负载机。

## 后续门

本实验不足以修改4个写许可或8个总请求许可，也不足以决定拆多少Raft组。
真正的容量选择需要Linux release、独立负载机、真实分布/SLO、长时稳态及负载机能力门，
再共同测CPU/RSS、存储IO、线路字节、确认率和P95/P99。
不能通过增加重试、无界排队、提高实验历史上限或隐藏拒绝来“改善结果”。
