# 本地模型块剪枝

## 功能与范围

`model-blockmax`为显式可选的精确模型后端，复用`GroupedRecall`现有领域/完整标签分组，
以及原Rust六维模型、完整排序键和Top-K选择器。
两个推荐入口共用同一选择接口，不增加网络请求或模型服务。
默认仍为原配置，`catalog`、`model-topk`及`model-pruned`继续保留。

## 跳过评分的条件

现有组内成员按先验降序和ID升序排列。
同组候选除了先验，其他模型特征在同一请求下相同；
当前有限权重和固定求和方式保证分数对先验单调或保持常数。
同一组的可见端点评分最大值覆盖组内全部候选。
这个前提与原整组剪枝一致，不是通用神经模型的上界。

新路径先执行原来的整组过滤、可见候选计数和整组上界检查。
对于超过64项且两端分数不等的组，按索引位置划为固定64项块，
先处理模型分数较高的一端；不反转分数的先验/ID同分规则。
每块找到实际可见端点，用原模型计算上界。

跳过块的条件：

```text
完整领域/标签过滤允许该组
且该块存在可见候选
且Top-K已形成有效分数门槛
且块上界严格小于门槛
则可以跳过块内其他评分
```

块上界为零时提升为正零，保守覆盖正负零差别。
同分或舍入平台不能按相等条件跳过；最终选择仍使用模型分数、先验和ID完整排序。
组端点或块端点评分复用，不重复记作一次新的模型求值。

## 成本和观测

块边界按现有成员切片计算，不存额外常驻块索引。
这不消除原分组索引：同`model-pruned`一样，索引每个副本独立构建。
选择器的评分暂存仍最多2K项，未将索引字节当作进程RSS。

`ModelPrunedWork`新增块检查、跳过块、块上界求值及反向遍历组计数；
`model_evaluations`同时计入所有端点评分，
`model_evaluations_skipped`是合法候选总数减实际模型求值。
有隐藏ID时仍扫描候选以保持`considered`，并为可见端点与候选检查承担额外工作。

小组或同分组回到原整组处理；很多小组、隐藏ID或近似平台可能没有收益。
模型评分减少不等于CPU、RSS、网络或用户体感改善，必须结合相同输入的成本对照。

## 配置与部署

```powershell
$env:VS_RECALL_BACKEND = 'model-blockmax'
$env:VS_RANK_MODEL = '<固定模型>'
$env:VS_RANK_MODEL_SHA256 = '<模型指纹>'
```

固定部署选择使用：

```json
{
  "recall": {"backend": "model-blockmax"},
  "rank_model_sha256": "<模型指纹>"
}
```

必须先加载固定模型，不能与旧召回、已有模型选择或已绑定部署同时重新配置。
无模型、目录不符、过期/越权画像或部署选择错配时拒绝。
响应头与指标报告`model-blockmax`；运行中的旧实例不跟随新部署变更。
新枚举是配置扩展，旧二进制会拒绝，应协调升级，不能静默降级。

## 参考与边界

参考固定Tantivy块上界/竞争门槛机制，具体上界继续使用本项目原有端点规则，
没有复制完整Block-WAND、倒排运行时或新建检索系统。
来源见`LICENSES/tantivy-blockmax-NOTICE.md`。
改变模型特征、权重合成、求和顺序或组内排序时必须重新验证单调前提；
不能将此优化直接套用于任意新增模型。

## 复算

在加载项目的非C盘工具环境后，于`vedioServer`构建和运行四路release矩阵：

```powershell
cargo build --offline --locked --release -p vs-core --example model_pruned_matrix
```

直接执行生成的`model_pruned_matrix`，以不同的新文件保存两次结果。
当前输出schema为`model-blockmax-matrix-v1`，每格24次预热、24次测量，
四路全部24种排列各覆盖一次。旧三路矩阵输出仍保存在原证据中；
比较工具需要按新schema读取`blockmax_work`与第四路时间字段。

独立进程内存采样复用`labs/model-pruned/measure-memory.ps1`，
显式传入`-Backends @('full','topk','pruned','blockmax')`，
以及release二进制和一个尚不存在的非C盘输出目录。
此脚本的固定内存负载不保证触发块剪枝，只检验共享索引的持有代价与阶段内存，
不能据此评定所有块剪枝负载的峰值内存。
