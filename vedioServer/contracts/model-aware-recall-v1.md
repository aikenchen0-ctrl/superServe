# 模型感知召回实验

## 决策边界

本路径为离线实验，不接入`/v1/feed`和`/v1/recommendations`的默认配置。
需要精确保留全部模型结果时，继续使用全量模型、`model-topk`或已验证的`model-pruned`路径。
模型感知候选需逐目录、模型和请求集合审计，不能因使用成熟索引就默认视为无损。

## 复用与表示

复用固定Qdrant 1.20.0稀疏向量索引、Query API、过滤和读回接口；
传输复用现有有界客户端，重排使用现有Rust六维线性模型。
没有复制或重写Qdrant存储、检索或分布式内核。

投影`domain-tag-linear-f32-v1`由公开目录构建：

- 全体候选共享一个存在维度。
- 每个领域拥有偏置、先验维度及按标签字典排序的标签维度。
- 候选保存偏置1、先验值、每个标签的`1/标签数`；无标签候选也写入。
- 查询按领域组合模型权重、正负兴趣及非零兴趣命中系数，包含全局权重和领域修正。
- 未训练领域沿用原模型的全局权重。

字典按领域和标签排序，目录重排不改变维度。模型更新只改变查询权重，
同一目录投影可以供不同模型使用；目录变化则建立新集合。
集合名包含投影版本和完整目录SHA256，查询固定物理集合，不跟随可变别名。

全零模型、冷启动和空标签候选仍需要向量交集，因此查询包含`1e-20`公共存在系数。
该系数及所有f32转换均纳入近似边界，不作为精确排序承诺。
有限精度会丢失近分差异，Qdrant同分次序也不等于原模型的“先验降序、ID升序”规则。
取回候选后按原Rust f64模型重排，只能恢复已取回候选的完整分数，不能补回遗漏候选。

## 索引生命周期

`QdrantModelRecall::publish`只创建新集合，已有集合拒绝覆盖。
所有候选完成写入后，精确计数并逐批读回公开属性、向量维度及权重。
`verify`先清除已验证状态，全部核对通过后才允许查询；失败或取消不得留下可查询状态。
读回能提供快照证据，不能保证验证结束后没有其他写者；部署仍需禁止旁路修改。

单次HTTP正文不超过256KiB，不跟随重定向、不自动重试；查询沿用800毫秒客户端超时，
发布/读回单个操作5秒，整个发布最多120秒，整体验证最多60秒。
发布超时或连接中断可能已在远端产生部分集合，不能将错误解释为没有写入。
实验CLI不会自动删除、重建或覆盖不确定集合。

## 查询与计量

候选预算必须覆盖原请求的返回量，且不超过512。
远端带目录、投影、领域、隐藏ID和拒绝标签过滤；响应再次检查本地固定目录与授权。
未知、重复、越权、错误目录、错误投影、无效分数或超大响应均拒绝。
不能使用旧接口的正分阈值，否则负分或零分的模型候选会被提前删掉。

实验提供两种响应模式，共用相同的检索、预算和远端过滤：

- `payload`：保留候选属性，核对固定点ID、候选ID、目录和投影之间的一致性。
- `id_only`：使用上游`with_payload=false`，只根据完整验证时建立的点ID映射还原本地候选。
  同时检查点ID归属、候选重复、有效分数、领域、隐藏ID和拒绝标签。

两种模式的点ID均沿用现有`SHA256(目录指纹:候选ID)`派生的128位UUID。
同一目录下`id_only`不返回重复的候选属性，也不增加二次批量读取。
响应中的UUID不是授权证明，映射也不证明远端向量或属性在校验后未被旁路改写。
完整读回是共同前提，部署必须限制写权限；不能用省略载荷代替一致性保护。

当前点ID映射以UUID字符串为键，占用额外的本地键存储。
实验仅记录字符串长度之和，未计HashMap桶、对象、容量和分配器，不能当作RSS。
这替换了原候选ID映射，不是新叠加一份映射；实际内存差异仍需测量。

请求只发送模型与画像派生系数、领域和排除集合，不发送主体ID或原始私人文本。
这些系数仍可能透露偏好；私有化、授权、传输加密和保留规则继续由部署环境负责。
报告省略原始画像，但公开候选ID和请求ID仍需按来源授权管理。

分别记录请求及响应JSON正文、本地模型重排数量、检索和重排耗时。
正文计数不包含HTTP头、TLS、重传、存储读取或集群内部流量；
本地评分减少不代表整个系统CPU减少，单次调试构建计时不代表生产延迟。
固定Qdrant源码显示负查询权重不能使用该实现的非负权重剪枝，不能忽略检索端代价。

## 独立入口

在`vedioServer`构建：

```powershell
cargo build --offline --locked -p vs-service --example probe_model_recall
```

配置格式：

```json
{
  "schema": "model-recall-probe-v1",
  "catalog": {"path": "catalog.json", "sha256": "<固定目录SHA256>"},
  "models": [{"path": "model.json", "sha256": "<固定模型SHA256>"}],
  "queries": [{
    "at": 100,
    "request": {
      "request_id": "probe",
      "domains": ["video", "article", "service"],
      "limit": 10,
      "profile": null
    }
  }],
  "budgets": [10, 128, 512],
  "publish": true,
  "response_modes": ["payload", "id_only"]
}
```

`response_modes`可省略，省略或空列表时沿用原来的`payload`模式。
最多两项，不允许重复；开启两个模式时每个模型、请求和预算分别执行两次检索，
这些额外检索仅供离线对照，不会成为线上一次请求的双调用。
报告记录各模式的请求/响应正文、候选集合指纹和完整重排响应指纹，
并统计配对分歧。配置顺序就是实际执行顺序；需要自行倒序复跑，
不能用未均衡的单次耗时宣称性能排名。
同组候选集合相同不代表全目录保真，原有近分和同分截断仍由Top-K保留率反映。

模型路径和目录路径相对配置目录，必须匹配固定指纹，不得越出来源目录。
`at`应处于模型训练截止之后，个人画像仍必须在该时点有效。
最多8个模型、32条请求、4个严格递增预算；配置最多256KiB、报告最多8MiB。
来源总读取沿用32MiB上限，所有输入验证通过后才执行网络操作。

环境指定`VS_QDRANT_URL`和可选的`VS_QDRANT_API_KEY`，执行：

```powershell
probe_model_recall.exe <配置JSON> <尚不存在的报告JSON>
```

`publish=true`会创建并完整读回实验集合；已有集合使用`publish=false`重新验证。
同一实验矩阵全保留且存在非空结果时退出0；有漏召回或全部空结果时保存报告并退出2；
输入或后端错误、重复报告输出则退出1。该结果只检查模型Top-K保留率，
没有用户偏好标签、曝光倾向或真实推荐质量结论。
配对分歧是报告中的独立诊断项，退出码门禁仍由全目录模型结果保留率决定。
