# 共识画像到Feed的只读实验契约

日期：2026-11-09。范围：显式回环实验，不是生产权限或物理集群准入。

后续新增可选[专用读取mTLS](profile-read-mtls-v1.md)：固定私网目标和独立证书/令牌，
TLS就绪不再读取writer元数据。下文共享控制令牌描述原回环兼容路径，不适用于新TLS配置。

## 目的与复用

将既有共识画像的线性投影接入 `vs-service` 的 Feed，
不把画像事件转发、writer取得或换代权限并入推荐请求。
复用原 `ProfileBackend`、reqwest、`ProfileState`、Feed授权与排序过滤。
读取节点选择参考固定OpenRaft
`8815cdba2826f74e848acef361ad03f93bb1c3f8`
的 `examples/raft-kv-memstore/src/client.rs`，
但不复制其写重试、主节点返回地址跟随或日志打印请求的实现。
既有OpenRaft MIT许可与来源保留；本轮无新克隆、依赖或服务端锁文件变化。
同提交的`openraft/src/raft/mod.rs`线性读契约亦核对；官方HTTP与固定克隆
按CRLF至LF归一后逐字符一致，原字节与归一散列分别记录。

## 配置

API显式设置 `VS_PROFILE_CONSENSUS_CONFIG`，
值为已有配置文件的绝对路径，最大8KiB：

```json
{
  "cluster_id":"example-profile-lab",
  "endpoints":["127.0.0.1:8101","127.0.0.1:8102","127.0.0.1:8103"],
  "service_token":"example-only-token-not-for-production-0000",
  "shard_count":2,
  "minimum_applied_index":4
}
```

该示例不提供真实凭据。配置包含敏感服务令牌，不进入命令行正文、日志或公共接口。
端点须为1至5个唯一固定回环SocketAddr，禁止端口0，不接受DNS/URL/远程地址。
分片数为2/4/8/16，最低应用索引为1至9007199254740991。
仅用于api/all角色，不与本地日志、单画像入口、固定分片入口或部署通道混用。
未配置时默认行为不变。旧单日志历史guard不能用于共识后端。

就绪检查实际调用线性读取接口，核对集群、目录、分片数、索引和响应schema。
API的 `profile_read_only=true` 只说明适配代码路径只读，不代表配置中的令牌是只读权限。
当前协调回环服务仍使用共享管理令牌；跨机/生产须专用读取身份和严格TLS，
不得将此配置直接用于公网或生产多租户。

## 读取与主故障

每次Feed请求只读，不提交画像事件或取得writer。
按最近可用节点优先、在固定名单内至多遍历一次：

- 连接失败、请求发送失败或503/504可尝试名单内下一个节点；
- 单节点请求期限600ms，连接期限200ms，完整读取总期限2秒；
- 不使用系统代理、自动请求重试或HTTP重定向；
- 不信任响应中的Location或leader地址，不改变端点白名单；
- 已返回200但身份/正文不符时立即拒绝，不去其他节点寻找“能通过”的结果；
- 响应正文最大64KiB，超限、格式错误、未知字段均拒绝。

协调端先 `ensure_linearizable`，再在同一状态锁下取投影账本和applied index。
返回信封必须带：

```text
schema、cluster_id、catalog_sha256、shard_count、applied_index、
subject、domains、profile（必须显式为对象或null）
```

即使冷主体返回null，也必须匹配请求主体/范围和权威身份，不将失败转换为null。
已存在画像还须校验作用范围、有效期、权重、兴趣/隐藏上限和`memory-N`版本；
N须大于0且不大于应用索引，有效期不得超出本地当前时间60秒。
复用原 `RequestContext` 再校验，Feed仍执行原隐藏/拒绝/范围过滤。

## 历史边界

客户端保留一个进程内最大已观察applied index。
响应低于配置下限或已观察值时拒绝；并发较早响应晚到也可能因此被拒绝。
这是保守的一致性代偿，不自动重试，也不声称存在性能收益。

索引不是历史前缀摘要、集群重建身份、用户授权或防篡改证明。
同名重建集群若具有更高索引，当前适配无法仅凭索引证明原历史完整。
API重启仅保留配置下限，不会持久化本轮已观察的更高索引。
不能据此实现安全灾后切换、删除撤回或读己之写跨API持久凭据。
正式接入仍需权威实例/历史证明与生产授权设计。

## 拒绝写与失败

显式共识只读模式下，`/v1/profile/events` 返回405，
不向远端发送画像写入，也不写本地内存或JSONL。
远端全部不可用或失去多数派时，Feed与readyz返回不可用；
错误集群、目录、布局、旧索引、伪造主体或范围返回冲突。
不降级为目录裸排序或本地空画像，以免隐藏事实被绕过。
通用 `/v1/recommendations` 的既有接口语义不改变，本契约描述的是Feed路径。

`/internal/v2/feed` 继续要求既有服务凭据和Ed25519主体凭据。
签名sub进入共识读取；请求正文不能覆盖subject，领域不能超出签名范围。
旧`/v1/feed`仍为内部兼容入口，不能直接对终端公开。
合成发行者只证明验签与共识读取接线，不等于生产用户授权或即时撤回。

## 验收与仍缺

协议夹具验证固定端点、拒写、主节点发现、错身份/范围/到期/索引、
显式null与缺字段区别、有无Content-Length的64KiB边界、超时及签名主体。
连接/503/504可切换；401/403/404/429/500和重定向不可切换。
独立进程验证三协调节点、两个API：
实际使用Ed25519签名Feed，权威提交Hide/Like后Feed一致；主故障后保留Hide；
失去多数派时Feed和readyz均不可用；恢复、writer换代和API重启后结果仍正确。
错误签名、缺用户身份、正文主体、越权领域及缺服务Bearer均拒绝；
冷主体不影响已有主体Hide，原内部v1返回保持兼容。
最终成功回执在所有进程kill/wait及五个TCP端口重绑之后输出。
运行器按唯一schema定位JSON，允许测试器同一行前缀；仍拒绝零匹配、重复及字段不符。

同机进程不是独立物理故障域。当前仍是一个共识组，有限实验主体/事件预算保持。
本轮不实现生产读取身份、远程TLS、画像写入网关、旧JSONL迁移、
历史前缀/实例证明、跨组迁移、真机或三低基准。
Linux启动器4GiB余量门保持；资源不足时不启动、不降保护线、不回退C盘。
