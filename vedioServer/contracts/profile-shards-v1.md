# 固定画像分片实验契约

日期：2026-11-09。状态：实验接线，不具备生产准入或在线扩容保证。

## 范围

将多个API副本对同一主体的事件和投影定向到一个固定画像进程。
每个分片复用原独占JSONL、CQRS事件信封、历史事实、幂等和落盘后发布投影。
不改变媒体路径、画像算法、单入口默认值或已有部署记录格式。

分片数仅支持2、4、8、16，索引从0开始且必须完整。
映射为SHA256的前8字节大端整数对分片数取模；
哈希输入是ASCII `superserve-profile-shard-v1`、一个零字节、主体原始UTF-8字节。
主体仍必须通过原 `valid_id`，不做大小写、Unicode或字符串归一化。
该算法是本项目协议胶合，不冒充Qdrant哈希兼容。

分片节点的 `VS_PROFILE_SHARD`：

```json
{"schema":"profile-shard-v1","count":2,"index":0}
```

仅用于 `VS_ROLE=profile`，同时要求 `VS_PROFILE_EVENT_LOG`。
只允许新建或既有空日志首次登记；非空无标记日志不自动迁移。
在原日志独占锁保护下用原 `atomic_create` 发布 `.shard.json` 身份。
重启必须保持同一身份；禁止改数量、索引或退回无分片启动。
分片标记存在但日志缺失时拒绝，不悄悄创建空历史。
重放逐事件校验主体归属；标记格式错误、未知字段、目录或符号链接拒绝。
标记在目录内的维护仍需要运维访问控制；它不是认证、分布式租约或全局fence。

API的 `VS_PROFILE_SHARDS_CONFIG` 须指向绝对路径，读取最多16KiB：

```json
{
  "schema":"profile-shards-v1",
  "shards":[
    {
      "shard":{"schema":"profile-shard-v1","count":2,"index":0},
      "endpoint":"http://127.0.0.1:8100",
      "token":"example-only-profile-token-0000000000"
    },
    {
      "shard":{"schema":"profile-shard-v1","count":2,"index":1},
      "endpoint":"http://127.0.0.1:8101",
      "token":"example-only-profile-token-1111111111"
    }
  ]
}
```

示例令牌不能用于生产。真实配置包含敏感凭据，应由受保护的文件交付，不放命令行或日志。
仅用于无本地画像日志的api/all角色，不与单入口、部署通道或单日志水位混用。
配置任意顺序，启动校验完整集合、唯一索引、规范化入口不重复及原客户端令牌/URL限制。
不把不同DNS名称一定当不同物理节点；节点还须通过实际就绪身份核对。

## 请求边界

客户端只对主体映射所得节点发一个事件或投影请求，不广播、重试或失败改投。
复用原客户端的连接池、2秒期限、禁重定向、禁隐式重试和64KiB响应限制。
请求和响应都绑定 `x-profile-shard-guard`，值如 `profile-shard-v1:2:0`。
服务端独立重算主体归属，不信任单个客户端路由结果。
单入口权威也拒绝带分片guard的POST，避免把多分片配置误接普通权威。
guard不是密钥；原内部令牌和目录校验仍必须成立。

API启动时并发校验全部分片，最多16路；原readyz也检查全部分片。
某分片失联使整体就绪失败，其主体请求返回不可用，绝不以空画像或其他节点替代。
存活分片原地址仍可处理已到达的主体请求；负载均衡器可能摘除整个API，属于当前可用性代偿。
写结果丢失仍是未知结果，不自动转为新事件；重试必须保留原subject/event_id/正文。

## 恢复与扩容禁区

目前每分片仍是32MiB上限的本地单写者日志，无复制或自动升主。
身份只描述固定布局，不包含endpoint、所有权epoch或租约。
复制同一日志和标记到别的目录/主机，仍可能产生双写；本实现不能阻止管理员制造重复权威。
同时丢失日志与标记也不能由本地自证历史存在，因此不能自动灾难恢复。

现有单日志备份与交接拒绝分片日志，防止遗漏身份或误解除其边界。
分片日志和标记必须作为敏感配套资产保留，正式备份/恢复扩展待独立设计。
禁止在线改分片数、自动重分配、自动清除标记或复制为新权威。
切换同索引endpoint也不代表全局旧写者已隔离；实验配置不可直接用于生产滚动切流。
正式迁移需要旧权威隔离、最终历史水位、目标重放、读写切流及失败恢复的联合证明。

固定Qdrant源码的稳定映射和读/写重分片阶段用于机制对照；
未复制完整哈希环、双写或共识内核。原不可覆盖发布实现及来源许可证继续复用。
不把本实验主体键改成Iggy消息键：两者是不同协议，Iggy worker路由仍独立待实现。

## 验收

见 `vs-service/tests/profile_shards.rs` 和 `profile_shard_process.rs`：
2至16分片唯一归属与独立SHA向量、错节点/错身份/伪响应、失联不改投、
两API跨域读写/幂等/Hide、日志布局固定与独立程序重启。
实际独立程序验收为同机2画像进程加2API、32个合成主体；
不等于物理集群、故障转移、在线扩容、真实用户效用或三低基准。
