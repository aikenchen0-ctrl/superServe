# 本机播放消费持久化接线

## 范围

把`playback_lab`真实浏览器帧回调和XHR正文观测，经已有反馈收集器写入消息协议，
再由`feedback-evidence-v1`与`consumption-replay-v1`读取和重建。
它只用于本机合成实验，不是生产登录、匿名采集或原生SDK。

省略`VS_LAB_FEEDBACK_CONFIG`时旧行为不变：`/lab/consumption`返回200、
`persisted=false`，只规范化，不写日志。
显式开启后配置必须是绝对路径、最多64KiB，且满足：

- `endpoint`是字面IPv4回环HTTP地址，无备用地址。
- `source_id=playback-lab`、`data_kind=synthetic`。
- broker凭据仅由`VS_FEEDBACK_IGGY_TOKEN`交付后端，不写浏览器夹具或URL。
- 沿用原`IggyFeedbackConfig`坐标、超时和凭据限制。
- 在浏览器入口可用前执行原主题就绪检查；不以启动成功证明追加权限或物理持久性。

## 实例绑定

实验服务仍只在回环监听，沿用Host、Origin、Sec-Fetch-Site与CSP边界。
只把服务自己刚签发的播放授权登记到最多8项内存表：
`playback_id -> decision_id + candidate_id + issued_at + expires_at`。
重复身份不覆盖，仅回收已过期绑定；服务重启不恢复旧实例。

提交还须满足固定实验主体`local-lab-viewer`、Web平台、固定来源、
合成标记、当前登记的决策和候选以及`generation=1`。
每个服务器随机播放ID是新实例，所以与UI的页面操作代次分开；
本模式不允许客户端自行重置计数代次。
事件时间必须处于登记窗口，单批仍经原消费规范化且最多64事件、32KiB。
未签发、跨主体/候选/决策/平台/代次或已过期请求不进入写入。

这是实验所有权边界，不是有能力抵抗同源恶意脚本的用户身份体系。
同源页面仍能伪造当前实例内的观测；不能当观看证明。

## 写入与客户端行为

新网关复用原`Role::Feedback`路由，在进程内注入内部凭据，
不新增日志实现、消息格式、重试队列或线上角色混用。
`201 + persisted + 正确坐标`的协议确认仍由原适配校验；
成功返回202和`playback-lab-consumption-v1`，附原提交摘要。
失败保持原错误或unknown语义，不回退成`persisted=false`成功。

浏览器仅在显式持久化模式：

1. 得到实例后、加载媒体前记录首次已知零字节基线。
2. `submitPlaybackCheckpoint()`追加进度声明，提交尚未确认的事件切片。
3. 每批深拷贝并序列化冻结；并发调用共用当前一次请求。
4. 验证响应版本、持久化等级和安全整数非负偏移后才推进已确认事件游标。
5. 请求5秒到期；网络失败、无有效确认或超时标记结果未知，后续自动发送停止。
6. 停止先取消媒体加载，等待所有XHR结束，再生成封存尾批；
   `submitPlaybackConsumption()`只发送未确认后缀，不丢取消尾部字节。

当前没有定时后台发送、页面关闭保证交付或无限批次滚动；
64事件本地预算和遗漏计数保持，超出预算不能冒充完整采集。
已封存载荷在验收中可被显式重传，以检验下游去重；
这不代表客户端会自动重试unknown写入。

`active_ms`保持未知；不会拿播放位置或帧数捏造活动时长。
XHR累计正文含清单与媒体，不含HTTP头、TLS、重传或线路开销。
`byte_scope=web_xhr_body`和原帧回调语义保持。

## 可重跑验收

先在O盘构建`playback_lab`和`feedback_log`目标，再运行：

```powershell
. 'D:\CodexVideoTools\enter.ps1'
& 'vedioServer/labs/playback/run-consumption-browser.ps1' -InputVideo 'O:\path\source.mp4'
```

运行器使用本轮新目录、独立Chrome、受控HTTP消息夹具和独立Rust播放进程。
验证真实解码、变化像素、桌面/手机宽度、检查点与尾批偏移、
显式重传与未签发实例拒绝，随后生成原始快照和重建报告。
只有浏览器结果及重建关系同时通过才成功。
播放进程在测试完成后主动终止并验证TCP可重绑，不宣称该进程优雅退出；
浏览器由自身关闭，不改系统信任、防火墙或用户浏览器。

上述默认验收的消息服务是`deterministic-http-fixture`，其`persisted`头只是协议夹具声明，
不能替代真实Iggy进程、磁盘、断电、跨节点多数派和故障恢复证据。
当前Rust真实Iggy构建/WSL存储风险仍见`labs/iggy/README.md`，
不能为跑通实验而回退C盘或忽略既有内核等待反例。

## 显式真实Iggy恢复验收

`labs/playback/run-consumption-iggy.ps1 -LaunchFile <已清理来宾启动收据>`
复用O盘已有Debian来宾和固定Iggy制品，不复制VM或启动C盘WSL/Docker。
首次执行前构建`playback_lab`、`snapshot_feedback`、`replay_consumption`及
`feedback_log`测试目标；真实服务运行和构建串行，不自动安装依赖。

每次新建流、单分区及显式`persisted`主题，独立签发写者和读者。
写者持本主题的读取元数据与追加权限，读者持元数据及消息读取权限。
固定Iggy的`read_topic`继承消息读取，所以写者并非严格只写；这是已知权限粒度代偿，
不能把`poll_messages=false`解释成读取被禁。实际检查读者追加返回403，
写者在已有消息后可读取一条。root管理令牌不交播放进程或浏览器。
启动浏览器CLI前清除宿主反馈令牌环境变量，结束后恢复调用方环境。

测试通过显式配置选择实际后端，缺配置保持夹具，实际模式失败不得回退。
同一浏览器流程仍要求真实解码、变化像素、检查点和尾批、显式完整重传、
未签发实例403及重建字节一致。实际消息坐标可能为0，不假定从1开始。
浏览器只能报告解码和HTTP确认；外层实际进程及恢复收据证明后端身份，
浏览器自身不声明磁盘持久性。

先回收播放写者，后续正常停止和确认后SIGKILL再重启均只读原偏移区间。
每次重新登录原读者，因为未设置持久JWT签名密钥时旧令牌会在重启失效。
检查主题和分区创建身份、显式持久策略、总消息数、全部消息ID、偏移、
原始载荷长度/摘要/字节，以及重建交互和覆盖信息。
`captured_at`和引用归档摘要保留每次真实值，不要求整个归档文件摘要相同，
也不回写旧时间以制造相同摘要。

失败使用新目录保留现场，不重发未知写入，不覆盖旧快照。
实验结束回收来宾、种子、浏览器和播放进程，并重绑宿主映射端口。
来宾磁盘内仍可能保留实验账户与临时密钥；这不是生产删除或凭据治理方案。
真实后端模式仅解除“HTTP夹具不能证明消息恢复”的组合缺口，
不解除断电、物理故障域、三端或性能门。
